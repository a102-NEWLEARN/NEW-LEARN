- **원문** (L794, 05:53): "대규모 추천 피드는 제외하되, **이전에 이야기한 홈의 가벼운 이슈 카드 추천**은 남겨두면 좋겠습니다. 추천 이슈를 누르면 사건 흐름과 관점·근거로 이어지는 **정도로** 생각"

### G2. "곧 제공"의 의미: 관점 비교를 MVP에서 뺀 근거가 사용자 정의와 어긋남
- **원문** (L308, NEW:RUN 서비스 소개): "프로토타입에 들어 있는 기능은 '구현됨', **UI 자리만 있는 기능은 '곧 제공'으로 구분**한다."
- **원문** (L308, 기대효과): "B. **관점을 보면서 사고력 향상**(사고력)"
- **PRD 현황**: 4.8 제외 목록에 "관점 비교: 프로토타입에서 '곧 제공' 상태. MVP 이후 후보"가 있다. 5.3 범위 밖에도 들어가 있다.
  - 사용자 정의로 "곧 제공"은 프로토타입 구현 상태(자리는 있고 아직 구현 전)일 뿐이고, 범위에서 뺀다는 결정이 아니다.
  - 제외는 assistant가 L679에서 알렸고 사용자가 반대하지 않았지만, 명시적으로 승인한 적도 없다.
  - 관점 비교는 기대효과 B(관점을 보며 사고력)를 가장 직접 구현하는 기능이다. 그런데 PRD 7.3 B는 변화 카드와 사실/해석 구분으로만 B를 설명하고, 5.3은 논점 맵을 A(정보량)에 연결한다.
- **함께 빠진 것**: "구현됨 / 곧 제공" 구분 자체가 기능 표(4.0)에 적용되지 않았다. 기능별 프로토타입 상태를 볼 수 없다.
- **넣을 곳**: 4.8의 관점 비교를 "제외"에서 열린 질문(새 Q)으로 옮기거나, 팀 확인 표시를 붙인다. 4.0 기능 한눈에 표에 "프로토타입 상태(구현됨 / 곧 제공 / 화면 없음)" 열을 추가한다. 7.3 B에 논점 맵(관점 보기)을 연결한다.

### G3. 기대효과 A·B를 재는 지표가 없음
- **원문** (L308): "기대효과 / 뉴스를 보면서 / A. 다양한 정보를 여러 관점 측면으로 습득(정보량) / B. 관점을 보면서 사고력 향상(사고력)". 브레인 덤프의 첫 항목이다.
- **PRD 현황**: 7.3에 A, B가 서술돼 있다. 하지만 1.3 성공 지표에서 사용자 쪽 지표는 SM-5 하나이고, 질문이 "이슈의 흐름을 이해하는 데 도움이 됐다" 하나뿐이다. 여러 관점 습득(A)과 사고력(B)은 어떤 지표로도 확인하지 않는다.
- **넣을 곳**: 1.3 SM-5에 문항을 추가한다(예: "같은 사건의 여러 관점을 알게 됐다"(A), "근거를 보고 스스로 판단하는 데 도움이 됐다"(B)). 또는 7.3에 각 효과를 확인할 지표 번호를 단다.

### G4. F01~F11 전부 P0인데, M1 프로토타입 범위에서 기사 마인드맵이 빠짐

- **넣을 곳**: 1.4 M1 행에 기사 마인드맵(최소 F03~F05)을 넣거나, "M1에 기사 마인드맵을 넣는가"를 새 Q로 올린다. 1.3 SM-1 문장도 함께 맞춘다.

### G5. 용어: 사용자는 "마인드맵"을 여러 맵에 섞어 쓴다
- **원문**:

- **넣을 곳**: 부록 A 용어집에 "팀에서 흔히 쓰는 말 → 정식 용어" 표를 추가한다. 5.2 설명에도 "팀 피드백의 '이슈 마인드맵'은 이 타임라인을 가리킨다"는 한 줄을 넣는다.
