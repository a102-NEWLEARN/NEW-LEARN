# NEW:LEARN 경험 설계

NEW:LEARN 화면이 **어떻게 동작하는지** 정한다. 화면 목록과 이동, 상태, 문구, 키보드, 접근성, 화면 크기별 변화를 다룬다. 생김새(색 · 글자 · 모양 · 크기)는 `DESIGN.md` 가 정한다.
SEED Design 과 다른 것과 NEW:LEARN 에만 있는 것만 적는다.

**SEED · 프로토타입 v15 와 다르게 정한 것**

| 무엇 | 어느 절 |
| --- | --- |
| 화면마다 주소가 있고 고른 사건 · 노드도 주소에 남는다 (프로토타입은 주소 없이 이동) | Information Architecture |
| 앱 안 탭(열어 둔 화면을 늘어놓은 띠)은 만들지 않는다 | Information Architecture |
| 사이드바는 768px(md) 미만에서 서랍이 되고 끌어서 폭을 바꾸지 않는다 (프로토타입은 1024px 기준 · 폭 조절) | 앱 셸 · Responsive & Platform |
| 오른쪽 패널은 하나만 열리고 사건 패널 · 노드 패널이 같은 자리를 쓴다 | 앱 셸 |
| 불러오기에 실패하면 화면 전체가 아니라 실패한 영역 자리에 안내를 둔다 | State Patterns |
| P2 기능 버튼을 비활성으로 두지 않고, 누르면 곧 나온다고 안내한다 | Component Patterns |
| 패널 모션은 열림 300ms · 닫힘 250ms 다 (프로토타입은 220ms) | Interaction Primitives |

- **범위**는 확정 기능 아홉 개다 (`docs/mvp-overview.md` 3-1): F01 뉴스 데이터 적재·조회, F02 카테고리별 뉴스·이슈 조회, F03 기사 핵심 정보 구조화, F04 기사 마인드맵 생성, F05 노드 상세 및 근거 확인, F06 동일 사건 기사 클러스터링, F07 사건 중심 이슈 에볼루션 맵, F08 사건별 관련 기사 조회, F11 기사·이슈 양방향 연결.
- F04 · F05 · F07 은 맵 안 배치와 조작을 아직 정하지 않았다. F09 주장 관계 및 변화 분석과 F10 근거 기반 변화 카드는 추후 논의 기능이다. 둘 다 [아직 정하지 않은 것](#아직-정하지-않은-것)에 적었다.
- 근거 문서가 없어 이 문서에서 정한 것은 `[가정]` 으로 표시한다.
- 프로토타입 · 디자인 시스템 v2 원본과 이 문서가 다르면 이 문서를 따른다.
- 절 제목은 BMAD 검사가 이름으로 찾기 때문에 영어로 둔다.

## Foundation

- **반응형 웹 하나.** PC 1280px 이상을 기준으로 설계하고 모바일 360~430px 에서는 깨지지 않게만 한다. 모바일 다듬기는 일정에 여유가 있을 때 한다. 앱 · PWA 는 만들지 않는다 (PRD 1.1 · 4.10 · 4.11).
- **브라우저**는 최신 Chrome · Edge 다 `[가정]` (PRD 에도 가정으로 표시돼 있다).
- **UI 시스템**은 SEED Design 3 (React) 이다. 포커스 이동 · Esc · aria 같은 컴포넌트 동작은 SEED 를 따른다.
- **기준 프로토타입**은 v15 다 (`.claude/stack.md` §7).
- **로그인이 없다.** 로그인이 필요한 나의 뉴스함 · 마이페이지 · 북마크는 P2 다.

## Information Architecture

화면마다 주소가 있다. 주소를 복사해 열면 같은 화면이 같은 선택으로 열린다. 고른 사건 · 노드는 주소 뒤에 쿼리로 붙인다. 그래야 기사에서 이슈 화면으로 갈 때(F11) 그 사건을 고른 채 열리고, 뒤로 가기로 돌아와도 고른 사건 · 노드가 남는다.

| 화면 | 주소 | 들어오는 길 | 하는 일 | API |
| --- | --- | --- | --- | --- |
| 랜딩 | `/` | 처음 방문 | 서비스 소개. *서비스 둘러보기* → 홈, *기사로 마인드맵 만들기* → 홈 + URL 입력 모달. 소개 메뉴를 누르면 같은 페이지 안의 해당 부분으로 스크롤한다 | — |
| 홈 | `/home` | 로고, 사이드바 *홈*, 랜딩 | 7개 분야 탭, 고른 분야의 이슈 카드(최근 업데이트 순), 최신 기사 | A1 · A2 · A7 |
| 이슈 화면 | `/issues/:issueId` | 이슈 카드, 사이드바 이슈 | 이슈 헤더와 사건 타임라인 | A3 · A4 |
| 사건 패널 | `/issues/:issueId?event=:eventId` | 타임라인 사건 노드, 사이드바 사건, 기사 마인드맵의 *이 기사가 속한 이슈 보기* | 사건 요약, 관련 기사 4건과 *더 보기*, 이전 · 다음 사건 | A5 · A6 |
| 기사 마인드맵 | `/articles/:articleId` | 최신 기사, 사건 패널의 관련 기사, 분석 완료 | 기사 헤더, 마인드맵, *이 기사가 속한 이슈 보기* | A8 · A9 |
| 노드 패널 | `/articles/:articleId?node=:nodeId` | 마인드맵 노드 | 노드 요약, 원문 근거, 문단 위치 | A9 |
| URL 입력 모달 | 주소 없음 | 헤더 *마인드맵 만들기*, 랜딩 | 지원 출처 기사 URL 입력 (PRD FR-32). 흐름은 [URL 분석](#url-분석) | A10 · A12 |
| 분석 중 | `/analyze/:jobId` | URL 제출 | 분석 진행 표시 | A11 |
| 찾을 수 없음 | 그 밖의 주소 | 없는 주소, `_NOT_FOUND` 오류 | 무엇이 없는지(「이슈를 찾을 수 없어요」)와 *홈으로* | — |
| 통합 검색 | 홈 검색창 | ⌘/Ctrl+K, 사이드바 *빠른 이동* | **MVP 포함 미정** (Jira S15P31A102-46). 넣으면 결과를 이슈 · 사건 · 기사로 나누고, ↑↓ 로 오가며 Enter 로 연다. 결과가 없으면 「'…'에 맞는 이슈·사건·기사가 없어요」 | A13 |
| 나의 뉴스함 · 마이페이지 | — | 헤더, 사이드바 | P2. 곧 제공 항목이다 (Component Patterns) | — |

**이동 규칙**
- 무엇을 눌렀느냐에 따라 도착 화면이 다르다. 기사는 기사 마인드맵, 이슈는 이슈 화면, 사건은 사건 패널이 열린 이슈 화면이다. 기사와 이슈는 아이콘으로 구분한다. 기사는 문서 아이콘, 이슈는 갈래 아이콘이다 (PRD FR-30).
- 다른 화면으로 가면 브라우저 방문 기록을 하나 쌓는다. 같은 화면 안에서 고른 것만 바꾸면(다른 사건 고르기, 패널 닫기) 기록을 새로 쌓지 않고 지금 기록의 주소만 바꾼다 `[가정]`. 그래서 뒤로 가기는 앞 화면으로 간다.
- 홈에서 고른 분야는 `/home?category=` 로 남긴다 `[가정]`.
- 프로토타입의 앱 안 탭은 MVP 에서 만들지 않는다. P2 다 (PRD FR-27).

### 앱 셸

랜딩을 뺀 모든 화면은 네 영역으로 짠다 (v2 `Foundations/04-layout.md`). 랜딩은 셸 없이 혼자 뜬다. 프로토타입에서도 랜딩은 앱 앞에 따로 뜬다. 화면 폭에 따라 달라지는 것은 [Responsive & Platform](#responsive--platform) 표에 있다.

| 영역 | 동작 |
| --- | --- |
| 헤더 | 스크롤해도 화면 위에 붙어 있다 `[가정]`. 항목은 왼쪽부터 메뉴 열기(사이드바가 서랍일 때만) · 로고 · *마인드맵 만들기* · 나의 뉴스함 · 마이페이지다. 로고를 누르면 홈으로 가서 열린 패널을 닫고 맨 위로 스크롤한다 |
| 사이드바 | 접기 · 펼치기 버튼이나 ⌘/Ctrl+\ 로 접고(64px) 편다(216px). 끌어서 폭을 바꾸지 않는다. 처음에는 접혀 있다 (프로토타입). 펼치면 빠른 이동과 이슈 탐색(분야 → 연도 → 이슈 → 사건)이 보인다 (PRD FR-3). 이슈를 누르면 이슈 화면, 사건을 누르면 사건 패널이 열린다. 서랍일 때는 헤더 메뉴로 연다. 바깥 어두운 막이나 Esc 를 누르거나 항목을 고르면 닫힌다 |
| 본문 | 화면 내용. 사이드바와 오른쪽 패널이 차지한 만큼 좁아진다 |
| 오른쪽 패널 | 한 번에 하나만 열린다. 사건 패널과 노드 패널이 같은 자리를 쓴다. 본문을 덮지 않고 본문 오른쪽에 붙는다. 서랍을 쓰는 좁은 화면에서는 아래에서 올라오는 시트(화면 높이 85%)가 되고 뒤를 딤으로 덮는다 `[가정]`. 패널이 열리면 사이드바를 접는다. X 버튼(`aria-label="상세 패널 닫기"`) · Esc · 타임라인 빈 곳 · 시트 바깥을 누르면 닫힌다. 이전 · 다음 사건 버튼은 패널을 연 채 사건만 바꾼다 |

## Voice and Tone

화면 문구 규칙이다. 브랜드 분위기는 `DESIGN.md` Brand & Style 이 정한다.

| 한다 | 하지 않는다 |
| --- | --- |
| 해요체, 아라비아 숫자, 한 문장에 한 내용 (v2 `07-writing.md`) | 딱딱한 공문체, 한 문장에 여러 안내 |
| 오류에는 할 수 있는 일을 적는다 — 「타임라인을 불러오지 못했어요」 · 「네트워크 상태를 확인한 뒤 다시 시도해 주세요.」 | 오류 코드 · 서버 메시지(`detail` · `message`)를 화면에 그대로 내기 (`api.md` 1절) |
| 주의를 주는 시스템 안내는 「~니다」로 끝낸다 — 「지원하지 않는 출처의 기사입니다」 | 겁주는 말투로 경고하기 |
| 보도가 엇갈리면 「상충 후보」라고 쓰고 사용자가 확인해 볼 지점으로 보여 준다 | 「오보」 · 「거짓」처럼 어느 쪽이 맞는지 판정하는 말 (PRD 4.10) |
| 언론사 이름은 사실 그대로 쓴다 | 언론사 성향 · 신뢰도 평가, 특정 언론사를 앞세우기 |
| 근거 문장은 원문 그대로 두고 요약과 나눈다 | 근거를 고쳐 쓰거나 요약에 섞기 |
| AI 가 만든 요약 · 마인드맵에는 AI 생성 표시를 붙인다 | 표시 없이 사실처럼 두기 |
| 「마인드맵 만들기」, 「북마크」 | 「마인드맵 생성하기」 · 「생성」, 「스크랩」 |
| 「사건 3개 · 기사 12개」. 0이면 그 항목을 뺀다 (v2 IssueCard) | 「사건 0건」 |

**날짜 · 숫자**

| 무엇 | 표기 | 근거 |
| --- | --- | --- |
| 기사 날짜 | 오늘 · 어제는 상대 시간(「방금 전」 · 「N분 전」 · 「N시간 전」 · 「1일 전」), 그 밖은 「10월 14일」. 올해가 아니면 「2025년 10월 14일」 `[가정]` | v2 ArticleList · `06-international-design.md` |
| 타임라인 사건 날짜 | `MM.DD`. 해가 바뀌는 첫 사건에만 연도 | v2 Timeline |

| 발생 시점을 기사 발행일로 추정했을 때 | 날짜 옆에 「추정」 `[가정]` | `api-screen.md` A4 `occurredAtBasis` |
| 근거 위치 | 「가람일보 2번째 문단」. API 문단 번호는 0부터 세므로 1을 더한다 | `api-screen.md` 3절 |
| 큰 수 | 만 · 억으로 끊는다 | v2 `06-international-design.md` |

## Component Patterns

동작만 적는다. 생김새는 `DESIGN.md` Components, 원본 패턴은 `imports/newlearn-design-system-v2/components/<패턴>/README.md` 에 있다. 여러 컴포넌트에 걸친 접근성 규칙(aria-label · 누르는 영역 · 포커스 이동)은 Accessibility Floor 에 있다.

| 컴포넌트 | 쓰는 곳 | 동작 |
| --- | --- | --- |
| 헤더 · 사이드바 · 오른쪽 패널 | 랜딩 밖 모든 화면 | [앱 셸](#앱-셸) |
| URL 입력 모달 | 헤더, 랜딩 | SEED Dialog. 제출한 뒤의 흐름과 오류 자리는 [URL 분석](#url-분석) |
| 분야 탭 (CategoryTabs) | 홈 | 하나만 고른다(`role="tab"` · `aria-selected`). 고르면 아래 이슈 카드 · 최신 기사가 그 분야로 통째로 바뀐다. 탭이 넘치면 가로로 스크롤한다 |
| 필터 칩 | 이슈 화면 타임라인 필터 | 여러 개 고른다(`aria-pressed`). 「초기화」로 모두 푼다. 화면에 탭이 있으면 칩 줄을 탭 바로 아래에 둔다. 드롭다운 칩은 값을 고르면 칩 글자가 그 값(「이번 주」)으로 바뀐다 |
| 이슈 카드 (IssueCard) | 홈 | 카드 전체가 누르는 면 하나다. 누르면 이슈 화면으로 간다 |
| 기사 행 (ArticleList) | 홈 최신 기사, 사건 패널 관련 기사 | 행 전체가 누르는 면이다. 누르면 기사 마인드맵으로 간다. 사건 패널 안에서는 작은 변형으로 처음 4건을 보여 주고, *더 보기*를 누르면 다음 쪽(A6 `page`)을 불러 아래에 붙인다 |
| 사건 노드 (Timeline) | 이슈 화면 | 누르거나 Enter · Space 로 사건 패널을 연다. 고른 노드에는 `{components.list-row-selected}` 선택 표시가 남는다. 맵 배치는 아직 정하지 않았다 |
| 원문 근거 | 사건 패널, 노드 패널 | 원문 문장 그대로 `{components.evidence-quote}` 에 담는다. 근거가 없으면 근거 상자를 빼고 State Patterns 의 근거 없음 문구를 둔다 |
| 버튼 | 전역 | SEED ActionButton. 요청을 보내는 동안 `loading` 으로 두어 다시 누르지 못하게 한다 |
| 스낵바 | 전역 | 짧은 알림 한 줄. 2.4초 뒤 사라진다 (프로토타입). 오류는 스낵바로 알리지 않고 실패한 영역 자리에 둔다 `[가정]` |
| 곧 제공 항목 | 헤더 나의 뉴스함 · 마이페이지, 사이드바 관심 이슈 | P2 기능 자리다. 누를 수 있고 키보드로도 닿는다. 누르면 스낵바 「MVP 이후 제공 예정인 기능이에요」가 뜬다. 비활성으로 두지 않는다. 비활성 버튼에는 키보드로 닿을 수 없어 사용자가 안내를 못 받는다 |
| 태그 | 카드, 패널 | 누를 수 없는 라벨이다 `[가정]` |

## State Patterns

**공통 규칙**
- **불러오는 중**에는 그 자리 모양을 딴 스켈레톤을 둔다 (반짝임 모양은 `DESIGN.md`). 스피너는 버튼 안 로딩에만 쓴다 `[가정]`.
- **빈 결과**에는 그 자리에 빈 상태 문구를 둔다. 문구는 아래 표에 있다.
- **불러오기 실패**는 실패한 영역 자리에 안내와 *다시 시도*를 둔다. 화면 전체를 오류로 바꾸지 않는다 `[가정]`. 안내 문구 예는 Voice and Tone 에 있다.
- **없는 것**(`_NOT_FOUND`, 없는 주소)은 화면 전체를 찾을 수 없음 화면으로 바꾼다 (Information Architecture).
- 오류 코드별 문구와 할 일은 `docs/api.md` 2절이 정한다. 그 밖의 화면 상태 문구는 아래 표가 정한다. `api.md` 가 말하는 일반 오류 안내에는 「일시적으로 서비스를 사용할 수 없어요. 잠시 후 다시 시도해 주세요.」를 쓴다 (v2 `07-writing.md`).

| 상태 | 화면 | 처리 |
| --- | --- | --- |
| 분야에 이슈 없음 | 홈 | 「이 분야의 이슈가 아직 없어요」 (A1 `issueCount` 가 0일 때) |
| 준비 중인 이슈 | 이슈 화면 | 「이 이슈의 상세 데이터는 준비 중이에요」와 「사건 N개 · 기사 N개를 정리하고 있어요」 |
| 필터 결과 없음 | 이슈 화면 | 「조건에 맞는 사건이 없어요」. 칩의 「초기화」로 푼다 |
| 근거 없음 | 사건 패널, 노드 패널 | 「원문 근거를 찾지 못했어요」 |
| 마인드맵이 아직 없음 | 기사 마인드맵 | `MINDMAP_NOT_FOUND` 면 A8 `mindmapStatus` 를 본다. `QUEUED` 면 분석 중 화면을, `FAILED` 면 분석 실패 화면을 그대로 보여 준다 |
| 사건 연결 상태 | 기사 마인드맵의 *이 기사가 속한 이슈 보기* | A8 `eventMatchStatus` 를 본다. 다음 두 경우에는 버튼 대신 문구를 둔다 `[가정]`. `QUEUED` 면 「사건을 찾는 중이에요」, `SUCCEEDED` 인데 `issue` 가 없으면 「아직 이슈로 묶이지 않았어요」. `issue` 가 있으면 버튼을 눌러 사건 패널이 열린 이슈 화면으로 간다 |

### URL 분석

URL 입력부터 기사 마인드맵까지 이어지는 흐름이다. 오류 코드의 문구는 `api.md` 2절을 따르고 여기에는 문구가 뜨는 자리만 적는다.

| 단계 | 결과 | 화면 |
| --- | --- | --- |
| URL 입력 모달에서 *마인드맵 만들기* (A10) | 새 작업 (202) | 분석 중 화면(`/analyze/:jobId`)으로 간다 |
| 〃 | 이미 분석된 기사 (200 · `SUCCEEDED`) | 바로 기사 마인드맵으로 간다 |
| 〃 | `INVALID_URL` | 모달 안 입력칸 옆에 안내 |
| 〃 | `UNSUPPORTED_SOURCE` | 모달 안에 「지원하지 않는 출처의 기사입니다」와 지원 언론사 칩 (A12) |
| 〃 | `SOURCE_FETCH_FAILED` · `TOO_MANY_REQUESTS` | 모달 안에 안내 |
| 분석 중 화면 (A11) | 진행 중 | 「기사를 분석하고 있어요」. 단계 표시는 P1 이다 (PRD 4.11) |
| 〃 | `SUCCEEDED` | 기사 마인드맵으로 간다. 분석 중 주소를 기사 마인드맵 주소로 바꿔서 뒤로 가기가 분석 중 화면으로 돌아오지 않게 한다 `[가정]` |
| 〃 | `FAILED` | 작업 실패 코드별 안내. `retryable` 이면 *다시 시도*를 둔다. 그 밖에 갈 곳은 [아직 정하지 않은 것](#아직-정하지-않은-것) |

## Interaction Primitives

마우스와 터치가 먼저다. 키보드로도 모든 기능에 닿는다.

**키보드**
- ⌘/Ctrl+\ — 사이드바를 접거나 편다 (PRD FR-3).
- Esc — 맨 위에 열린 것 하나만 닫는다. 순서는 팝오버 · 메뉴 → 모달 → 오른쪽 패널 → 서랍이다.
- Enter · Space — 노드 · 카드 · 탭을 고른다.
- 검색 단축키는 Information Architecture 의 통합 검색 행에 있다.

**호버 · 눌림** (v2 `02-feedback.md`, 모양은 `DESIGN.md` 상태별 모양)
- 호버에만 기대는 기능을 두지 않는다. 호버는 마우스가 있는 기기에서만 보인다.
- 축소(누르면 살짝 작아지는 효과)는 누르는 면이 하나인 요소(카드 · 버튼 · 칩)에만 쓴다. 문장 속 링크에는 쓰지 않는다. 줄어드는 요소 안에 든 요소는 따로 줄이지 않는다. 로딩 중에도 줄이지 않는다. 탭은 색 대신 축소만 쓴다.
- 색 전환과 축소는 둘 다 150ms 라서 한 반응으로 읽힌다.

**모션** (v2 `01-motion.md`)
- 작은 움직임은 200ms(`duration-d4`) 이하, 큰 움직임은 250~300ms 다.
- 오른쪽 패널과 시트는 열릴 때 300ms(`enter` 곡선), 닫힐 때 250ms(`exit` 곡선)다. 프로토타입의 220ms 는 따르지 않는다.
- 동작 줄이기(`prefers-reduced-motion`)를 켜면 위치 · 크기 변화를 없애거나 짧은 페이드로 바꾼다. 색 전환은 남긴다.

## Accessibility Floor

**보기**
- 목표 수준은 WCAG 2.1 AA 다 `[가정]`.
- 색만으로 정보를 전하지 않는다. 글자와 아이콘을 함께 쓴다.
- 글자 크기를 rem 으로 정해 브라우저 글자 크기 설정을 따라 커지게 한다.

**포커스**
- 키보드 포커스는 늘 보인다. 카드 · 칩은 윤곽선을 바깥으로 띄우고 리스트 행 · 탭은 안쪽에 그린다 (윤곽선 모양은 `DESIGN.md` 상태별 모양).
- 다른 화면으로 가면 브라우저 탭 제목(`<title>`)을 그 화면 이름으로 바꾸고 포커스를 화면 맨 위 제목으로 옮긴다 `[가정]`.
- 모달을 열면 포커스가 모달 안 첫 입력으로 가고 닫으면 모달을 연 버튼으로 돌아간다 (SEED Dialog). 오른쪽 패널도 마찬가지로 열면 포커스가 패널 제목으로 가고 닫으면 고른 노드로 돌아간다 `[가정]`.
- DOM 순서를 화면에서 읽는 순서와 같게 둔다.

**스크린 리더**
- 지금 위치는 `aria-current` 로 알린다 (현재 화면의 사이드바 항목, 고른 이슈 카드 · 기사 행). 탭 · 칩의 ARIA 는 Component Patterns 에 있다.
- 아이콘만 있는 버튼에는 `aria-label` 을 단다. 옆에 같은 뜻의 글자가 있는 아이콘과 장식 아이콘은 `aria-hidden` 이다. 뜻이 있는 이미지에는 짧은 대체 텍스트를 붙인다.
- 분석 완료 · 실패 알림과 스낵바는 `aria-live` 로 읽어 준다 `[가정]`.

**누르기**
- 누르는 영역은 44px 이상을 목표로 하고 24px 아래로는 내리지 않는다. 아이콘 버튼은 40px 다. 아이콘을 키우지 않고 여백으로 넓힌다.
- 맵의 핀치 줌 · 드래그는 누르기만으로도 할 수 있게 대체 수단을 둔다 (v2 `05-inclusive-design.md`). 어떻게 할지는 F04 · F07 화면을 설계할 때 정한다.

## Responsive & Platform

v2 브레이크포인트를 따른다. 작은 화면용 스타일을 먼저 쓰고 `min-width` 미디어 쿼리로 넓혀 간다. 프로토타입의 1024px · 760px 기준은 따르지 않는다. 여백과 최대 폭은 `DESIGN.md` Layout & Spacing 에 있다.

| 폭 | 사이드바 | 오른쪽 패널 | 헤더 오른쪽 버튼 |
| --- | --- | --- | --- |
| lg 1280px 이상 (설계 기준) | 보인다 | 본문 오른쪽에 붙는다 | 글자 |
| md 768~1279px | 보인다 | 본문 오른쪽에 붙는다. 768px 근처에서는 본문이 좁다 — [아직 정하지 않은 것](#아직-정하지-않은-것) | 글자 |
| sm · base 767px 이하 | 서랍 (헤더 메뉴) | 아래에서 올라오는 시트 | 아이콘만 `[가정]` |

- 홈 · 랜딩 카드 그리드는 좁아지면 열 수를 줄인다. 이슈 카드는 최소 280px 이다 (v2 IssueCard).

## Key Flows

페르소나와 여정 전체는 `docs/user-flow.md` 에 있다. 여기서는 각 여정이 지나는 주소와 상태만 적는다.

### Flow A — 사쿠, 매일 아침 동향을 챙기는 취준생

1. `/home` 에서 분야 탭 「경제」를 고르고 이슈 카드를 누른다. user-flow 의 출발점인 *추천 이슈*(개인화)는 P2 라 분야 탭 이슈 카드로 대신한다.
2. `/issues/:issueId` 에서 이슈 헤더와 타임라인을 본다.
3. 가장 최근 사건을 누른다. 주소에 `?event=` 가 붙고 사건 패널이 열린다.
4. **핵심 순간** — 미정 ([아직 정하지 않은 것](#아직-정하지-않은-것)).

실패: 타임라인을 불러오지 못하면 그 자리에 *다시 시도*가 뜬다.

### Flow B — 요섭, 점심에 업계 기사를 읽는 직장인

1. `/home` 에서 최신 기사를 누른다. `/articles/:articleId` 기사 마인드맵이 열린다.
2. 노드를 누르면 주소에 `?node=` 가 붙고, 노드 패널에서 원문 근거를 본다.
3. *이 기사가 속한 이슈 보기*를 누른다. 이슈 화면(`/issues/:issueId?event=:eventId`)이 그 사건을 고른 채 열린다 (F11).
4. **핵심 순간** — 미정 ([아직 정하지 않은 것](#아직-정하지-않은-것)).

다른 입구: 헤더 *마인드맵 만들기*를 누르고 모달에 URL 을 넣는다. 이어지는 흐름과 실패는 [URL 분석](#url-분석) 표에 있다.
