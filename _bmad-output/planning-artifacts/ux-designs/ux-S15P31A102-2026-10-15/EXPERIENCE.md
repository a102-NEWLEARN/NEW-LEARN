# NEW:LEARN 경험 설계

NEW:LEARN 화면이 **어떻게 동작하는지** 정한다. 화면 목록과 이동, 상태, 문구, 키보드, 접근성, 화면 크기별 변화를 다룬다. 생김새(색 · 글자 · 모양 · 크기)는 `DESIGN.md` 가 정한다.
SEED Design 과 다른 것과 NEW:LEARN 에만 있는 것만 적는다.

**SEED · 프로토타입과 다르게 정한 것**

| 무엇 | 어느 절 |
| --- | --- |
| 화면마다 주소가 있고 고른 사건 · 보기도 주소에 남는다. 로그인 · 가입 · 마이페이지도 그렇다 (프로토타입은 주소 없이 이동하고 로그인 화면을 보던 화면 위에 띄운다) | Information Architecture |
| 앱 안 탭(열어 둔 화면을 늘어놓은 띠)은 만들지 않는다 | Information Architecture |
| 왼쪽 사이드바를 두지 않는다 — 좁은 화면 서랍은 S15P31A102-195, 넓은 화면 레일 · 이슈 탐색은 S15P31A102-196 에서 뺐다(2026-11-12 사용자). 분야별 이슈는 홈 추천 이슈 *전체보기* 로 여는 분야별 이슈 화면이 맡는다 (프로토타입은 사이드바 · 1024px 기준 · 폭 조절) | 앱 셸 · Responsive & Platform |
| 불러오기에 실패하면 화면 전체가 아니라 실패한 영역 자리에 안내를 둔다 | State Patterns |
| P2 기능 버튼을 비활성으로 두지 않고, 누르면 곧 나온다고 안내한다 | Component Patterns |
| 패널 모션은 열림 300ms · 닫힘 250ms 다 (프로토타입은 220ms) | Interaction Primitives |
| 프로토타입에 있어도 MVP 가 「추후」 · P2 로 둔 것(노드 상세 카드와 원문 근거, 논점 · 관점, 지난 방문 이후 새 사건)은 만들지 않는다 | `docs/mvp-overview.md` 3-1 · 6장 |

- **범위**는 `docs/mvp-overview.md` 3-1 을 따른다.
  - 확정: F01 뉴스 데이터 적재·조회, F02 카테고리별 뉴스·이슈 조회, F03 기사 핵심 정보 구조화, F04 기사 마인드맵 생성, F06 동일 사건 기사 클러스터링, F07 사건 중심 이슈 에볼루션 맵, F08 사건별 관련 기사 조회, F11 기사·이슈 양방향 연결, F12 회원·관심 분야, F13 용어사전 — F12 · F13 은 2026-10-20 · 10-21 팀 회의로 MVP 에 넣었다(`SSOT.md` 9절, MVP 개요 3-1 은 2026-10-29 부터 P0)
  - 추후: F05 노드 상세 및 근거 확인. 추후 논의: F09 주장 관계 및 변화 분석, F10 근거 기반 변화 카드. 셋 다 [아직 정하지 않은 것](#아직-정하지-않은-것)에 적었다
- 근거 문서가 없어 이 문서에서 정한 것은 `[가정]` 으로 표시한다.
- 프로토타입 · 디자인 시스템 v2 원본 · `docs/user-flow.md` 와 동작이 다르면 이 문서를 따른다. user-flow 는 10월 20일 회의 전 내용이다.
- 절 제목은 BMAD 검사가 이름으로 찾기 때문에 영어로 둔다.

## Foundation

- **반응형 웹 하나.** PC 1280px 이상을 기준으로 설계하고 모바일 360~430px 에서는 깨지지 않게만 한다. 모바일 다듬기는 일정에 여유가 있을 때 한다. 앱 · PWA 는 만들지 않는다 (PRD 1.1 · 4.10 · 4.11).
- **브라우저**는 최신 Chrome · Edge 다 `[가정]` (PRD 에도 가정으로 표시돼 있다).
- **UI 시스템**은 SEED Design 3 (React) 이다. 포커스 이동 · Esc · aria 같은 컴포넌트 동작은 SEED 를 따른다.
- **기준 프로토타입**은 v21 이다 (`.claude/stack.md` §7 「가장 높은 버전이 최신」). 이 문서에서 「프로토타입」은 v21 을 말한다.
- **회원이 있다** (F12). 탈퇴와 이름 · 비밀번호 바꾸기는 없다. 가입 항목은 IA 의 가입 행, 로그인 유지는 `api.md` 1절 「인증」에 있다. 손님(로그인하지 않은 사람)이 무엇을 볼 수 있는지는 이동 규칙에 있다.

## Information Architecture

화면마다 주소가 있다. 주소를 복사해 열면 같은 화면이 같은 선택으로 열린다. 고른 사건 · 보기는 주소 뒤에 쿼리로 붙인다. 그래야 기사에서 이슈 화면으로 갈 때(F11) 그 사건을 고른 채 열리고, 뒤로 가기로 돌아와도 고른 것이 남는다.

| 화면 | 주소 | 들어오는 길 | 하는 일 | API |
| --- | --- | --- | --- | --- |
| 랜딩 | `/` | 처음 방문 | 서비스 소개. *서비스 시작하기* · *로그인*을 누르면 손님은 로그인 화면, 회원은 홈으로 간다. 프로토타입 v21 의 섹션을 차례로 둔다 — 첫 화면(노드 그물 · 큰 NEW:LEARN · *서비스 시작하기* · *어떻게 정리하나요*) → 「기사 한 편만으로는…」과 기사 제목 띠 → 스크롤 연출 ①(기사 막대가 쌓여 「기사 N건 → 사건 n개」) → 스크롤 연출 ② 「어떻게 정리하나요」(기사 → 사건 → 이슈 흐름 → 흐름지도 · 마인드맵 미리보기) → 근거와 신뢰 → 자주 묻는 질문 → 마지막 권유 → 바닥글. 예시는 2026-11-12 운영 데이터로 만든 고정 예시라 API 를 부르지 않는다(이슈 80 · 사건 1450 · 기사 55961, `frontend/src/components/landing/landingSample.ts`). MVP 밖 기능(F10 의 UPDATE · F05 의 원문 근거 인용)은 말하지 않는다. 머리는 위에 붙고 내리면 흰 바탕 · 흐림 · 밑줄이 생긴다. 머리 메뉴(*어떻게 정리하나요* · *근거와 신뢰* · *자주 묻는 질문*, 좁은 화면은 숨김)를 누르면 같은 페이지 안의 그 섹션으로 머리 높이만큼 덜 부드럽게 내린다. 스크롤 연출의 단계 번호 · 미리보기 보기 버튼도 그 자리로 내린다. 스크롤 연출의 화면 문장은 스크롤에 따라 바뀌어 화면 읽기에서 빼고, 같은 문장을 처음부터 다 읽히는 숨은 글로 둔다 — 화면 읽기는 스크롤과 상관없이 차례로 읽는다. 움직임은 Interaction Primitives 「모션」 (2026-11-12 사용자, S15P31A102-32 — 열 때의 브랜드 색 인사 막(2026-11-03, S15P31A102-66)은 뺐다) | — |
| 로그인 | `/login?next=<보던 주소>` | 랜딩, 손님이 앱 화면을 열 때, 세션이 끝나 401 을 받았을 때 | 아이디 · 비밀번호. *아직 계정이 없나요?* → 가입 | A15 |
| 가입 | `/signup?next=<보던 주소>` | 로그인 화면 | 한 화면에 질문 하나씩 네 단계 — 01 이름 · 02 아이디 · 비밀번호 · 비밀번호 확인 · 03 관심 분야 · 04 사용 목적(고르지 않아도 된다). 질문 띠 아래 진행 막대가 단계만큼 찬다. 마지막 단계의 *가입하기* 로 보내고, 가입하면 바로 로그인된다 (`api-screen.md` A14). 사용 목적은 A14 에 칸이 없어 보내지 않는다(「아직 정하지 않은 것」). *이미 계정이 있나요?* → 로그인 은 첫 단계에만 둔다 (2026-11-03, S15P31A102-66) | A14 |
| 홈 | `/home` | 로고, 로그인 뒤 | 인사(「OO님, …」), 검색창과 그 아래 「새로운 이슈」 3개(한 줄에 하나씩 바뀐다 — Interaction Primitives 「모션」), 추천 이슈(분야 탭, 탭마다 이슈 3개 — 그 분야의 관심 이슈를 먼저(A25), 그다음 마지막 사건 최신순(A2). 모자라도 다른 관심 분야로 채우지 않는다 — v21 이 껐다 (PRD FR-28, 2026-11-05 S15P31A102-172). A25 를 받는 동안은 카드 자리만 둔다 — A2 순서로 그렸다가 눈앞에서 바뀌지 않게. A25 가 실패하면 알리지 않고 A2 순서로 둔다 `[가정]`. 머리 설명은 「여러 언론사 기사를 사건 단위로 묶어 정리한 이슈예요.」 한 문장 — 별 안내는 뺐다(2026-11-12 사용자, S15P31A102-195). *관심사 편집* → 마이페이지, 넓은 화면만. 카드 아래 *OO 이슈 N개 전체보기* → 분야별 이슈 — N 은 그 분야 이슈 수(A2), 이슈가 없으면 두지 않는다 (2026-11-12 S15P31A102-196)), 최신 기사(「전체」와 분야 탭, 처음 8개와 *기사 N개 더 보기* — N 은 한 번에 붙는 수, 최대 8). 좁은 화면은 추천 이슈 · 최신 기사를 위에 붙는 「추천 이슈 / 최신 기사」 탭으로 하나씩 보이고, 고른 탭은 `?view=latest` 로 남긴다 `[가정]` (모바일 프로토타입 v1, 2026-11-03, S15P31A102-161) | A1 · A2 · A7 · A13 · A17 · A25 |
| 분야별 이슈 | `/issues?category=:code` | 홈 추천 이슈 *OO 이슈 N개 전체보기* | 한 분야의 이슈를 마지막 사건 최신순으로 이슈 카드 그리드에 보인다(A2). 처음 12개와 *이슈 N개 더 보기* — N 은 한 번에 붙는 수, 최대 12. 분야 탭은 추천 이슈와 같은 순서(관심 분야 먼저)다. 고른 분야는 `?category=` 로 남기고 기록을 쌓지 않는다. 모르는 코드면 맨 앞 탭이다. 관심 이슈를 앞으로 당기지 않는다 — 전체 목록이라서. PRD FR-3 · FR-4 카테고리별 이슈 목록이 이 화면이다 (2026-11-12 S15P31A102-196) | A1 · A2 · A17 |
| 이슈 화면 | `/issues/:issueId` | 이슈 카드(홈 · 분야별 이슈), 검색 | 이슈 헤더(제목 옆 관심 이슈 별)와 사건 타임라인(메인 흐름 · 서브 흐름 두 레인). 요약 아래 *더보기* 와 같은 줄에 AI 생성 표시를 둔다 — v21 처럼 문장 끝에 붙이면 두 줄로 잘릴 때 가려진다 `[가정]` (2026-11-03, S15P31A102-159) | A3 · A4 · A23 · A24 |
| 사건 패널 | `/issues/:issueId?event=:eventId` | 타임라인 사건 노드(넓은 화면 지도는 노드 옆 제목 · 날짜 글자도 — 2026-11-05 S15P31A102-182), 기사 마인드맵의 *이 기사가 속한 이슈 보기* | 속한 이슈, 사건 제목, 「사건 발생」 · 「첫 기사」 날짜, 요약(AI 생성 표시, 없으면 칸을 두지 않는다 `[가정]`), 관련 기사 처음 5건(A6 `size=5`)과 *기사 N개 더 보기*(N 은 한 번에 붙는 수, 최대 5), 이전 · 다음 사건. 주소의 사건이 다른 이슈의 사건이면 그 이슈 주소로 바꾼다 `[가정]` | A5 · A6 |

| 마이페이지 | `/me` | 헤더 *마이페이지*, 홈 *관심사 편집*(넓은 화면) | 이름 아래 머리 줄 「관심 분야 N개 · 관심 이슈 N개 · 북마크 N개」 — 저장된 관심 분야(A17) · A25 · A22 의 개수다. 셋 다 받았을 때만 보이고, 하나라도 실패하면 줄을 두지 않는다 `[가정]` (2026-11-04, S15P31A102-163). 그 아래로 이름 · 아이디 보기(바꿀 수 없다), 관심 분야 바꾸기, 관심 이슈 — 이 차례로 섹션을 둔다 — 섹션은 상자 없이 위 1px 줄로 나눈다(2026-11-12 사용자 「박스가 나열이라 안 예쁘다」, S15P31A102-195). 로그아웃은 이 화면이 아니라 헤더 프로필 메뉴에 있다 (2026-11-05 사용자 — 맨 아래 로그아웃 · 카드 가운데 저장 줄이 버튼이 엉뚱한 데 있어 보였다, S15P31A102-182). 관심 이슈는 저장한 순서(A25)로 이름과 「분야 · 사건 N개」를 보이고 누르면 이슈 화면이다. 「새 사건 N」 배지는 데이터가 없어 두지 않는다(`api-screen.md` A25, 2026-11-03 S15P31A102-68). 관심 분야는 지금 관심 분야를 고른 칩으로 시작하고, 고쳐도 바로 보내지 않는다. 화면 아래에 붙은 *변경사항 저장하기* 하나가 A18 로 보내고 「관심사를 저장했어요」를 띄운 뒤 마이페이지에 남는다 — 저장된 것과 같으면 누를 수 없다. 저장 실패 안내는 그 버튼 위에 둔다. 고친 채 다른 화면으로 가려 하면 확인 창 「저장하지 않고 나갈까요?」(*계속 고치기* · *나가기*)로 묻고, 새로 고침 · 탭 닫기는 브라우저 기본 물음이다. 로그아웃 · 세션 만료로 떠날 때는 묻지 않는다. 섹션 제목 옆 *저장*(2026-11-05)은 촌스러워 뺐다 (2026-11-12 사용자, S15P31A102-195) | A16 · A17 · A18 · A22 · A25 |

| 찾을 수 없음 | 그 밖의 주소 | 없는 주소, `_NOT_FOUND` 오류 | 무엇이 없는지(「이슈를 찾을 수 없어요」)와 *홈으로* | — |
| 통합 검색 | 홈 검색창 | ⌘/Ctrl+K — 어느 화면에서든 홈으로 가서 검색창에 포커스한다 | 화면은 넣었다 (2026-10-23, Jira S15P31A102-46). 비어 있으면 「최근 업데이트된 이슈」 5개, 글자를 치면 결과를 이슈 · 사건 · 기사로 나누고, ↑↓ 로 오가며 Enter 로 연다. 결과가 없으면 「'…'에 맞는 이슈·사건·기사가 없어요」. 검색은 백엔드 A13 이 한다 — 제목만 찾고, 유형마다 최신순 20개까지, 검색어는 50자까지(2026-10-30, Jira 43). 칸에는 50자까지만 들어가고, 서버가 까닭을 준 400 이면 목록 안에 그 문장만 둔다(*다시 시도* 없음) (2026-11-03, S15P31A102-46) | A2 · A13 |
| 나의 뉴스함 | `/bookmarks` `[가정]` | 헤더 | 북마크한 기사를 최근에 담은 순서대로 기사 행으로 보인다(A22). 없으면 빈 상태 문구. v21 의 분야 탭은 두지 않는다 — 담은 기사가 적으면 탭이 비어 보인다 `[가정]`. 범위는 「아직 정하지 않은 것」 (2026-11-03, S15P31A102-67) | A20 · A21 · A22 |

**이동 규칙**
- 무엇을 눌렀느냐에 따라 도착 화면이 다르다. 기사는 기사 마인드맵, 이슈는 이슈 화면, 사건은 사건 패널이 열린 이슈 화면이다. 기사와 이슈는 아이콘으로 구분한다. 기사는 문서 아이콘, 이슈는 갈래 아이콘이다 (PRD FR-30).
- **손님은 로그인부터 한다** ([팀 확인 남음](#아직-정하지-않은-것)). 손님이 랜딩 밖 주소를 열면 `/login?next=<그 주소>` 로 보낸다. 손님인지 가리는 법(A17 의 401)과 API 가 로그인 없이 열려 있다는 것은 `api.md` 1절 「인증」에 있다.
- 세션이 끝나 401 `UNAUTHORIZED` 를 받으면 `/login?next=<지금 주소>` 로 보낸다 (`api.md` 2절). 로그인 화면이 받는 `LOGIN_FAILED`(401)와 로그아웃의 401 은 여기에 들지 않는다. 어느 조회 · 저장이 받든 화면 전체에서 한 곳(QueryClient)이 「내 정보」를 손님으로 바꿔 보낸다 — 목록이 401 이어도 「불러오지 못했어요」를 띄우지 않는다 (2026-11-04, S15P31A102-165).
- 로그인 · 가입을 마치면 `next` 로 간다. `next` 가 없으면 `/home` 으로 간다. 이미 로그인했는데 `/login` · `/signup` 을 열면 `/home` 으로 보낸다 `[가정]`.
- 로그아웃하면 랜딩(`/`)으로 간다. 손님은 셸 안 화면에 남을 수 없고, 손님이 처음 서는 곳이 랜딩이다. 세션이 이미 끝나 로그아웃이 401 이어도 로그아웃한 것과 같다. 받아 둔 응답은 모두 버린다 — 기사 · 이슈의 북마크 · 관심 상태가 회원 기준이다 (2026-11-03, S15P31A102-66).
- 다른 화면으로 가면 브라우저 방문 기록을 하나 쌓는다. 같은 화면 안에서 고른 것만 바꾸면(다른 사건 고르기, 패널 닫기, 보기 바꾸기) 기록을 새로 쌓지 않고 지금 기록의 주소만 바꾼다 `[가정]`. 그래서 뒤로 가기는 앞 화면으로 간다.
- 추천 이슈에서 고른 분야는 `/home?category=` 로 남긴다 `[가정]`.
- 최신 기사에서 고른 분야는 `/home?latest=` 로 남기고 「전체」면 뺀다. 추천 이슈의 `?category=` 와 따로 움직인다 `[가정]` (2026-11-03, S15P31A102-45).
- 프로토타입의 앱 안 탭은 MVP 에서 만들지 않는다. P2 다 (PRD FR-27).

### 앱 셸

랜딩 · 로그인 · 가입은 셸 없이 전체 화면으로 뜬다. 나머지 화면은 네 영역으로 짜고 본문의 글을 드래그하면 그 옆에 용어사전 말풍선이 뜬다 (v2 `Foundations/04-layout.md`). 화면 폭에 따라 달라지는 것은 [Responsive & Platform](#responsive--platform) 표에 있다.

| 영역 | 동작 |
| --- | --- |
| 헤더 | 스크롤해도 화면 위에 붙어 있다 `[가정]`. 항목은 왼쪽부터 로고 · 나의 뉴스함 · 마이페이지다(좁은 화면의 메뉴 열기는 서랍과 함께 뺐다, 2026-11-12 S15P31A102-195). 로고를 누르면 홈으로 가서 열린 패널을 닫고 맨 위로 스크롤한다. 지금 화면이 나의 뉴스함 · 마이페이지면 그 버튼을 브랜드 옅은 바탕 · Fill 아이콘으로 칠한다. 나의 뉴스함은 `aria-current` 로 알린다 (모바일 v1 · v21, 2026-11-04 S15P31A102-163). **마이페이지는 프로필 메뉴를 여는 버튼이다** — 누르면 오른쪽 아래로 *마이페이지* · *로그아웃* 메뉴가 열린다(넓은 화면은 「마이페이지 ▾」, 좁은 화면은 사람 아이콘). 지금 화면은 메뉴 안 *마이페이지* 가 `aria-current` 로 알린다. Esc · 바깥 · 항목을 누르면 닫히고, *로그아웃* 은 보내는 동안 메뉴를 열어 두며 실패하면 그 아래에 안내를 띄운다 — 오류는 스낵바가 아니라 실패한 자리에 둔다. 로그아웃은 마이페이지 이름 줄에 있었는데 어색해서 옮겼다 (2026-11-05 사용자, S15P31A102-182) |
| 사이드바 | 두지 않는다 (2026-11-12 사용자). 넓은 화면의 접는 레일(64px) · 펼친 이슈 탐색(분야 → 연도 → 이슈 → 사건, 216px) · ⌘/Ctrl+\ 는 S15P31A102-196 에서, 좁은 화면 서랍은 S15P31A102-195 에서 뺐다. 분야별 이슈는 홈 추천 이슈 *OO 이슈 N개 전체보기* 로 여는 분야별 이슈 화면(`/issues`)이, 사건은 이슈 화면 타임라인이, 빠른 이동은 ⌘/Ctrl+K 와 홈 검색창이 맡는다 |
| 본문 | 화면 내용. 오른쪽 패널이 차지한 만큼 좁아진다 |
| 오른쪽 패널 | 사건 패널이 열리는 자리다. 본문을 덮지 않고 본문 오른쪽에 붙는다. 좁은 화면(767px 이하)에서는 아래에서 올라오는 시트(화면 높이 85%)가 되고 뒤를 딤으로 덮는다 `[가정]`. X 버튼(`aria-label="상세 패널 닫기"`) · Esc · 타임라인 빈 곳 · 시트 바깥을 누르면 닫힌다. 이전 · 다음 사건 버튼은 패널을 연 채 사건만 바꾼다. 넓은 화면 패널은 420px 이고 본문 폭의 절반을 넘지 않는다. 화면 안에서 사건을 골라 열면 포커스가 패널 제목으로, 닫으면 그 사건 노드로 간다 (2026-10-28, S15P31A102-52). 닫으면 가로 타임라인은 처음 열었을 때 보기(배율 · 위치)로 돌아간다 — 사건을 보이려고 옮긴 자리 · 키운 배율에 멈추지 않는다 (2026-11-12 사용자 QA, S15P31A102-197) |
| 용어사전 말풍선 | 화면 고정 버튼은 없다(2026-11-10, S15P31A102-187 — 버튼 · 창을 뺐다). 본문의 드래그 대상 글을 고르면 선택 영역 옆에 뜬다. 넓은 화면은 위, 좁은 화면은 OS 메뉴(복사 · 붙여넣기)를 피해 아래가 먼저고, 뜻 카드가 다 커질 자리가 없으면 반대쪽에 둔다. 좁은 화면의 사건 시트 안 글이면 시트 안에 그린다 — 바깥에 그리면 누르는 순간 시트가 「바깥 누르기」로 닫힌다. 동작은 Component Patterns 「용어사전 말풍선」 |

## Component Patterns

동작만 적는다. 생김새는 `DESIGN.md` Components, 원본 패턴은 `imports/newlearn-design-system-v2/components/<패턴>/README.md` 에 있다. 여러 컴포넌트에 걸친 접근성 규칙(aria-label · 누르는 영역 · 포커스 이동)은 Accessibility Floor 에 있다.

| 컴포넌트 | 쓰는 곳 | 동작 |
| --- | --- | --- |
| 헤더 · 오른쪽 패널 · 용어사전 말풍선 | 셸 | [앱 셸](#앱-셸) |
| 로그인 · 가입 폼 | 로그인 · 가입 | *로그인* · *가입하기*를 누르면 칸마다 검사하고 틀린 칸 아래에 오류를 띄운다. 보내는 동안 버튼을 로딩 상태로 둔다. 문구는 State Patterns 에 있다. 닫기(X)를 누르면 랜딩으로 간다. 폼 아래 「아직 계정이 없나요?」 · 「이미 계정이 있나요?」 줄의 *회원가입* · *로그인* 으로 서로 오가고, 돌아올 곳(`next`)을 그대로 넘긴다. 아이디 글자 규칙(영문 소문자 · 숫자 · `_` 4 ~ 20자, `api-screen.md` A14)은 화면이 4자 미만만 먼저 보고 나머지는 서버 `reason` 으로 안내한다 (2026-11-03, S15P31A102-66). 가입은 단계마다 *다음* · Enter 가 그 단계 칸만 검사하고, 맞으면 다음 단계의 첫 칸으로 포커스를 옮긴다. *이전* 으로 돌아가도 쓴 값이 남는다. 서버가 칸 오류를 주면 틀린 칸이 있는 첫 단계로 돌아가 그 칸에 포커스하고, 다른 단계 칸의 오류는 그 단계에 가면 보인다 (2026-11-03, S15P31A102-66) |
| 분야 탭 (CategoryTabs) | 홈 추천 이슈 · 최신 기사, 분야별 이슈 | 하나만 고른다(`role="tab"` · `aria-selected`). 추천 이슈 · 분야별 이슈 탭은 관심 분야(별표) → 나머지 분야 → 스포츠 · 문화/연예 순이다. 스포츠 · 문화/연예는 준비 중이라 잠겨 있다 (State Patterns). 최신 기사 탭은 「전체」와 분야 탭이다. 탭이 넘치면 가로로 스크롤한다 |
| 관심 분야 칩 | 가입, 마이페이지 | 여러 개 고른다(`aria-pressed`). 고른 칩이 하나 이상 남아야 해서 마지막 남은 칩은 눌러도 풀리지 않는다. 스포츠 · 문화/연예는 준비 중이라 고를 수 없다(「스포츠 · 준비 중」). 안내 문구는 State Patterns 에 있다. 고른 칩은 체크 아이콘과 DESIGN.md 「선택된 필터 칩」 색, 안 고른 칩은 더하기 아이콘이다. 높이는 40px `[가정]` (2026-11-03, S15P31A102-66). 가입 마지막 단계의 사용 목적 칩(취업 준비 · 업무 · 업계 동향 · 시사 공부 · 그 밖에)도 같은 모양이지만 하나만 고르고, 다시 누르면 푼다 (2026-11-03, S15P31A102-66) |
| 관심 이슈 별 | 이슈 화면 머리 | 이슈 머리는 별 버튼(40px) — 넓은 화면은 제목 바로 옆, 좁은 화면은 분야 줄 · 제목 오른쪽 위(기사 머리 북마크와 같은 자리. 제목 옆에 두면 별이 첫 줄보다 내려가 보였다, 2026-11-12 사용자 S15P31A102-195). (프로토타입 v21 PinButton, 2026-11-05 S15P31A102-172). 누르면 저장(A23) · 해제(A24)하고 별은 응답의 `interested` 로 맞춘다. 이름은 「관심 이슈로 저장」이다. 상태로 이름을 바꾸지 않고 눌림(`aria-pressed`)으로 알린다. 보내는 동안 다시 눌러도 보내지 않는다. 401 이면 세션이 끝난 것이라 로그인 화면으로 간다. 그 밖의 실패는 스낵바 「관심 이슈를 바꾸지 못했어요. 잠시 후 다시 시도해 주세요.」 `[가정]` — 별 하나라 그 자리에 문장을 둘 곳이 없다 (2026-11-03, S15P31A102-68). 저장 · 해제하면 받아 둔 이슈 머리 · 이슈 목록(홈 추천 · 분야별 이슈 카드의 「관심 이슈」 표시)을 응답대로 바꾸고 관심 이슈 목록을 새로 받는다 |
| 필터 칩 | 이슈 화면 타임라인 필터 | P1 이다 (mvp-overview 6장). 넣으면 여러 개 고르고(`aria-pressed`) 「초기화」로 모두 푼다 |
| 이슈 카드 (IssueCard) | 홈 | 카드 전체가 누르는 면 하나다. 누르면 이슈 화면으로 간다. 사건이 0개인 이슈(A2 `lastEvent` null)는 「최근 사건」 줄을 두지 않는다 (2026-11-03, S15P31A102-159). 관심 이슈(`interested`)면 분야 옆에 별과 「관심 이슈」를 붙인다 — v21 은 「고정」(핀)이지만 우리 말은 관심 이슈(별)다 (PRD FR-28, 2026-11-05 S15P31A102-172) |
| 기사 행 (ArticleList) | 홈 최신 기사, 사건 패널 관련 기사 | 행 전체가 누르는 면이다. 누르면 기사 마인드맵으로 간다. 처음 몇 개를 보일지는 IA 표에 있고, *더 보기*를 누르면 다음 쪽을 불러 아래에 붙이고 붙인 첫 기사로 포커스를 옮긴다. 홈 최신 기사는 여러 분야가 섞여서 언론사 · 시각 뒤에 분야를 적는다(v21) |
| 북마크 버튼 | 기사 행, 기사 마인드맵 머리 | 누르면 담기(A20) · 빼기(A21)하고 응답의 `bookmarked` 로 맞춘다. 기사 행은 원문 보기 왼쪽의 아이콘 버튼(40px) — 이름 「{제목} 나의 뉴스함에 담기」는 그대로 두고 눌림(`aria-pressed`)으로 상태를 알린다. 기사 머리도 같은 아이콘 버튼(40px, 아이콘 22px — 이슈 머리 별과 같은 크기)이다. 좁은 화면은 분야 · 제목 칸 오른쪽 위, 넓은 화면은 원문 보기 왼쪽 — 글자 버튼 「북마크」 · 「북마크됨」은 폰에서 버튼 셋이 두 줄로 커서 뺐다 (2026-11-12 사용자, S15P31A102-195). 보내는 동안 다시 눌러도 보내지 않는다. 401 이면 세션이 끝난 것이라 로그인 화면으로 간다. 그 밖의 실패는 스낵바 「북마크를 바꾸지 못했어요. 잠시 후 다시 시도해 주세요.」 `[가정]` (2026-11-03, S15P31A102-67) |
| 사건 노드 (Timeline) | 이슈 화면 | 누르거나 Enter · Space 로 사건 패널을 연다. 노드는 메인 흐름 · 서브 흐름 두 레인에 놓인다. 레인은 사건의 역할로 백엔드가 정한다 — 상황을 바꾸는 행위는 메인, 다른 사건에 대한 반응 · 평가 · 여론은 서브 (`api-screen.md` A4, Jira 130). 가로는 시간 순서이고 간격은 시각 차이에 비례하지 않는다(프로토타입 v21 `LaneTimeline`). 마우스를 올리면 제목 · 날짜 · 기사 수 · 레인이 툴팁으로 뜨고, 키보드 포커스에도 같은 툴팁을 띄운다 `[가정]`. 사건 사이의 선과 관계 태그는 그리지 않는다 (`api-screen.md` A4). 고른 노드에는 `{components.list-row-selected}` 선택 표시가 남는다 |
| 보기 탭 | 기사 마인드맵 | 흐름지도 보기(기본) · 마인드맵 보기 중 하나를 고른다. 같은 A9 응답을 두 모양으로 그린다 (mvp-overview F04). 세부 노드를 누르면 그 노드를 강조한다(확대는 하지 않는다). 흐름지도 보기는 가지를 「무슨 일이? → 왜 일어났나? → 누가 뭐라고 했나? → 앞으로는?」 순서로 둔다. 흐름지도 자리(화면 폭이 아니라 본문 폭)가 1024px 이상이면 가지 하나가 한 열인 가로, 아니면 세로다. 잎은 문장 전체를 카드로 두고(전망 가지 잎에는 「전망·해석」 점선 태그), 누르면 강조하고 나머지 카드를 흐리게 한다. 다시 누르기 · 빈 곳 · Esc 로 푼다. 마인드맵 보기에서 가지(분류 원)를 누르면 그 가지만 확대하고 나머지는 흐리게 한다. 다시 누르기 · 빈 곳 · Esc · *화면에 맞추기* 로 전체로 돌아간다. 노드 상세 카드와 원문 근거는 F05(추후)라 띄우지 않는다. 마인드맵 보기 위 범례에는 있는 가지만 칩으로 둔다 — 누르면 그 가지를 숨기고 다시 누르면 되살리며, 하나라도 숨기면 *모두 보기* 가 생긴다. 전망 가지의 잎은 점선이고 범례에 「전망·해석」으로 적는다. 그래프 왼쪽 아래에 확대 · 축소 · *화면에 맞추기*, 오른쪽 위 톱니(*탐색 설정*)에 「라벨 표시」 스위치(기본 켬)를 둔다 — 끄면 강조 · 키보드 포커스 · 마우스를 올린 잎만 글을 보인다. Esc 는 설정 창 → 가지 포커스 · 강조 순으로 닫는다. 보기 탭을 오가도 숨긴 가지 · 라벨 표시는 남고, 확대 · 가지 포커스 · 강조는 풀린다. 보기 탭 줄 오른쪽 끝 *크게 보기*(그린 보기가 있을 때만)는 지금 보기를 화면을 꽉 채운 창으로 다시 그린다 — 머리는 기사 제목 · *작게 보기*, Esc 로도 닫히고 포커스는 *크게 보기* 로 돌아온다. 숨긴 가지 · 라벨 표시는 그대로, 확대 · 포커스 · 강조는 창에서 새로 시작한다. 아이폰 사파리는 Fullscreen API 를 영상에만 허락해서 브라우저 전체 화면이 아니라 화면을 덮는 창이다 (2026-11-12 사용자, S15P31A102-195). 처음 열 때와 *화면에 맞추기* 는 어느 폭에서나 가운데 기사 제목을 그래프 칸 가운데 두고 지도 전체가 들어오게 맞춘다(최대 115%). 좁은 화면에서는 글이 작아진다 — 손가락으로 키우거나 크게 보기로 본다 (2026-11-12 사용자 「메인이 가장 가운데로」 「모두 보이게」, S15P31A102-195. 전에는 폰에서 72% 아래로 줄이지 않아 가장자리가 잘렸다) |
| 용어사전 말풍선 | 셸 | 기사 제목 · 흐름지도 잎 · 마인드맵 보기의 잎과 가운데 제목 · 이슈 제목과 요약 · 사건 패널 제목과 요약 · 타임라인 사건 이름을 드래그하면, 선택 영역 옆에 「의미」 버튼 하나만 든 작은 말풍선이 뜬다(Claude 데스크톱 앱의 선택 말풍선처럼). 날짜 · 언론사 · 가지 이름 · 레인 이름 같은 고정 문구와 메뉴 · 목록은 대상이 아니다. 「라벨 표시」를 끈 마인드맵의 잎 글도 대상이 아니다. 「의미」를 누르기 전에는 서버를 부르지 않는다. 누르면 메인 컬러 점 셋이 하나씩 위로 튀고(0.9초 주기, 한 번에 한 점, 동작 줄이기면 멈춘 점), 뜻이 오면 말풍선이 200ms 로 커지며 표제어 · 품사 · 뜻풀이를 보인다. 「AI 생성」 표시는 붙이지 않는다(2026-11-10 사용자 결정, Jira 188 — AI 요약 · 마인드맵의 표시 규칙은 그대로). 공백 · 문장부호 · 숫자만, 앞 글자에 붙은 한 글자(「받은」의 「은」), 영문 · 숫자 낱말의 중간(「F13」의 「F1」), 50자 · 6어절 초과, 문장 경계 · 줄바꿈 · 여러 글에 걸친 선택, 줄임표에 닿은 낱말에는 뜨지 않는다 — 규칙과 시험은 `frontend/src/components/meaning/pickTerm.ts`. 마인드맵 보기 · 가로 타임라인은 글 위에서 누르면 글을 고르고 빈 곳 · 노드에서 누르면 지금처럼 지도를 옮긴다. 드래그 끝에 따라오는 클릭은 잎 강조 · 사건 열기 · 패널 닫기로 치지 않는다. 바깥 누르기 · Esc · 휠 · 스크롤 · 화면 크기 바뀜 · 다른 화면으로 가면 닫는다. 기다리는 중 다른 말을 고르면 앞 답은 버린다. 찾은 것은 어디에도 저장하지 않는다 (S15P31A102-187) |
| 버튼 | 전역 | SEED ActionButton. 요청을 보내는 동안 `loading` 으로 두어 다시 누르지 못하게 한다 |
| 스낵바 | 전역 | 짧은 알림 한 줄. 2.4초 뒤 사라진다. 오류는 스낵바로 알리지 않고 실패한 영역 자리에 둔다 `[가정]` |
| 곧 제공 항목 | 이슈 헤더 *관점 비교* · *새 기사 알림 받기* | P2 · 미정 기능 자리다. 누를 수 있고 키보드로도 닿는다. 누르면 스낵바 「MVP 이후 제공 예정인 기능이에요」가 뜬다. 비활성으로 두지 않는다. 비활성 버튼에는 키보드로 닿을 수 없어 사용자가 안내를 못 받는다 |

## State Patterns

**공통 규칙**
- **불러오는 중**에는 그 자리 모양을 딴 스켈레톤을 둔다 (반짝임 모양은 `DESIGN.md`). 스피너는 버튼 안 로딩에만 쓴다 `[가정]`.
- **빈 결과**에는 그 자리에 빈 상태 문구를 둔다. 문구는 아래 표에 있다.
- **불러오기 실패**는 실패한 영역 자리에 안내와 *다시 시도*를 둔다. 화면 전체를 오류로 바꾸지 않는다 `[가정]`. 안내 문구 예는 Voice and Tone 에 있다.
- **없는 것**(`_NOT_FOUND`, 없는 주소)은 화면 전체를 찾을 수 없음 화면으로 바꾼다 (Information Architecture).
- 오류 코드별 문구와 할 일은 `docs/api.md` 2절이 정한다. 그 밖의 화면 상태 문구는 아래 표가 정한다. `api.md` 가 말하는 일반 오류 안내에는 「일시적으로 서비스를 사용할 수 없어요. 잠시 후 다시 시도해 주세요.」를 쓴다 (v2 `07-writing.md`).

| 상태 | 화면 | 처리 |
| --- | --- | --- |
| 분야에 이슈 없음 | 홈 | 「이 분야의 이슈가 아직 없어요」 (그 분야의 A2 결과가 비었을 때. A1 `issueCount` 가 0인 것과 같다) |
| 분야에 기사 없음 | 홈 최신 기사 | 「이 분야의 기사가 아직 없어요」 (그 분야의 A7 결과가 비었을 때. 「전체」도 같은 문구) |
| 준비 중인 분야 | 홈, 가입, 마이페이지 | 스포츠 · 문화/연예 탭이나 칩을 누르면 「…는 준비 중이에요」를 안내한다 |
| 관심 분야 0개 | 가입, 마이페이지 | 마지막 남은 칩을 누르면 「관심 분야를 1개 이상 골라 주세요.」. 가입은 하나도 고르지 않고 보내도 같은 안내다(마이페이지는 저장된 것과 같으면 저장을 누를 수 없어 이 경우가 없다, 2026-11-12 S15P31A102-195) |
| 사건 없는 이슈 | 이슈 화면 | 타임라인 자리에 「아직 이 이슈에 정리된 사건이 없어요」 `[가정]` (A4 `events` 가 비었을 때, 2026-10-28) |
| 필터 결과 없음 | 이슈 화면 | 필터와 함께 P1. 「조건에 맞는 사건이 없어요」 |
| 관련 기사 없음 | 사건 패널 | 「아직 이 사건을 다룬 기사가 없어요.」 |
| 관심 이슈 없음 | 마이페이지 | 「아직 저장한 이슈가 없어요. 이슈 이름 옆 별표를 눌러 보세요.」 (A25 `items` 가 비었을 때, v21) |
| 담은 기사 없음 | 나의 뉴스함 | 「아직 담은 기사가 없어요. 기사 옆 북마크를 누르면 여기에 모여요.」 (A22 `items` 가 비었을 때, v21) |
| 없는 사건 | 사건 패널 | 주소의 이슈는 있으니 화면 전체를 바꾸지 않고 패널 안에 「사건을 찾을 수 없어요」 (`EVENT_NOT_FOUND`). 위 「없는 것」 규칙의 예외다 `[가정]` (2026-10-28) |
| 마인드맵 분석 중 | 기사 행, 기사 마인드맵 | `mindmapStatus` 가 `QUEUED` 면 「분석 중」을 표시한다. 기사 마인드맵에서는 `MINDMAP_NOT_FOUND` 를 받으면 A8 의 `mindmapStatus` 를 본다 (`api-screen.md`). 마인드맵 자리에 `QUEUED` 면 「기사를 분석하고 있어요」, 그 밖(`NONE` · `FAILED` · `NOT_ANALYZABLE`)이면 「이 기사의 마인드맵이 아직 없어요」, 모르는 마인드맵 버전이면 「이 마인드맵은 지금 보여 드릴 수 없어요」, 가지가 하나도 없으면 「이 기사에서 정리한 내용이 없어요」를 둔다 `[가정]` (2026-10-30) |
| 사건 연결 상태 | 기사 마인드맵의 *이 기사가 속한 이슈 보기* | A8 `eventMatchStatus` 를 본다. 다음 두 경우에는 버튼 대신 문구를 둔다 `[가정]`. `QUEUED` 면 「사건을 찾는 중이에요」, `SUCCEEDED` 인데 `issue` 가 없으면 「아직 이슈로 묶이지 않았어요」. `issue` 가 있으면 버튼을 눌러 사건 패널이 열린 이슈 화면으로 간다. `NONE` · `FAILED` · `NO_EVENT` 면 아무것도 두지 않는다 `[가정]` (2026-10-30) |
| 입력 오류 | 로그인, 가입 | 화면이 먼저 검사한다: 「아이디를 입력해 주세요.」 · 「비밀번호를 입력해 주세요.」 · 「이름을 입력해 주세요.」 · 「아이디는 4자 이상으로 입력해 주세요.」 · 「비밀번호는 8자 이상으로 입력해 주세요.」 · 「비밀번호가 서로 달라요.」. 서버가 `VALIDATION_FAILED` 를 주면 `errors[].reason` 을 오류가 난 칸 아래에 그대로 띄운다 (`api.md` 2절) |
| 로그인 실패 · 아이디 겹침 | 로그인, 가입 | `LOGIN_FAILED` 는 폼 안에, `LOGIN_ID_TAKEN` 은 아이디 칸 아래에 띄운다. 문구는 `api.md` 2절 |
| 용어사전 풀이 불가 | 용어사전 말풍선 | 「뜻을 풀이하기 어려워요. 낱말 전체를 골라 보세요.」 — A26 이 세 칸 null 로 답할 때(말 조각 · 문맥에 근거 없음) |
| 용어사전 서버 오류 | 용어사전 말풍선 | `DICTIONARY_UNAVAILABLE` 이면 「지금은 찾을 수 없어요」, `RATE_LIMITED`(코드 없는 429 포함)이면 「요청이 많아요. 잠시 뒤 다시 시도해 주세요」를 말풍선 안에 띄운다(`api.md` 2절). 연결 실패 · 그 밖의 오류는 일반 오류 안내. 다시 부르지 않는다 — 다시 드래그해 누르면 된다 |
| 성공 알림 | 로그인, 가입, 마이페이지, 이슈 화면, 북마크 | 스낵바 「로그인했어요」 · 「가입을 마쳤어요」 · 「관심사를 저장했어요」 · 「로그아웃했어요」(랜딩에 뜬다) · 「관심 이슈로 저장했어요」 · 「관심 이슈에서 뺐어요」 · 「나의 뉴스함에 담았어요」 · 「나의 뉴스함에서 뺐어요」 |

## Interaction Primitives

마우스와 터치가 먼저다. 키보드로도 모든 기능에 닿는다.

**키보드**
- Esc — 맨 위에 열린 것 하나만 닫는다. 닫는 순서는 팝오버 · 메뉴 → 모달(확인 창 · 크게 보기 · 사건 시트) → 오른쪽 패널이다. 용어사전 말풍선은 그 무엇보다 먼저 닫힌다(캡처 단계, S15P31A102-187).
- Enter · Space — 노드 · 카드 · 탭을 고른다.
- 검색 단축키는 Information Architecture 의 통합 검색 행에 있다. 용어사전에는 단축키 · 버튼이 없고 글을 드래그해 연다(2026-11-09 사용자, S15P31A102-187). MVP 개요의 「단축키나 버튼」 문구는 PM 확인을 거쳐 고친다.

**호버 · 눌림** (v2 `02-feedback.md`, 모양은 `DESIGN.md` 상태별 모양)
- 호버에만 기대는 기능을 두지 않는다. 호버는 마우스가 있는 기기에서만 보인다.
- 이슈 카드 「흐름 보기 ›」 · 기사 행 「마인드맵 보기 ›」는 호버 · 키보드 포커스 때만 나타나는 안내다. 카드 · 행 전체가 이미 링크라 안 보여도 쓸 수 있고, 화면 읽기에서 뺀다(링크 이름은 그대로). 「마인드맵 보기」는 마인드맵이 있는 기사(`SUCCEEDED`)에만, 마우스가 있는 768px 이상 홈 최신 기사 · 나의 뉴스함에만 둔다 — 안 보일 때도 자리를 차지해서 터치 태블릿에서는 두지 않고, 사건 패널은 좁아서 뺀다 (프로토타입 v21, S15P31A102-184). 모양은 `DESIGN.md` IssueCard · ArticleList.
- 축소(누르면 살짝 작아지는 효과)는 누르는 면이 하나인 요소(카드 · 버튼 · 칩)에만 쓴다. 문장 속 링크에는 쓰지 않는다. 줄어드는 요소 안에 든 요소는 따로 줄이지 않는다. 로딩 중에도 줄이지 않는다. 탭은 색 대신 축소만 쓴다.
- 색 전환과 축소는 둘 다 150ms 라서 한 반응으로 읽힌다.

**모션** (v2 `01-motion.md`)
- 작은 움직임은 200ms(`duration-d4`) 이하, 큰 움직임은 250~300ms 다.
- 오른쪽 패널과 시트는 열릴 때 300ms(`enter` 곡선), 닫힐 때 250ms(`exit` 곡선)다. 프로토타입의 220ms 는 따르지 않는다.
- 동작 줄이기(`prefers-reduced-motion`)를 켜면 위치 · 크기 변화를 없애거나 짧은 페이드로 바꾼다. 색 전환은 남긴다.
- 랜딩은 위 숫자의 예외다 — 프로토타입 v21 값을 따른다 (2026-11-12 사용자, S15P31A102-32). 첫 화면은 한 줄 소개(460ms) · NEW:LEARN(줄 아래에서 올라옴 760ms, 180ms 뒤) · 설명 · 버튼(560ms, 400 · 520ms 뒤)이 차례로 떠오르고 900ms 에 *어떻게 정리하나요* 가 나타나며 그 화살표는 1.8초 주기로 까딱인다. 뒤의 노드 그물은 선이 900ms 로 그려지고 노드가 520ms 로 튀어나온 뒤(차례로) 몇 px 씩 떠다니고, 1.6초부터 민트 점 셋이 2.4초마다 다른 선을 따라 달리며 그 선을 밝힌다(화면에 보일 때만). 기사 제목 띠 두 줄은 70초 · 80초에 한 바퀴씩 서로 반대로 흐른다. 섹션 제목 · 칸은 화면에 들어오면 16px 아래에서 500ms 로 떠오른다(칸마다 70ms 간격). 스크롤 연출 둘은 화면에 붙은 채(330 · 410svh) 내리는 만큼 장면이 바뀌고, 스크롤을 한 장마다 남은 거리의 14% 씩 따라가 부드럽다. 흐름지도 · 마인드맵 미리보기는 2.6 · 2.8초마다 강조한 잎이 바뀌고, 잎에 마우스 · 키보드 포커스가 오면 멈추며 화면 밖이면 멈춘다. 마인드맵 미리보기의 노드는 몇 px 씩 떠다닌다 — 실제 마인드맵 잎은 읽기 어려워 떠다니지 않게 했지만(2026-11-10, S15P31A102-188) 미리보기는 장식이라 프로토타입대로 둔다. 자주 묻는 질문의 답은 180ms 에 나타난다. 동작 줄이기를 켜면 모두 멈춘 그림이고 스크롤 연출은 화면에 붙이지 않고 마지막 장면을 보인다 — 그때 보기 버튼은 미리보기를 바로 바꾸고, 단계 번호는 옮길 장면이 없어 누르지 않는 표시다.
- 홈 인사 줄은 회원 정보가 오면 타자 치듯 한 글자에 30ms 로 찍히고 끝의 막대 커서가 0.9초 더 깜빡인 뒤 사라진다. 화면 읽기에는 처음부터 전체 문장을 준다. 「새로운 이슈」 3개는 한 줄에 하나씩 보이고 3초마다 지금 제목이 위로 빠지며 다음 제목이 아래에서 올라온다(350ms). 마우스를 올리거나 키보드로 들어오면 멈추고 키보드로 온 링크를 보이며, 바뀔 때 화면 읽기가 읽지 않는다. 동작 줄이기를 켜면 인사 줄은 바로 전체, 「새로운 이슈」는 셋을 한 줄에 둔다 (2026-11-12 사용자, S15P31A102-32).
- 가입은 단계가 바뀔 때 질문과 칸이 300ms 로 아래에서 떠오르고, 진행 막대는 300ms `enter` 곡선으로 찬다.
- 홈 첫 화면(인사 · 검색창) 뒤에는 마인드맵 모양 배경을 깐다 — 작은 네모 노드 22개를 가까운 것끼리 잇고 가운데는 비운다. 노드는 16 ~ 31초 주기로 몇 px 씩 떠다니는데, 위 숫자의 예외다. 동작 줄이기를 켜면 멈춘다. 장식이라 화면 읽기에서 빼고 누를 수 없다 (프로토타입 v21 `HomeHeroBg`, 2026-11-04 S15P31A102-168).
- 랜딩 · 가입에는 마우스를 조금 늦게 따라오는 원 커서를 덧붙인다. 누를 수 있는 것 위에서 1.5배 커진다. 원래 커서는 그대로 두고, 마우스(`hover: hover` · `pointer: fine`)일 때만 띄우며 동작 줄이기를 켜면 띄우지 않는다. 장식이라 화면 읽기에서 뺀다 (2026-11-03, S15P31A102-66).
- 앱 전체의 등장도 위 숫자의 예외다 — 프로토타입 값을 따른다 (2026-11-06 사용자 결정, 프로토타입 v21 · 모바일 v1, S15P31A102-184). 셸 안 화면은 다른 화면으로 갈 때마다 본문이 10px 아래에서 300ms 로 떠오른다(쿼리만 바뀌면 그대로). 기사 · 이슈 화면은 빼고 위 예외의 등장만 쓴다 — 본문 높이를 꽉 채워서 옮기면 스크롤바가 잠깐 생긴다. 홈 추천 이슈 · 분야별 이슈 카드는 하나에 440ms 로 45ms 간격, 목록 행(홈 최신 기사 · 나의 뉴스함)은 하나에 380ms 로 30ms 간격으로 떠오르고, 차례는 카드 8번째 · 행 10번째부터 같이 나온다. 분야를 바꾸면 다시 나온다. 홈 배경은 520ms 에 걸쳐 나타난다. 로그인은 화면이 150ms 에 나타나며 폼이 260ms 로 떠오른다. 검색 목록은 120ms, 좁은 화면 홈 보기 탭 내용은 180ms 에 나타나고, 용어사전 말풍선은 사전 쪽 200ms · 내 질문 160ms 로 떠오른다. 호버 안내는 왼쪽 4px 에서 미끄러지며 나타난다(카드 150ms · 행 180ms). 동작 줄이기를 켜면 모두 처음부터 다 그린 모양이고, 호버 안내는 미끄러지지 않고 나타나기만 한다.
- 기사 화면(기사 머리 · 흐름지도 · 마인드맵 보기)과 이슈 화면(이슈 머리 · 이슈 흐름 · 사건 패널)은 위 숫자의 예외다 — 하나하나 500 ~ 650ms 로 넘쳤다 자리 잡으며 차례로 나오고, 다 나오기까지 2초가 안 걸린다(잎이 많으면 차례 간격을 묶는다). 보기 탭을 바꿀 때마다 다시 나온다 (2026-11-05 사용자 「밋밋하다」, 프로토타입 v21 을 키웠다). 기사 머리는 분야 → 제목 → 정보 → 버튼 순서로 떠오른다. 흐름지도는 머리 줄 → 가지 열(300ms 간격)이다 — 번호 원이 튀어나오며 파문이 번지고, 다음 번호로 선이 자라며 그 끝을 따라 가지색 점이 달려가, 점이 닿을 즈음 다음 번호 원이 나온다. 열 안에서는 질문 → 잎 카드(60ms 간격)다. 마인드맵은 가운데가 튀어나오며 파문이 번지고, 가지가 가운데에서(A9 순서로 90ms 간격) · 잎이 그 가지에서(50ms 간격) 날아 나온다. 선은 날아가는 노드를 따라 뻗는다. 다 나온 뒤에도 가운데 원 · 흐름지도 머리 줄 점은 3초마다 파문이 번진다 — 홈 배경처럼 계속 도는 꾸밈이다. 마인드맵 잎은 날아 나온 뒤 제자리에 선다(2026-11-10 둥실을 뺐다 — 잎 글이 계속 움직여 읽기 어려웠다, Jira 188). 강조한 잎은 원이 한 번 튀고 파문이 번진다. 마인드맵 노드에 마우스를 올리면 넘치며 커지고, 가운데에서 그 노드까지 이어진 것(가지면 그 잎들까지)만 또렷이 두고 나머지를 흐리며, 그 길 위로 점선이 바깥쪽으로 흐른다 — 마우스 · 펜일 때만이다. 터치는 누르면 마우스 흉내가 와서 강조와 겹치기 때문이다. 가지를 포커스한 동안에는 그 가지 안에서만 그렇게 하고, 키보드로 옮긴 노드는 가지 포커스로도 흐리지 않는다. 흐름지도 잎 카드는 마우스를 올리면 2px 들리고 원이 커진다. 모양은 `DESIGN.md` Components 「기사 마인드맵 두 보기」. 이슈 화면은 이슈 머리가 분야 → 제목 → 요약 순서로 떠오르고, 이슈 흐름은 레인 이름이 먼저 나온 뒤 메인 흐름 선이 첫 사건에서 마지막 사건까지 같은 빠르기로 뻗으며(사건 수만큼 늘되 1초까지) 선 끝이 지나는 자리의 사건이 튀어나온다. 같은 시각 사건은 함께, 서브 흐름 사건은 그 자리를 선이 지나간 뒤 조금 늦게, 라벨 · 달 눈금은 그 사건 · 자리를 따라 나온다. 사건에 마우스를 올리면 넘치며 커지고 툴팁이 나타난다. 사건을 고르면 둘레에 파문이 번지고 시간축 날짜 표시가 튀어나온다. 사건 패널은 열거나 이전 · 다음으로 바꿀 때마다 속한 이슈 → 제목 → 날짜 → 요약 → 관련 기사(한 줄씩) 차례로 떠오른다 — 이전 · 다음 버튼은 포커스를 지키려고 다시 그리지 않는다. 동작 줄이기를 켜면 두 화면 모두 처음부터 다 그린 모양이고 파문 · 달리는 점 · 흐르는 점선도 없다. 흐리기 · 색 전환만 남는다.

## Accessibility Floor

**보기**
- 목표 수준은 WCAG 2.1 AA 다 `[가정]`.
- 색만으로 정보를 전하지 않는다. 글자와 아이콘을 함께 쓴다.
- 글자 크기를 rem 으로 정해 브라우저 글자 크기 설정을 따라 커지게 한다.

**포커스**
- 키보드 포커스는 늘 보인다. 카드 · 칩은 윤곽선을 바깥으로 띄우고 리스트 행 · 탭은 안쪽에 그린다 (윤곽선 모양은 `DESIGN.md` 상태별 모양).
- 다른 화면으로 가면 브라우저 탭 제목(`<title>`)을 그 화면 이름으로 바꾸고 포커스를 화면 맨 위 제목으로 옮긴다 `[가정]`.
- 모달을 열면 포커스가 모달 안 첫 입력으로 가고 닫으면 모달을 연 버튼으로 돌아간다 (SEED Dialog). 오른쪽 패널도 마찬가지다 `[가정]`. 용어사전 말풍선은 포커스를 가져가지 않는다 — 고른 글이 풀리지 않게. 그래서 키보드만 쓰는 사람은 Shift+화살표로 고르면 말풍선은 뜨지만 「의미」까지 Tab 으로 가기 어렵다. 옛 창의 입력칸 경로가 없어진 한계로 남긴다 (2026-11-10, S15P31A102-187).
- DOM 순서를 화면에서 읽는 순서와 같게 둔다.

**스크린 리더**
- 지금 위치는 `aria-current` 로 알린다 (헤더의 지금 화면 버튼, 고른 이슈 카드 · 기사 행). 탭 · 칩의 ARIA 는 Component Patterns 에 있다.
- 아이콘만 있는 버튼에는 `aria-label` 을 단다. 옆에 같은 뜻의 글자가 있는 아이콘과 장식 아이콘은 `aria-hidden` 이다. 뜻이 있는 이미지에는 짧은 대체 텍스트를 붙인다.
- 입력 오류는 그 칸에 이어서 읽히게 한다(`aria-describedby`) `[가정]`.
- 스낵바와 용어사전 말풍선의 뜻 · 실패 안내는 `aria-live` 로 읽어 준다 `[가정]`.

**누르기**
- 누르는 영역은 44px 이상을 목표로 하고 24px 아래로는 내리지 않는다. 아이콘 버튼은 40px 다. 아이콘을 키우지 않고 여백으로 넓힌다. 줄 안에 들어가는 작은 아이콘 버튼은 28px 까지 줄일 수 있다 — 줄 높이를 넘지 않게, 24px 하한은 지킨다 (2026-11-05, S15P31A102-172).
- 맵의 핀치 줌 · 드래그는 누르기만으로도 할 수 있게 대체 수단을 둔다 (v2 `05-inclusive-design.md`). 어떻게 할지는 F04 · F07 화면을 설계할 때 정한다.

## Key Flows

페르소나와 여정 전체는 `docs/user-flow.md` 에 있다. user-flow 는 10월 20일 회의 전 내용이라, 여기서는 각 여정이 지금 지나는 주소와 상태를 적는다.

### Flow A — 사쿠, 매일 아침 동향을 챙기는 취준생

1. `/` 랜딩에서 *서비스 시작하기*를 누르고 `/login?next=/home` 에서 로그인한다.
2. `/home` 추천 이슈의 맨 앞 탭은 관심 분야 「경제」다. 그 탭의 이슈 카드를 누른다.
3. `/issues/:issueId` 에서 이슈 헤더와 타임라인을 본다.
4. 가장 최근 사건을 누른다. 주소에 `?event=` 가 붙고 사건 패널이 열린다.
5. **핵심 순간** — 미정 ([아직 정하지 않은 것](#아직-정하지-않은-것)).

실패: 로그인에 실패하면 폼 안에 안내가 뜬다. 타임라인을 불러오지 못하면 그 자리에 *다시 시도*가 뜬다.

### Flow B — 요섭, 점심에 업계 기사를 읽는 직장인

1. `/home` 에서 최신 기사를 누른다. `/articles/:articleId` 가 흐름지도 보기로 열린다.
2. 가지 네 개를 위에서 아래로 읽는다.
3. *이 기사가 속한 이슈 보기*를 누른다. 이슈 화면(`/issues/:issueId?event=:eventId`)이 이 기사가 속한 사건을 고른 채 열린다 (F11).
4. **핵심 순간** — 미정 ([아직 정하지 않은 것](#아직-정하지-않은-것)).

실패: 마인드맵이 아직 없으면 「분석 중」을 안내한다. 기사가 아직 이슈로 묶이지 않았으면 버튼 대신 안내 문구가 뜬다.
