# NEW:LEARN 경험 설계

NEW:LEARN 화면이 **어떻게 동작하는지** 정한다. 화면 목록과 이동, 상태, 문구, 키보드, 접근성, 화면 크기별 변화를 다룬다. 생김새(색 · 글자 · 모양)는 `DESIGN.md` 가 정한다.
동작은 SEED Design 기본값을 그대로 쓰고, 이 문서에는 SEED 와 다른 것과 NEW:LEARN 에만 있는 것을 적는다.

- **범위**는 확정 기능(F01~F08 · F11)이다. 기사 마인드맵(F04 · F05)과 이슈 에볼루션 맵(F07)의 맵 안 배치 · 조작, F09 · F10 은 맨 끝 「아직 정하지 않은 것」에 있다.
- 근거 문서가 없어 이 문서에서 정한 곳은 `[가정]` 으로 표시한다.
- 프로토타입 · 디자인 시스템 v2 원본과 이 문서가 다르면 이 문서를 따른다.
- 절 제목은 BMAD 검사가 이름으로 찾기 때문에 영어로 둔다.

## Foundation

- **반응형 웹 하나.** PC 1280px 이상을 기준으로 설계하고, 모바일 360~430px 에서는 깨지지 않게만 한다. 모바일 다듬기는 일정에 여유가 있을 때 한다. 앱 · PWA 는 만들지 않는다 (PRD 1.1 · 4.10 · 4.11).
- **브라우저**는 최신 Chrome · Edge 다 `[가정]` (PRD 에도 가정으로 표시돼 있다).
- **UI 시스템**은 SEED Design 3 (React) 이다. 포커스 이동 · Esc · aria 같은 컴포넌트 동작은 SEED 를 따른다.
- **라이트 테마 고정**이다 (`DESIGN.md` Brand & Style).
- **기준 프로토타입**은 v15 다. 화면 이동 · 패널 · 키보드 · 상태 문구는 v13 과 같다.
- **로그인이 없다.** 로그인이 필요한 나의 뉴스함 · 마이페이지 · 북마크는 P2 다.

## Information Architecture

화면마다 주소가 있다. 주소를 복사해 열면 같은 화면, 같은 선택이 나온다. 고른 사건 · 노드는 주소 뒤에 쿼리로 붙인다. 그래야 F11 기사·이슈 양방향 연결에서 사건이 골라진 채 열리고, 브라우저 뒤로 가기가 된다.

| 화면 | 주소 | 들어오는 길 | 하는 일 | API |
| --- | --- | --- | --- | --- |
| 랜딩 | `/` | 처음 방문 | 서비스 소개. *서비스 둘러보기* → 홈, *기사로 마인드맵 만들기* → 홈 + URL 입력 모달. 소개 메뉴는 같은 페이지 안에서 스크롤한다 | — |
| 홈 | `/home` | 로고, 사이드바 *홈*, 랜딩 | 7개 분야 탭, 고른 분야의 이슈 카드(최근 업데이트 순), 최신 기사 | A1 · A2 · A7 |
| 이슈 화면 | `/issues/:issueId` | 이슈 카드, 사이드바 이슈 | 이슈 헤더와 사건 타임라인 (F07) | A3 · A4 |
| 사건 패널 | `/issues/:issueId?event=:eventId` | 타임라인 사건 노드, 사이드바 사건, 기사 마인드맵 *이 기사가 속한 이슈 보기* | 사건 요약, 관련 기사 4건과 *더 보기*, 이전 · 다음 사건 (F08) | A5 · A6 |
| 기사 마인드맵 | `/articles/:articleId` | 최신 기사, 사건 패널의 관련 기사, 분석 완료 | 기사 머리, 마인드맵 (F04), *이 기사가 속한 이슈 보기* | A8 · A9 |
| 노드 패널 | `/articles/:articleId?node=:nodeId` | 마인드맵 노드 | 노드 요약, 원문 근거, 문단 위치 (F05) | A9 |
| URL 입력 모달 | 주소 없음 | 헤더 *마인드맵 만들기*, 랜딩 | 지원 출처 기사 URL 입력 (PRD FR-32) | A10 · A12 |
| 분석 중 | `/analyze/:jobId` | URL 제출 | 분석 진행 표시. 끝나면 기사 마인드맵으로 바뀐다 | A11 |
| 찾을 수 없음 | 그 밖의 주소 | 없는 주소, `_NOT_FOUND` 오류 | 무엇이 없는지와 *홈으로* | — |
| 통합 검색 | 홈 검색창 | ⌘/Ctrl+K | 이슈 · 사건 · 기사로 나눈 결과. **MVP 포함 미정** (Jira S15P31A102-46) | A13 |
| 나의 뉴스함 · 마이페이지 | — | 헤더, 사이드바 | P2. 누르면 「곧 제공」 안내 (Component Patterns) | — |

**이동 규칙**
- 누른 것이 무엇이냐에 따라 도착 화면이 정해진다. 기사는 기사 마인드맵, 이슈는 이슈 화면, 사건은 이슈 화면과 사건 패널이다. 기사와 이슈는 아이콘으로 구분한다. 기사는 문서 아이콘, 이슈는 갈래 아이콘이다 (PRD FR-30).
- 화면을 옮기면 주소 기록을 쌓는다. 같은 화면 안에서 고른 것만 바꾸면(다른 사건 고르기, 패널 닫기) 기록을 쌓지 않고 바꿔 놓는다 `[가정]`. 뒤로 가기는 앞 화면으로 간다.
- 분석이 끝나 기사 마인드맵으로 갈 때는 분석 중 주소를 바꿔 놓는다. 뒤로 가기를 눌러도 분석 중 화면으로 돌아오지 않는다 `[가정]`.
- 홈에서 고른 분야는 `/home?category=` 로 남긴다 `[가정]`.
- 프로토타입의 앱 안 탭(열린 화면 띠)은 만들지 않는다. 여러 탭은 P2 다 (PRD FR-27).

**앱 셸** — 랜딩을 뺀 모든 화면은 헤더 · 사이드바 · 본문 · 오른쪽 패널 네 영역으로 짠다 (v2 `Foundations/04-layout.md`). 랜딩은 셸 없이 혼자 뜬다. 프로토타입에서도 랜딩은 앱 앞에 따로 뜬다.

- **헤더**는 위에 붙어 있고, 왼쪽부터 아래 순서다.
  - 메뉴 열기: md 미만에서만 보인다.
  - 로고: 홈으로 가서 패널을 닫고 맨 위로 올린다.
  - 오른쪽: *마인드맵 만들기*, 나의 뉴스함, 마이페이지. md 미만에서는 글자 없이 아이콘만 보인다 `[가정]`.
- **사이드바**는 md 이상에서 보인다. ⌘/Ctrl+\ 나 펼치기 버튼으로 접고(64px) 편다(216px). 끌어서 폭을 바꾸지는 않는다. 처음에는 접혀 있다 (프로토타입).
  - 펼치면 빠른 이동과 이슈 탐색(분야 → 연도 → 이슈 → 사건)이 보인다 (PRD FR-3). 빠른 이동은 통합 검색이라 검색과 함께 MVP 포함 미정이다. 이슈를 누르면 이슈 화면, 사건을 누르면 사건 패널이 열린다.
  - md 미만에서는 서랍이 된다. 헤더 메뉴로 열고, 바깥 어두운 막 · Esc · 항목 선택으로 닫는다.
  - md 이상에서 오른쪽 패널이 열리면 사이드바를 접는다.

## Voice and Tone

화면 문구 규칙이다. 브랜드 분위기는 `DESIGN.md` Brand & Style 이 정한다.

| 한다 | 하지 않는다 |
| --- | --- |
| 해요체, 아라비아 숫자, 한 문장에 한 내용 (v2 `07-writing.md`) | 딱딱한 공문체, 한 문장에 여러 안내 |
| 오류에는 할 수 있는 일을 적는다 — 「타임라인을 불러오지 못했어요. 네트워크 상태를 확인한 뒤 다시 시도해 주세요.」 | 오류 코드 · 서버 메시지(`detail` · `message`)를 화면에 그대로 내기 (`api.md` 1절) |
| 사용자가 조심해야 하는 자동 메시지는 「~니다」 — 「지원하지 않는 출처의 기사입니다」 | 경고를 겁주는 말투로 쓰기 |
| 보도가 엇갈리면 「상충 후보」, 사용자가 확인해 볼 지점으로 쓴다 | 「오보」 · 「거짓」, 어느 쪽이 맞는지 판정하는 말 (PRD 원칙) |

| 근거 문장은 원문 그대로, 요약과 나눠 둔다 | 근거를 고쳐 쓰거나 요약에 섞기 |

| 「사건 3개 · 기사 12개」. 0이면 그 항목을 뺀다 (v2 IssueCard) | 「사건 0건」 |

## Component Patterns

동작만 적는다. 생김새는 `DESIGN.md` Components, 원본 패턴은 `imports/newlearn-design-system-v2/components/<패턴>/README.md` 에 있다.

| 컴포넌트 | 쓰는 곳 | 동작 |
| --- | --- | --- |
| 헤더 · 사이드바 | 랜딩 밖 모든 화면 | Information Architecture 「앱 셸」 |
| 오른쪽 패널 | 이슈 화면, 기사 마인드맵 | 한 번에 하나만 열린다. 사건 패널과 노드 패널이 같은 자리를 쓴다. md 이상에서는 본문 오른쪽에 붙는 420px 패널이고, 본문을 덮지 않고 좁힌다. md 미만에서는 아래에서 올라오는 시트(화면 높이 85%)이고 뒤를 `bg-overlay` 로 덮는다 `[가정]`. 닫는 법은 X(「상세 패널 닫기」), Esc, 타임라인 빈 곳 누르기, 시트 바깥 누르기다. 이전 · 다음 사건 버튼은 패널을 연 채 사건만 바꾼다 |
| URL 입력 모달 | 헤더, 랜딩 | SEED Dialog. 열리면 입력칸에 포커스가 간다. *마인드맵 만들기*를 누르면 A10 을 부르고, 기다리는 동안 버튼이 로딩 상태가 된다. 결과는 세 갈래다: 새 작업(202)이면 분석 중 화면, 이미 분석된 기사(200 · `SUCCEEDED`)면 바로 기사 마인드맵, 오류면 모달 안에 안내 (State Patterns) |
| 분야 탭 (CategoryTabs) | 홈 | 하나만 고른다(`role="tab"` · `aria-selected`). 고르면 아래 이슈 카드 · 최신 기사가 그 분야로 통째로 바뀐다. 탭이 넘치면 가로로 스크롤한다 |
| 필터 칩 | 이슈 화면 타임라인 필터 | 여러 개 고른다(`aria-pressed`). 「초기화」로 모두 푼다. 탭이 있으면 탭 바로 아래에 둔다. 드롭다운 칩은 값을 고르면 칩 글자가 그 값(「이번 주」)으로 바뀐다 |
| 이슈 카드 (IssueCard) | 홈 | 카드 전체가 누르는 면 하나다. 누르면 이슈 화면. 사건 수가 0이면 그 항목을 뺀다 |
| 기사 행 (ArticleList) | 홈 최신 기사, 사건 패널 관련 기사 | 행 전체가 누르는 면이다. 누르면 기사 마인드맵. 사건 패널 안에서는 작은 변형을 쓰고 처음 4건을 보인다. *더 보기*는 다음 쪽(A6 `page`)을 불러 아래에 붙인다 |
| 사건 노드 (Timeline) | 이슈 화면 | 누르거나 Enter · Space 로 사건 패널을 연다. 고른 노드는 `{components.list-row-selected}` 로 남는다. 맵 배치는 아직 정하지 않았다 |
| 원문 근거 | 사건 패널, 노드 패널 | 원문 문장 그대로 `{components.evidence-quote}` 에 둔다. 근거가 없으면 근거 상자 대신 「원문 근거를 찾지 못했어요」 한 줄을 둔다 |
| 버튼 | 전역 | SEED ActionButton. 요청을 보내는 동안 `loading` 으로 두어 다시 누르지 못하게 한다 |
| 텍스트 링크 | 본문 | 호버에 밑줄. 문장 속 링크는 눌러도 줄어들지 않는다 |
| 아이콘 버튼 | 닫기, 메뉴, 사이드바 접기 | `aria-label` 을 꼭 단다. 아이콘을 키우지 않고 여백으로 누르는 영역을 40px 로 넓힌다 |
| 스낵바 | 전역 | 짧은 알림 한 줄. 2.4초 뒤 사라진다 (프로토타입). 오류는 스낵바로 알리지 않고 그 자리에 둔다 `[가정]` |
| 「곧 제공」 항목 | 헤더 나의 뉴스함 · 마이페이지, 사이드바 관심 이슈 | P2 기능 자리다. 누를 수 있고 키보드로도 닿는다. 누르면 스낵바 「MVP 이후 제공 예정인 기능이에요」. 비활성으로 두지 않는다 — 비활성 버튼은 키보드로 닿지 않아 안내를 못 받는다 |
| 태그 | 카드, 패널 | 누를 수 없는 라벨이다 `[가정]` |
| 상태 라벨 · 변화 카드 (ChangeCard) | — | F09 주장 관계 및 변화 분석 · F10 근거 기반 변화 카드는 추후 논의 기능이라 동작을 정하지 않는다 |

## State Patterns

**공통 규칙**
- **불러오는 중**은 스켈레톤이다. 그 자리 모양을 딴 뼈대에 `shimmer-neutral` 반짝임을 쓰고, AI 반짝임(`magic` 계열)은 쓰지 않는다. 스피너는 버튼 안 로딩에만 쓴다 `[가정]`.
- **빈 결과**는 그 자리에 빈 상태 문구를 둔다. 멀티컬러 아이콘을 곁들일 수 있고, 한 화면에 몇 개만 쓴다.
- **오류**는 실패한 영역 자리에 문구와 *다시 시도*를 둔다. 화면 전체를 오류로 바꾸지 않는다 `[가정]`.
- **없는 것**(`_NOT_FOUND`, 없는 주소)은 화면 전체를 「찾을 수 없음」으로 바꾸고 *홈으로*를 둔다.
- 오류 코드별 문구와 할 일은 `docs/api.md` 2절 표를 따른다. 여기에는 문구가 **어디에** 뜨는지만 적는다. 「일반 오류 안내」 문구는 「일시적으로 서비스를 사용할 수 없어요. 잠시 후 다시 시도해 주세요.」다 (v2 `07-writing.md`).

| 상태 | 화면 | 처리 |
| --- | --- | --- |
| 첫 로딩 | 모든 화면 | 스켈레톤 |
| 불러오기 실패 | 모든 화면의 각 영역 | 그 영역 자리에 안내와 *다시 시도*. 이슈 화면 예: 「타임라인을 불러오지 못했어요」 · 「네트워크 상태를 확인한 뒤 다시 시도해 주세요.」 |
| 분야에 이슈 없음 | 홈 | 「이 분야의 이슈가 아직 없어요」 (A1 `issueCount` 가 0) |
| 준비 중인 이슈 | 이슈 화면 | 「이 이슈의 상세 데이터는 준비 중이에요」와 「사건 N개 · 기사 N개를 정리하고 있어요」 |
| 필터 결과 없음 | 이슈 화면 | 「조건에 맞는 사건이 없어요」. 칩의 「초기화」로 푼다 |
| 검색 결과 없음 | 통합 검색 (미정) | 「'…'에 맞는 이슈·사건·기사가 없어요」 |
| 근거 없음 | 사건 패널, 노드 패널 | 「원문 근거를 찾지 못했어요」 |
| URL 모양이 아님 | URL 입력 모달 | 입력칸 아래에 `INVALID_URL` 안내 |
| 지원하지 않는 출처 | URL 입력 모달 | 「지원하지 않는 출처의 기사입니다」와 지원 언론사 칩(A12). 그 밖의 A10 오류(`SOURCE_FETCH_FAILED` · `TOO_MANY_REQUESTS`)도 모달 안에 둔다 |
| 분석 중 | 분석 중 화면 | 「기사를 분석하고 있어요」. A11 을 2초마다 부른다. 단계 표시(기사 본문 확인 → 인물·기관·사건 추출 → 마인드맵 구조 생성 → 관련 기사·이슈 연결)는 P1 이다 |
| 분석 실패 | 분석 중 화면 | 작업 실패 코드별 안내(`api.md` 2절). `retryable` 이면 *다시 시도*를 둔다. 그 밖에 갈 곳은 「아직 정하지 않은 것」 |
| 마인드맵이 아직 없음 | 기사 마인드맵 | `MINDMAP_NOT_FOUND` 면 A8 `mindmapStatus` 를 본다. `QUEUED` 는 분석 중과 같게 보이고, `FAILED` 는 분석 실패와 같게 보인다 |
| 사건 연결 상태 | 기사 마인드맵 *이 기사가 속한 이슈 보기* | A8 `eventMatchStatus` 를 본다. `QUEUED` 면 「사건을 찾는 중이에요」, `SUCCEEDED` 인데 `issue` 가 없으면 「아직 이슈로 묶이지 않았어요」를 버튼 대신 둔다 `[가정]`. `issue` 가 있으면 버튼이 사건 패널을 연 이슈 화면으로 간다 |
| 「곧 제공」 | 헤더, 사이드바 | 스낵바 「MVP 이후 제공 예정인 기능이에요」 |
| 찾을 수 없음 | 화면 전체 | 무엇이 없는지(「이슈를 찾을 수 없어요」)와 *홈으로* |

## Interaction Primitives

마우스와 터치가 먼저다. 키보드로도 모든 기능에 닿는다.

**키보드**
- ⌘/Ctrl+\ — 사이드바를 접거나 편다 (PRD FR-3).
- ⌘/Ctrl+K — 홈 검색창으로 간다. 통합 검색을 MVP 에 넣을 때만 쓴다.
- Esc — 맨 위에 열린 것 하나만 닫는다. 순서는 팝오버 · 메뉴 → 모달 → 오른쪽 패널 → 서랍이다.
- Enter · Space — 노드 · 카드 · 탭을 고른다. 검색 결과는 ↑↓ 로 옮긴다.

**호버 · 눌림** — 모양은 `DESIGN.md` 「상태별 모양」에 있다. 동작 규칙은 아래와 같다 (v2 `02-feedback.md`).
- 호버에만 기대는 기능을 두지 않는다. 호버는 마우스가 있는 기기에서만 보인다.
- 눌리면 표면 색만 바뀌고 글자 · 아이콘 색은 그대로다.
- 축소는 하나의 면으로 잡히는 요소(카드 · 버튼 · 칩)에만 쓴다. 이미 줄어드는 요소 안에 있는 요소는 줄이지 않고, 로딩 중에는 줄이지 않는다. 탭은 색 대신 축소만 쓴다.
- 색 전환과 축소는 둘 다 150ms 라서 한 반응으로 읽힌다.

**모션** (v2 `01-motion.md`)
- 작은 움직임은 200ms(`duration-d4`) 이하, 큰 움직임은 250–300ms 다.
- 오른쪽 패널과 시트는 열릴 때 300ms(`enter` 곡선), 닫힐 때 250ms(`exit` 곡선)다. 프로토타입의 220ms 는 따르지 않는다.
- 동작 줄이기(`prefers-reduced-motion`)를 켜면 위치 · 크기 변화를 없애거나 짧은 페이드로 바꾼다. 색 전환은 남긴다.

**목록** — 긴 목록은 *더 보기*로 다음 쪽을 부른다 (A6).

## Accessibility Floor

- 목표 수준은 WCAG 2.1 AA 다 `[가정]`.
- 색만으로 정보를 전하지 않는다. 글자와 아이콘을 함께 쓴다.
- 키보드 포커스에는 `stroke-focus-ring` 2px 윤곽선을 그린다. 카드 · 칩은 바깥으로 2px 띄우고, 리스트 행 · 탭은 안쪽에 그린다.
- 화면을 옮기면 문서 제목(`<title>`)을 화면 이름으로 바꾸고, 포커스를 화면 제목으로 옮긴다 `[가정]`.
- 모달을 열면 포커스가 모달 안 첫 입력으로 가고, 닫으면 연 버튼으로 돌아간다 (SEED Dialog). 오른쪽 패널도 같게 패널 제목으로 갔다가 닫으면 고른 노드로 돌아간다 `[가정]`.
- 지금 위치는 `aria-current` 로 알린다 (현재 화면의 사이드바 항목, 고른 이슈 카드 · 기사 행). 탭은 `role="tab"` · `aria-selected`, 칩은 `aria-pressed` 다.
- 아이콘만 있는 버튼에는 `aria-label` 을 단다. 옆에 같은 뜻의 글자가 있는 아이콘과 장식 아이콘은 `aria-hidden` 이다. 뜻이 있는 이미지에는 짧은 대체 텍스트를 붙인다.
- 누르는 영역은 44px 이상(최소 24px), 아이콘 버튼은 40px 다.
- 분석 완료 · 실패, 스낵바는 `aria-live` 로 읽어 준다 `[가정]`.
- 맵의 핀치 줌 · 드래그에는 탭(누르기)으로 하는 대체 수단을 둔다 (v2 `05-inclusive-design.md`). 방법은 F04 · F07 화면을 정할 때 정한다.
- 글자 크기는 rem 이라 사용자 설정을 따라 커진다. 콘텐츠 순서는 읽는 순서와 같게 둔다.

## Responsive & Platform

v2 브레이크포인트를 따른다. 작은 화면부터 쓰고 `min-width` 로 넓힌다. 프로토타입의 1024px · 760px 기준은 따르지 않는다.

| 폭 | 사이드바 | 오른쪽 패널 | 헤더 오른쪽 | 본문 |
| --- | --- | --- | --- | --- |
| lg 1280px 이상 (설계 기준) | 보임. 패널이 열리면 접힘 | 본문 오른쪽 420px | 글자 버튼 | 가운데 정렬, 최대 1040px (넓은 탐색 화면 1280px) |

## Key Flows

페르소나와 여정 전체는 `docs/user-flow.md` 에 있다. 여기서는 각 여정이 지나는 주소와 상태만 적는다.

### Flow A — 사쿠, 매일 아침 동향을 챙기는 취준생

1. `/home` 에서 분야 탭 「경제」를 고르고 이슈 카드를 누른다. user-flow 의 출발점인 *추천 이슈*(개인화)는 P2 라 분야 탭 이슈 카드로 대신한다.
2. `/issues/:issueId` 에서 이슈 헤더와 타임라인을 본다.
3. 가장 최근 사건을 누른다. `?event=` 가 붙고 사건 패널이 열린다.
4. **핵심 순간** — user-flow 에서는 상충 후보 변화 카드다. F10 이 추후 논의라 지금 범위에는 없다.

실패: 타임라인을 불러오지 못하면 그 자리에 *다시 시도*가 뜬다.

### Flow B — 요섭, 점심에 업계 기사를 읽는 직장인

1. `/home` 최신 기사를 누른다. `/articles/:articleId` 기사 마인드맵이 열린다.
2. 노드를 누르면 `?node=` 가 붙고 노드 패널에서 원문 근거를 본다.
3. *이 기사가 속한 이슈 보기*를 누른다. `/issues/:issueId?event=:eventId` 가 그 사건이 골라진 채 열린다 (F11).
4. **핵심 순간** — user-flow 에서는 20조 → 25조 갱신 변화 카드다. F10 이 추후 논의라 지금 범위에는 없다.

다른 입구: 헤더 *마인드맵 만들기*에 URL 을 넣는다 → `/analyze/:jobId` → `/articles/:articleId`.
실패: 지원하지 않는 출처면 모달 안에 안내와 지원 언론사가 뜬다. 분석이 실패하면 실패 코드별 안내가 뜬다.

## 아직 정하지 않은 것

- **Key Flows 의 핵심 순간** — 사쿠 · 요섭 모두 F10 변화 카드에 기댄다. 확정 범위(F01~F08 · F11)만으로 핵심 순간을 다시 정해야 한다. PRD UJ-2 의 핵심 순간(사건이 강조된 이슈 맵)은 확정 범위 안에 있다. 팀 확인이 필요하다.
- **F04 · F05 기사 마인드맵** — 맵 안 배치, 줌 · 드래그, 노드 고르기. *근거 문장 모아 보기* 모달은 user-flow 에만 P0 로 있고, PRD 는 *원문에서 위치 보기*다 (본문 노출 범위 Q28 미정).
- **F07 이슈 에볼루션 맵** — 시간축 · 레인 배치와 맵 조작. 사건 패널의 *마인드맵으로 보기*(관련 기사 마인드맵)를 넣을지는 QA 때 정한다.
- **F09 · F10** — 상태 라벨 · 변화 목록 · 변화 카드 동작. PRD 는 NEW · UPDATE 같은 영어 코드를 화면에 쓰지 말라고 하고, `DESIGN.md` 상태 라벨은 영어 이름을 쓴다. 기능을 정할 때 함께 맞춘다.
- **통합 검색** MVP 포함 여부 (Jira S15P31A102-46, A13).
- **분석 실패 뒤 갈 곳** — user-flow 는 *홈으로*, PRD · `api.md` 는 저장된 기사로 가는 길이다 (user-flow 팀 확인 3).
- **비어 있는 문구** — `eventMatchStatus` 가 `FAILED` 일 때, `mindmapStatus` 가 `NONE` 일 때, 기사 요약이 아직 없을 때(`summary` null), 모르는 마인드맵 버전일 때.
- **준비 중인 이슈가 언제 생기나** — A2 는 사건이 있는 이슈만 준다.
- **md 구간에서 패널이 열렸을 때 본문 폭** — 768px 화면이면 사이드바 64px 와 패널 420px 를 빼고 본문이 284px 남는다. 구현하며 확인하고, 좁으면 md 에서는 패널을 본문 위에 띄우는 오버레이(v2 EventDetailPanel 오버레이 변형)로 바꾼다.
- **랜딩 내용**과 시연에 쓸지 — 주소만 `/` 로 정했다.
