# NEW:LEARN 경험 설계

NEW:LEARN 화면이 **어떻게 동작하는지** 정한다. 화면 목록과 이동, 상태, 문구, 키보드, 접근성, 화면 크기별 변화를 다룬다. 생김새(색 · 글자 · 모양 · 크기)는 `DESIGN.md` 가 정한다.
SEED Design 과 다른 것과 NEW:LEARN 에만 있는 것만 적는다.

**SEED · 프로토타입과 다르게 정한 것**

| 무엇 | 어느 절 |
| --- | --- |
| 화면마다 주소가 있고 고른 사건 · 보기도 주소에 남는다. 로그인 · 가입 · 마이페이지도 그렇다 (프로토타입은 주소 없이 이동하고 로그인 화면을 보던 화면 위에 띄운다) | Information Architecture |
| 앱 안 탭(열어 둔 화면을 늘어놓은 띠)은 만들지 않는다 | Information Architecture |
| 사이드바는 768px(md) 미만에서 서랍이 되고 끌어서 폭을 바꾸지 않는다 (프로토타입은 1024px 기준 · 폭 조절) | 앱 셸 · Responsive & Platform |
| 불러오기에 실패하면 화면 전체가 아니라 실패한 영역 자리에 안내를 둔다 | State Patterns |
| P2 기능 버튼을 비활성으로 두지 않고, 누르면 곧 나온다고 안내한다 | Component Patterns |
| 패널 모션은 열림 300ms · 닫힘 250ms 다 (프로토타입은 220ms) | Interaction Primitives |
| 프로토타입에 있어도 MVP 가 「추후」 · P2 로 둔 것(노드 상세 카드와 원문 근거, 논점 · 관점, 지난 방문 이후 새 사건)은 만들지 않는다 | `docs/mvp-overview.md` 3-1 · 6장 |

- **범위**는 `docs/mvp-overview.md` 3-1 을 따른다.
  - 확정: F01 뉴스 데이터 적재·조회, F02 카테고리별 뉴스·이슈 조회, F03 기사 핵심 정보 구조화, F04 기사 마인드맵 생성, F06 동일 사건 기사 클러스터링, F07 사건 중심 이슈 에볼루션 맵, F08 사건별 관련 기사 조회, F11 기사·이슈 양방향 연결, F12 회원·관심 분야, F13 용어사전 — F12 · F13 은 2026-10-20 · 10-21 팀 회의로 MVP 에 넣었다(`SSOT.md` 9절, MVP 개요 3-1 은 2026-10-29 부터 P0)
  - 추후: F05 노드 상세 및 근거 확인. 추후 논의: F09 주장 관계 및 변화 분석, F10 근거 기반 변화 카드. 셋 다 [아직 정하지 않은 것](#아직-정하지-않은-것)에 적었다
- 근거 문서가 없어 이 문서에서 정한 것은 `[가정]` 으로 표시한다.
- 프로토타입 · 디자인 시스템 v2 원본 · `docs/user-flow.md` 와 동작이 다르면 이 문서를 따른다. user-flow 는 10월 20일 회의 전 내용이다.
- 절 제목은 BMAD 검사가 이름으로 찾기 때문에 영어로 둔다.

## Foundation

- **반응형 웹 하나.** PC 1280px 이상을 기준으로 설계하고 모바일 360~430px 에서는 깨지지 않게만 한다. 모바일 다듬기는 일정에 여유가 있을 때 한다. 앱 · PWA 는 만들지 않는다 (PRD 1.1 · 4.10 · 4.11).
- **브라우저**는 최신 Chrome · Edge 다 `[가정]` (PRD 에도 가정으로 표시돼 있다).
- **UI 시스템**은 SEED Design 3 (React) 이다. 포커스 이동 · Esc · aria 같은 컴포넌트 동작은 SEED 를 따른다.
- **기준 프로토타입**은 v21 이다 (`.claude/stack.md` §7 「가장 높은 버전이 최신」). 이 문서에서 「프로토타입」은 v21 을 말한다.
- **회원이 있다** (F12). 탈퇴와 이름 · 비밀번호 바꾸기는 없다. 가입 항목은 IA 의 가입 행, 로그인 유지는 `api.md` 1절 「인증」에 있다. 손님(로그인하지 않은 사람)이 무엇을 볼 수 있는지는 이동 규칙에 있다.

## Information Architecture

화면마다 주소가 있다. 주소를 복사해 열면 같은 화면이 같은 선택으로 열린다. 고른 사건 · 보기는 주소 뒤에 쿼리로 붙인다. 그래야 기사에서 이슈 화면으로 갈 때(F11) 그 사건을 고른 채 열리고, 뒤로 가기로 돌아와도 고른 것이 남는다.

**이동 규칙**
- 무엇을 눌렀느냐에 따라 도착 화면이 다르다. 기사는 기사 마인드맵, 이슈는 이슈 화면, 사건은 사건 패널이 열린 이슈 화면이다. 기사와 이슈는 아이콘으로 구분한다. 기사는 문서 아이콘, 이슈는 갈래 아이콘이다 (PRD FR-30).
- **손님은 로그인부터 한다** ([팀 확인 남음](#아직-정하지-않은-것)). 손님이 랜딩 밖 주소를 열면 `/login?next=<그 주소>` 로 보낸다. 손님인지 가리는 법(A17 의 401)과 API 가 로그인 없이 열려 있다는 것은 `api.md` 1절 「인증」에 있다.
- 세션이 끝나 401 `UNAUTHORIZED` 를 받으면 `/login?next=<지금 주소>` 로 보낸다 (`api.md` 2절). 로그인 화면이 받는 `LOGIN_FAILED`(401)와 로그아웃의 401 은 여기에 들지 않는다. 어느 조회 · 저장이 받든 화면 전체에서 한 곳(QueryClient)이 「내 정보」를 손님으로 바꿔 보낸다 — 목록이 401 이어도 「불러오지 못했어요」를 띄우지 않는다 (2026-11-04, S15P31A102-165).
- 로그인 · 가입을 마치면 `next` 로 간다. `next` 가 없으면 `/home` 으로 간다. 이미 로그인했는데 `/login` · `/signup` 을 열면 `/home` 으로 보낸다 `[가정]`.
- 로그아웃하면 랜딩(`/`)으로 간다. 손님은 셸 안 화면에 남을 수 없고, 손님이 처음 서는 곳이 랜딩이다. 세션이 이미 끝나 로그아웃이 401 이어도 로그아웃한 것과 같다. 받아 둔 응답은 모두 버린다 — 기사 · 이슈의 북마크 · 관심 상태가 회원 기준이다 (2026-11-03, S15P31A102-66).
- 다른 화면으로 가면 브라우저 방문 기록을 하나 쌓는다. 같은 화면 안에서 고른 것만 바꾸면(다른 사건 고르기, 패널 닫기, 보기 바꾸기) 기록을 새로 쌓지 않고 지금 기록의 주소만 바꾼다 `[가정]`. 그래서 뒤로 가기는 앞 화면으로 간다.
- 추천 이슈에서 고른 분야는 `/home?category=` 로 남긴다 `[가정]`.
- 최신 기사에서 고른 분야는 `/home?latest=` 로 남기고 「전체」면 뺀다. 추천 이슈의 `?category=` 와 따로 움직인다 `[가정]` (2026-11-03, S15P31A102-45).
- 프로토타입의 앱 안 탭은 MVP 에서 만들지 않는다. P2 다 (PRD FR-27).

### 앱 셸

랜딩 · 로그인 · 가입은 셸 없이 전체 화면으로 뜬다. 나머지 화면은 네 영역으로 짜고 그 위에 용어사전 버튼을 띄운다 (v2 `Foundations/04-layout.md`). 화면 폭에 따라 달라지는 것은 [Responsive & Platform](#responsive--platform) 표에 있다.

| 영역 | 동작 |
| --- | --- |
| 헤더 | 스크롤해도 화면 위에 붙어 있다 `[가정]`. 항목은 왼쪽부터 메뉴 열기(사이드바가 서랍일 때만) · 로고 · 나의 뉴스함 · 마이페이지다. 로고를 누르면 홈으로 가서 열린 패널을 닫고 맨 위로 스크롤한다. 지금 화면이 나의 뉴스함 · 마이페이지면 그 버튼을 브랜드 옅은 바탕 · Fill 아이콘으로 칠하고 `aria-current` 로 알린다 (모바일 v1 · v21, 2026-11-04 S15P31A102-163) |
| 사이드바 | 접기 · 펼치기 버튼이나 ⌘/Ctrl+\ 로 접고(64px) 편다(216px). 끌어서 폭을 바꾸지 않는다. 처음에는 접혀 있다. 접힌 레일에는 펼치기 · 빠른 이동만 둔다 — 프로토타입 v21 레일의 홈 · 나의 뉴스함은 헤더(로고 · 버튼)와, 분야별 이슈는 펼치기와 겹치고, 관심 이슈는 마이페이지에 있다 (2026-11-04 사용자 결정, S15P31A102-167). 펼치면 빠른 이동과 이슈 탐색(분야 → 연도 → 이슈 → 사건)이 보인다 (PRD FR-3). 분야 이름 오른쪽에 A1 `issueCount` 를 둔다 — 눈으로 보는 보조라 화면 읽기에서 빼고 분야 버튼 이름은 분야 이름 그대로다 `[가정]` (2026-11-04, S15P31A102-163). 이슈를 누르면 이슈 화면, 사건을 누르면 사건 패널이 열린다. 이슈 줄 오른쪽에 관심 이슈 별을 둔다(Component Patterns 「관심 이슈 별」, 2026-11-05 S15P31A102-172). 사건은 지금 보고 있는 이슈 아래에만 A4 순서로 「날짜 키워드」(「10.06 착공식」)를 펼치고, 주소에서 고른 사건을 강조한다 (프로토타입 v21). 사건을 누르는 것은 같은 화면에서 고르는 것이라 기록을 쌓지 않고, 포커스는 패널 제목으로 간다 — 패널이 열리면 사이드바가 접혀 누른 링크가 사라지기 때문이다. 사건이 0개인 이슈(A2 기간 null)는 이슈를 만든 해에 둔다 (2026-11-03, S15P31A102-159). 서랍일 때는 헤더 메뉴로 연다. 바깥 어두운 막이나 Esc 를 누르거나 항목을 고르면 닫힌다. 서랍 머리는 로고(누르면 홈으로 가서 맨 위로) · 닫기를 둔 52px 줄이고 바탕은 넓은 화면 사이드바와 같은 회색이다. 서랍 이름 「메뉴」는 화면 읽기에만 남긴다 (모바일 v1, 2026-11-04 S15P31A102-163) |
| 본문 | 화면 내용. 사이드바와 오른쪽 패널이 차지한 만큼 좁아진다 |
| 오른쪽 패널 | 사건 패널이 열리는 자리다. 본문을 덮지 않고 본문 오른쪽에 붙는다. 서랍을 쓰는 좁은 화면에서는 아래에서 올라오는 시트(화면 높이 85%)가 되고 뒤를 딤으로 덮는다 `[가정]`. 패널이 열리면 사이드바를 접는다. X 버튼(`aria-label="상세 패널 닫기"`) · Esc · 타임라인 빈 곳 · 시트 바깥을 누르면 닫힌다. 이전 · 다음 사건 버튼은 패널을 연 채 사건만 바꾼다. 넓은 화면 패널은 420px 이고 본문 폭의 절반을 넘지 않는다. 화면 안에서 사건을 골라 열면 포커스가 패널 제목으로, 닫으면 그 사건 노드로 간다 (2026-10-28, S15P31A102-52) |
| 용어사전 버튼 | 오른쪽 아래에 떠 있다. 오른쪽 패널이 열리면 패널 폭만큼 왼쪽으로 비킨다 — 패널이 본문 폭의 절반으로 줄었으면 줄어든 폭만큼. 좁은 화면의 시트는 딤으로 덮어서 비키지 않는다 — 그러려고 시트를 본문 밖(body)에 그린다. 본문은 isolate 라 안에서 그리면 버튼이 딤 위로 올라온다 (2026-11-03, S15P31A102-161). 창의 동작은 Component Patterns 에 있다 (2026-11-03, S15P31A102-157) |

## Voice and Tone

화면 문구 규칙이다. 브랜드 분위기는 `DESIGN.md` Brand & Style 이 정한다.

| 한다 | 하지 않는다 |
| --- | --- |
| 해요체, 아라비아 숫자, 한 문장에 한 내용 (v2 `07-writing.md`) | 딱딱한 공문체, 한 문장에 여러 안내 |
| 오류에는 할 수 있는 일을 적는다 — 「타임라인을 불러오지 못했어요」 · 「네트워크 상태를 확인한 뒤 다시 시도해 주세요.」 | 오류 코드나 서버의 `detail` 을 화면에 그대로 내기 (`api.md` 2절) |

## Component Patterns

동작만 적는다. 생김새는 `DESIGN.md` Components, 원본 패턴은 `imports/newlearn-design-system-v2/components/<패턴>/README.md` 에 있다. 여러 컴포넌트에 걸친 접근성 규칙(aria-label · 누르는 영역 · 포커스 이동)은 Accessibility Floor 에 있다.

| 컴포넌트 | 쓰는 곳 | 동작 |
| --- | --- | --- |
| 헤더 · 사이드바 · 오른쪽 패널 · 용어사전 버튼 | 셸 | [앱 셸](#앱-셸) |
| 로그인 · 가입 폼 | 로그인 · 가입 | *로그인* · *가입하기*를 누르면 칸마다 검사하고 틀린 칸 아래에 오류를 띄운다. 보내는 동안 버튼을 로딩 상태로 둔다. 문구는 State Patterns 에 있다. 닫기(X)를 누르면 랜딩으로 간다. 폼 아래 「아직 계정이 없나요?」 · 「이미 계정이 있나요?」 줄의 *회원가입* · *로그인* 으로 서로 오가고, 돌아올 곳(`next`)을 그대로 넘긴다. 아이디 글자 규칙(영문 소문자 · 숫자 · `_` 4 ~ 20자, `api-screen.md` A14)은 화면이 4자 미만만 먼저 보고 나머지는 서버 `reason` 으로 안내한다 (2026-11-03, S15P31A102-66). 가입은 단계마다 *다음* · Enter 가 그 단계 칸만 검사하고, 맞으면 다음 단계의 첫 칸으로 포커스를 옮긴다. *이전* 으로 돌아가도 쓴 값이 남는다. 서버가 칸 오류를 주면 틀린 칸이 있는 첫 단계로 돌아가 그 칸에 포커스하고, 다른 단계 칸의 오류는 그 단계에 가면 보인다 (2026-11-03, S15P31A102-66) |
| 분야 탭 (CategoryTabs) | 홈 추천 이슈 · 최신 기사 | 하나만 고른다(`role="tab"` · `aria-selected`). 추천 이슈 탭은 관심 분야(별표) → 나머지 분야 → 스포츠 · 문화/연예 순이다. 스포츠 · 문화/연예는 준비 중이라 잠겨 있다 (State Patterns). 최신 기사 탭은 「전체」와 분야 탭이다. 탭이 넘치면 가로로 스크롤한다 |
| 관심 분야 칩 | 가입, 마이페이지 | 여러 개 고른다(`aria-pressed`). 고른 칩이 하나 이상 남아야 해서 마지막 남은 칩은 눌러도 풀리지 않는다. 스포츠 · 문화/연예는 준비 중이라 고를 수 없다(「스포츠 · 준비 중」). 안내 문구는 State Patterns 에 있다. 고른 칩은 체크 아이콘과 DESIGN.md 「선택된 필터 칩」 색, 안 고른 칩은 더하기 아이콘이다. 높이는 40px `[가정]` (2026-11-03, S15P31A102-66). 가입 마지막 단계의 사용 목적 칩(취업 준비 · 업무 · 업계 동향 · 시사 공부 · 그 밖에)도 같은 모양이지만 하나만 고르고, 다시 누르면 푼다 (2026-11-03, S15P31A102-66) |
| 관심 이슈 별 | 이슈 화면 머리, 사이드바 이슈 줄 | 이슈 머리는 제목 옆 별 버튼(40px). 사이드바는 이슈 줄 오른쪽 작은 별(28px)이고, 저장하지 않은 별은 줄에 마우스를 올리거나 별에 포커스할 때만 보인다 — 손가락으로도 누를 수 있는 기기(터치 노트북 포함)에서는 늘 보인다 — 숨은 별을 잘못 누르지 않게 `[가정]`. (프로토타입 v21 PinButton, 2026-11-05 S15P31A102-172). 누르면 저장(A23) · 해제(A24)하고 별은 응답의 `interested` 로 맞춘다. 이름은 이슈 머리가 「관심 이슈로 저장」, 사이드바는 앞에 이슈 제목을 붙인 「<제목> 관심 이슈로 저장」이다(줄마다 어느 이슈의 별인지 알게). 어느 쪽도 상태로 이름을 바꾸지 않고 눌림(`aria-pressed`)으로 알린다. 보내는 동안 다시 눌러도 보내지 않는다. 401 이면 세션이 끝난 것이라 로그인 화면으로 간다. 그 밖의 실패는 스낵바 「관심 이슈를 바꾸지 못했어요. 잠시 후 다시 시도해 주세요.」 `[가정]` — 별 하나라 그 자리에 문장을 둘 곳이 없다 (2026-11-03, S15P31A102-68). 저장 · 해제하면 받아 둔 이슈 머리 · 이슈 목록(사이드바 별, 홈 추천 카드의 「관심 이슈」 표시)을 응답대로 바꾸고 관심 이슈 목록을 새로 받는다 |
| 필터 칩 | 이슈 화면 타임라인 필터 | P1 이다 (mvp-overview 6장). 넣으면 여러 개 고르고(`aria-pressed`) 「초기화」로 모두 푼다 |
| 이슈 카드 (IssueCard) | 홈 | 카드 전체가 누르는 면 하나다. 누르면 이슈 화면으로 간다. 사건이 0개인 이슈(A2 `lastEvent` null)는 「최근 사건」 줄을 두지 않는다 (2026-11-03, S15P31A102-159). 관심 이슈(`interested`)면 분야 옆에 별과 「관심 이슈」를 붙인다 — v21 은 「고정」(핀)이지만 우리 말은 관심 이슈(별)다 (PRD FR-28, 2026-11-05 S15P31A102-172) |
| 기사 행 (ArticleList) | 홈 최신 기사, 사건 패널 관련 기사 | 행 전체가 누르는 면이다. 누르면 기사 마인드맵으로 간다. 처음 몇 개를 보일지는 IA 표에 있고, *더 보기*를 누르면 다음 쪽을 불러 아래에 붙이고 붙인 첫 기사로 포커스를 옮긴다. 홈 최신 기사는 여러 분야가 섞여서 언론사 · 시각 뒤에 분야를 적는다(v21) |
| 북마크 버튼 | 기사 행, 기사 마인드맵 머리 | 누르면 담기(A20) · 빼기(A21)하고 응답의 `bookmarked` 로 맞춘다. 기사 행은 원문 보기 왼쪽의 아이콘 버튼(40px) — 이름 「{제목} 나의 뉴스함에 담기」는 그대로 두고 눌림(`aria-pressed`)으로 상태를 알린다. 기사 머리는 원문 보기 왼쪽의 글자 버튼 「북마크」 · 「북마크됨」. 보내는 동안 다시 눌러도 보내지 않는다. 401 이면 세션이 끝난 것이라 로그인 화면으로 간다. 그 밖의 실패는 스낵바 「북마크를 바꾸지 못했어요. 잠시 후 다시 시도해 주세요.」 `[가정]` (2026-11-03, S15P31A102-67) |
| 사건 노드 (Timeline) | 이슈 화면 | 누르거나 Enter · Space 로 사건 패널을 연다. 노드는 메인 흐름 · 서브 흐름 두 레인에 놓인다. 레인은 사건의 역할로 백엔드가 정한다 — 상황을 바꾸는 행위는 메인, 다른 사건에 대한 반응 · 평가 · 여론은 서브 (`api-screen.md` A4, Jira 130). 가로는 시간 순서이고 간격은 시각 차이에 비례하지 않는다(프로토타입 v21 `LaneTimeline`). 마우스를 올리면 제목 · 날짜 · 기사 수 · 레인이 툴팁으로 뜨고, 키보드 포커스에도 같은 툴팁을 띄운다 `[가정]`. 사건 사이의 선과 관계 태그는 그리지 않는다 (`api-screen.md` A4). 고른 노드에는 `{components.list-row-selected}` 선택 표시가 남는다 |
| 보기 탭 | 기사 마인드맵 | 흐름지도 보기(기본) · 마인드맵 보기 중 하나를 고른다. 같은 A9 응답을 두 모양으로 그린다 (mvp-overview F04). 세부 노드를 누르면 그 노드를 강조한다(확대는 하지 않는다). 흐름지도 보기는 가지를 「무슨 일이? → 왜 일어났나? → 누가 뭐라고 했나? → 앞으로는?」 순서로 둔다. 흐름지도 자리(화면 폭이 아니라 사이드바를 뺀 본문 폭)가 1024px 이상이면 가지 하나가 한 열인 가로, 아니면 세로다. 잎은 문장 전체를 카드로 두고(전망 가지 잎에는 「전망·해석」 점선 태그), 누르면 강조하고 나머지 카드를 흐리게 한다. 다시 누르기 · 빈 곳 · Esc 로 푼다. 마인드맵 보기에서 가지(분류 원)를 누르면 그 가지만 확대하고 나머지는 흐리게 한다. 다시 누르기 · 빈 곳 · Esc · *화면에 맞추기* 로 전체로 돌아간다. 노드 상세 카드와 원문 근거는 F05(추후)라 띄우지 않는다. 마인드맵 보기 위 범례에는 있는 가지만 칩으로 둔다 — 누르면 그 가지를 숨기고 다시 누르면 되살리며, 하나라도 숨기면 *모두 보기* 가 생긴다. 전망 가지의 잎은 점선이고 범례에 「전망·해석」으로 적는다. 그래프 왼쪽 아래에 확대 · 축소 · *화면에 맞추기*, 오른쪽 위 톱니(*탐색 설정*)에 「라벨 표시」 스위치(기본 켬)를 둔다 — 끄면 강조 · 키보드 포커스 · 마우스를 올린 잎만 글을 보인다. Esc 는 설정 창 → 가지 포커스 · 강조 순으로 닫는다. 보기 탭을 오가도 숨긴 가지 · 라벨 표시는 남고, 확대 · 가지 포커스 · 강조는 풀린다. 좁은 화면(767px 이하)에서도 마인드맵 보기는 그대로 화면에 맞춘다 — 글이 작아지지만 흐름지도가 기본이라서다 (2026-10-30, Jira S15P31A102-58) |
| 용어사전 창 | 셸 | 용어사전 버튼을 누르면 그 자리에 작은 창이 열린다. 모달이 아니어서 창을 연 채로 기사를 보며 찾을 수 있다. 단어를 넣고 보내면(입력칸 예시 「예: 금리」) 뜻을 3개까지 보여 주고 나머지는 *N개 더 보기* 로 편다 — 표준국어대사전은 흔한 뜻을 뒤에 주기도 해서다(「사과」의 열매 뜻이 8개 중 5번째, 2026-11-03). 뜻마다 표제어 · 품사 · 뜻풀이를 보이고, 표제어의 `^`(띄어 써도 되는 자리)는 띄어 쓰고, 글자 사이의 `-`(낱말이 붙은 자리, 「이-자」)는 지운다. 맨 앞 · 맨 끝의 `-` 는 접사 · 어미 표시라 남긴다(「-자」). 결과 아래에 출처 「국립국어원 표준국어대사전」을 붙인다(CC BY-SA). 찾는 동안 점 세 개가 움직인다. 접기 버튼이나 Esc 로 닫는다. 대화는 셸이 떠 있는 동안만 남고 어디에도 저장하지 않는다 (S15P31A102-157) |
| 버튼 | 전역 | SEED ActionButton. 요청을 보내는 동안 `loading` 으로 두어 다시 누르지 못하게 한다 |
| 스낵바 | 전역 | 짧은 알림 한 줄. 2.4초 뒤 사라진다. 오류는 스낵바로 알리지 않고 실패한 영역 자리에 둔다 `[가정]` |

## State Patterns

**공통 규칙**
- **불러오는 중**에는 그 자리 모양을 딴 스켈레톤을 둔다 (반짝임 모양은 `DESIGN.md`). 스피너는 버튼 안 로딩에만 쓴다 `[가정]`.
- **빈 결과**에는 그 자리에 빈 상태 문구를 둔다. 문구는 아래 표에 있다.
- **불러오기 실패**는 실패한 영역 자리에 안내와 *다시 시도*를 둔다. 화면 전체를 오류로 바꾸지 않는다 `[가정]`. 안내 문구 예는 Voice and Tone 에 있다.
- **없는 것**(`_NOT_FOUND`, 없는 주소)은 화면 전체를 찾을 수 없음 화면으로 바꾼다 (Information Architecture).
- 오류 코드별 문구와 할 일은 `docs/api.md` 2절이 정한다. 그 밖의 화면 상태 문구는 아래 표가 정한다. `api.md` 가 말하는 일반 오류 안내에는 「일시적으로 서비스를 사용할 수 없어요. 잠시 후 다시 시도해 주세요.」를 쓴다 (v2 `07-writing.md`).

| 상태 | 화면 | 처리 |
| --- | --- | --- |
| 분야에 이슈 없음 | 홈 | 「이 분야의 이슈가 아직 없어요」 (그 분야의 A2 결과가 비었을 때. A1 `issueCount` 가 0인 것과 같다) |
| 분야에 기사 없음 | 홈 최신 기사 | 「이 분야의 기사가 아직 없어요」 (그 분야의 A7 결과가 비었을 때. 「전체」도 같은 문구) |
| 준비 중인 분야 | 홈, 가입, 마이페이지 | 스포츠 · 문화/연예 탭이나 칩을 누르면 「…는 준비 중이에요」를 안내한다 |
| 관심 분야 0개 | 가입, 마이페이지 | 마지막 남은 칩을 누르거나 하나도 고르지 않고 보내면 「관심 분야를 1개 이상 골라 주세요.」 |
| 사건 없는 이슈 | 이슈 화면 | 타임라인 자리에 「아직 이 이슈에 정리된 사건이 없어요」 `[가정]` (A4 `events` 가 비었을 때, 2026-10-28) |
| 필터 결과 없음 | 이슈 화면 | 필터와 함께 P1. 「조건에 맞는 사건이 없어요」 |

| 담은 기사 없음 | 나의 뉴스함 | 「아직 담은 기사가 없어요. 기사 옆 북마크를 누르면 여기에 모여요.」 (A22 `items` 가 비었을 때, v21) |
| 없는 사건 | 사건 패널 | 주소의 이슈는 있으니 화면 전체를 바꾸지 않고 패널 안에 「사건을 찾을 수 없어요」 (`EVENT_NOT_FOUND`). 위 「없는 것」 규칙의 예외다 `[가정]` (2026-10-28) |

| 입력 오류 | 로그인, 가입 | 화면이 먼저 검사한다: 「아이디를 입력해 주세요.」 · 「비밀번호를 입력해 주세요.」 · 「이름을 입력해 주세요.」 · 「아이디는 4자 이상으로 입력해 주세요.」 · 「비밀번호는 8자 이상으로 입력해 주세요.」 · 「비밀번호가 서로 달라요.」. 서버가 `VALIDATION_FAILED` 를 주면 `errors[].reason` 을 오류가 난 칸 아래에 그대로 띄운다 (`api.md` 2절) |
| 로그인 실패 · 아이디 겹침 | 로그인, 가입 | `LOGIN_FAILED` 는 폼 안에, `LOGIN_ID_TAKEN` 은 아이디 칸 아래에 띄운다. 문구는 `api.md` 2절 |
| 용어사전 결과 없음 | 용어사전 창 | 「'…'의 뜻을 찾지 못했어요. 다른 표현으로 물어봐 주세요.」 |
| 용어사전 서버 오류 | 용어사전 창 | `DICTIONARY_UNAVAILABLE` · `RATE_LIMITED`(코드 없는 429 포함)이면 창 안에 띄운다. 문구는 `api.md` 2절. 400 `VALIDATION_FAILED` 는 서버가 준 까닭(`errors[q]`)을, 연결 실패 · 그 밖의 오류는 일반 오류 안내를 창 안에 띄운다 |

## Interaction Primitives

마우스와 터치가 먼저다. 키보드로도 모든 기능에 닿는다.

**키보드**
- ⌘/Ctrl+\ — 사이드바를 접거나 편다 (PRD FR-3).
- Esc — 맨 위에 열린 것 하나만 닫는다. 닫는 순서는 팝오버 · 메뉴 → 모달 → 용어사전 창 → 오른쪽 패널 → 서랍이다. 이 가운데 용어사전 창의 자리가 `[가정]` 이다.
- Enter · Space — 노드 · 카드 · 탭을 고른다.
- 검색 단축키는 Information Architecture 의 통합 검색 행에 있다. 용어사전에는 단축키가 없다. MVP 개요는 「단축키나 버튼」으로 열게 했고, 여기서는 프로토타입대로 버튼만 둔다.

**호버 · 눌림** (v2 `02-feedback.md`, 모양은 `DESIGN.md` 상태별 모양)
- 호버에만 기대는 기능을 두지 않는다. 호버는 마우스가 있는 기기에서만 보인다.
- 축소(누르면 살짝 작아지는 효과)는 누르는 면이 하나인 요소(카드 · 버튼 · 칩)에만 쓴다. 문장 속 링크에는 쓰지 않는다. 줄어드는 요소 안에 든 요소는 따로 줄이지 않는다. 로딩 중에도 줄이지 않는다. 탭은 색 대신 축소만 쓴다.
- 색 전환과 축소는 둘 다 150ms 라서 한 반응으로 읽힌다.

**모션** (v2 `01-motion.md`)
- 작은 움직임은 200ms(`duration-d4`) 이하, 큰 움직임은 250~300ms 다.
- 오른쪽 패널과 시트는 열릴 때 300ms(`enter` 곡선), 닫힐 때 250ms(`exit` 곡선)다. 프로토타입의 220ms 는 따르지 않는다.
- 동작 줄이기(`prefers-reduced-motion`)를 켜면 위치 · 크기 변화를 없애거나 짧은 페이드로 바꾼다. 색 전환은 남긴다.
- 랜딩 인사는 위 숫자의 예외다 — 인사가 1.8초 머물고 막이 0.6초에 걷힌 뒤, 첫 화면 글이 0.6초씩 0.12초 간격으로 떠오른다. 동작 줄이기를 켜면 인사를 띄우지 않고 첫 화면을 바로 보인다 (2026-11-03, S15P31A102-66).
- 가입은 단계가 바뀔 때 질문과 칸이 300ms 로 아래에서 떠오르고, 진행 막대는 300ms `enter` 곡선으로 찬다.
- 홈 첫 화면(인사 · 검색창) 뒤에는 마인드맵 모양 배경을 깐다 — 작은 네모 노드 22개를 가까운 것끼리 잇고 가운데는 비운다. 노드는 16 ~ 31초 주기로 몇 px 씩 떠다니는데, 위 숫자의 예외다. 동작 줄이기를 켜면 멈춘다. 장식이라 화면 읽기에서 빼고 누를 수 없다 (프로토타입 v21 `HomeHeroBg`, 2026-11-04 S15P31A102-168).
- 랜딩 · 가입에는 마우스를 조금 늦게 따라오는 원 커서를 덧붙인다. 누를 수 있는 것 위에서 1.5배 커진다. 원래 커서는 그대로 두고, 마우스(`hover: hover` · `pointer: fine`)일 때만 띄우며 동작 줄이기를 켜면 띄우지 않는다. 장식이라 화면 읽기에서 뺀다 (2026-11-03, S15P31A102-66).
- 기사 화면(기사 머리 · 흐름지도 · 마인드맵 보기)과 이슈 화면(이슈 머리 · 이슈 흐름 · 사건 패널)은 위 숫자의 예외다 — 하나하나 500 ~ 650ms 로 넘쳤다 자리 잡으며 차례로 나오고, 다 나오기까지 2초가 안 걸린다(잎이 많으면 차례 간격을 묶는다). 보기 탭을 바꿀 때마다 다시 나온다 (2026-11-05 사용자 「밋밋하다」, 프로토타입 v21 을 키웠다). 기사 머리는 분야 → 제목 → 정보 → 버튼 순서로 떠오른다. 흐름지도는 머리 줄 → 가지 열(300ms 간격)이다 — 번호 원이 튀어나오며 파문이 번지고, 다음 번호로 선이 자라며 그 끝을 따라 가지색 점이 달려가, 점이 닿을 즈음 다음 번호 원이 나온다. 열 안에서는 질문 → 잎 카드(60ms 간격)다. 마인드맵은 가운데가 튀어나오며 파문이 번지고, 가지가 가운데에서(A9 순서로 90ms 간격) · 잎이 그 가지에서(50ms 간격) 날아 나온다. 선은 날아가는 노드를 따라 뻗는다. 다 나온 뒤에도 가운데 원 · 흐름지도 머리 줄 점은 3초마다 파문이 번지고 마인드맵 잎은 저마다 다른 박자로 둥실 떠 있다 — 홈 배경처럼 계속 도는 꾸밈이다. 강조한 잎은 원이 한 번 튀고 파문이 번진다. 마인드맵 노드에 마우스를 올리면 넘치며 커지고, 가운데에서 그 노드까지 이어진 것(가지면 그 잎들까지)만 또렷이 두고 나머지를 흐리며, 그 길 위로 점선이 바깥쪽으로 흐른다 — 마우스 · 펜일 때만이다. 터치는 누르면 마우스 흉내가 와서 강조와 겹치기 때문이다. 가지를 포커스한 동안에는 그 가지 안에서만 그렇게 하고, 키보드로 옮긴 노드는 가지 포커스로도 흐리지 않는다. 흐름지도 잎 카드는 마우스를 올리면 2px 들리고 원이 커진다. 모양은 `DESIGN.md` Components 「기사 마인드맵 두 보기」. 이슈 화면은 이슈 머리가 분야 → 제목 → 요약 순서로 떠오르고, 이슈 흐름은 레인 이름이 먼저 나온 뒤 메인 흐름 선이 첫 사건에서 마지막 사건까지 같은 빠르기로 뻗으며(사건 수만큼 늘되 1초까지) 선 끝이 지나는 자리의 사건이 튀어나온다. 같은 시각 사건은 함께, 서브 흐름 사건은 그 자리를 선이 지나간 뒤 조금 늦게, 라벨 · 달 눈금은 그 사건 · 자리를 따라 나온다. 사건에 마우스를 올리면 넘치며 커지고 툴팁이 나타난다. 사건을 고르면 둘레에 파문이 번지고 시간축 날짜 표시가 튀어나온다. 사건 패널은 열거나 이전 · 다음으로 바꿀 때마다 속한 이슈 → 제목 → 날짜 → 요약 → 관련 기사(한 줄씩) 차례로 떠오른다 — 이전 · 다음 버튼은 포커스를 지키려고 다시 그리지 않는다. 동작 줄이기를 켜면 두 화면 모두 처음부터 다 그린 모양이고 파문 · 달리는 점 · 흐르는 점선 · 둥실도 없다. 흐리기 · 색 전환만 남는다.

## Accessibility Floor

**보기**
- 목표 수준은 WCAG 2.1 AA 다 `[가정]`.
- 색만으로 정보를 전하지 않는다. 글자와 아이콘을 함께 쓴다.
- 글자 크기를 rem 으로 정해 브라우저 글자 크기 설정을 따라 커지게 한다.

**포커스**
- 키보드 포커스는 늘 보인다. 카드 · 칩은 윤곽선을 바깥으로 띄우고 리스트 행 · 탭은 안쪽에 그린다 (윤곽선 모양은 `DESIGN.md` 상태별 모양).
- 다른 화면으로 가면 브라우저 탭 제목(`<title>`)을 그 화면 이름으로 바꾸고 포커스를 화면 맨 위 제목으로 옮긴다 `[가정]`.
- 모달을 열면 포커스가 모달 안 첫 입력으로 가고 닫으면 모달을 연 버튼으로 돌아간다 (SEED Dialog). 오른쪽 패널 · 용어사전 창도 마찬가지다 `[가정]`. 다만 용어사전 창을 본문에서 Esc 로 닫으면 포커스를 그 자리에 둔다 (S15P31A102-157).
- DOM 순서를 화면에서 읽는 순서와 같게 둔다.

**스크린 리더**
- 지금 위치는 `aria-current` 로 알린다 (현재 화면의 사이드바 항목, 고른 이슈 카드 · 기사 행). 탭 · 칩의 ARIA 는 Component Patterns 에 있다.
- 아이콘만 있는 버튼에는 `aria-label` 을 단다. 옆에 같은 뜻의 글자가 있는 아이콘과 장식 아이콘은 `aria-hidden` 이다. 뜻이 있는 이미지에는 짧은 대체 텍스트를 붙인다.
- 입력 오류는 그 칸에 이어서 읽히게 한다(`aria-describedby`) `[가정]`.
- 스낵바와 용어사전 결과는 `aria-live` 로 읽어 준다 `[가정]`.

**누르기**
- 누르는 영역은 44px 이상을 목표로 하고 24px 아래로는 내리지 않는다. 아이콘 버튼은 40px 다. 아이콘을 키우지 않고 여백으로 넓힌다. 줄 안에 들어가는 작은 아이콘 버튼(사이드바 이슈 줄 별)은 28px 로 둔다 — 줄 높이를 넘지 않게, 24px 하한은 지킨다 (2026-11-05, S15P31A102-172).
- 맵의 핀치 줌 · 드래그는 누르기만으로도 할 수 있게 대체 수단을 둔다 (v2 `05-inclusive-design.md`). 어떻게 할지는 F04 · F07 화면을 설계할 때 정한다.

## Responsive & Platform

v2 브레이크포인트를 따른다. 작은 화면용 스타일을 먼저 쓰고 `min-width` 미디어 쿼리로 넓혀 간다. 프로토타입의 1024px · 760px 기준은 따르지 않는다. 여백과 최대 폭은 `DESIGN.md` Layout & Spacing 에 있다.

| 폭 | 사이드바 | 오른쪽 패널 | 헤더 오른쪽 버튼 |
| --- | --- | --- | --- |
| lg 1280px 이상 (설계 기준) | 보인다 | 본문 오른쪽에 붙는다 | 글자 |
| md 768~1279px | 보인다 | 본문 오른쪽에 붙는다. 768px 근처에서는 본문이 좁다 — [아직 정하지 않은 것](#아직-정하지-않은-것) | 글자 |

- 홈 · 랜딩 카드 그리드는 좁아지면 열 수를 줄인다. 이슈 카드는 최소 280px 이다 (v2 IssueCard).

- 폰 홈 화면에 설치된다(PWA). 설치한 앱은 주소창 없이(`standalone`) `/home` 에서 열리고, 손님이면 로그인 화면으로 간다. 이름 「NEW:LEARN」, 아이콘은 로고, 위 막대 색은 흰색. 연결이 끊긴 채 화면 주소를 열면 「인터넷에 연결되지 않았어요」와 *다시 시도* (`/offline.html`). 서비스 워커는 화면 파일(`/assets/`)과 오프라인 안내만 캐시하고 API 응답은 캐시하지 않는다 — 로그인 · 북마크 같은 회원별 응답이 남지 않게. 개발 · `dev:mock` 에서는 등록하지 않는다(MSW 워커와 같은 범위) (2026-11-05, S15P31A102-176)
- 좁은 화면(sm · base)은 모바일 프로토타입 v1 을 따른다. v1 은 v21 을 393 × 852 폰 폭에 고정한 판이라 서랍 · 시트 · 1열은 위 표와 같고, 다른 것은 아래뿐이다 (2026-11-03, S15P31A102-161).
  - 홈 — 「추천 이슈 / 최신 기사」 탭 (Information Architecture 홈 행)
  - 용어사전 — 버튼은 글자 없는 52px 동그라미 아이콘(오른쪽 16 · 아래 20px), 창은 좌우 · 아래 8px 까지 넓히고 높이 72%
  - 이슈 타임라인 — 레인 이름 칸 140 → 92px, 오른쪽 여백 200 → 96px, 레인 이름 글자 한 단계 작게. 확대 % 대신 확대 · 축소 묶음 안에 「전체 보기」 아이콘
  - 기사 화면 — *이 기사가 속한 이슈 보기* 는 한 줄을 꽉 채운 44px 버튼. 마인드맵을 전체에 맞출 때는 배율을 72 ~ 100% 로 묶고 가운데 기사 제목을 화면 가운데에 둔다 — 다 넣으려고 줄이면 글자를 못 읽는다
  - v1 의 글자 크기 축소(0.5 ~ 10px)는 따로 맞추지 않는다. SEED 글자 크기가 좁은 화면에서 이미 한 단계 작다
  - 여백 — 콘텐츠 좌우 20px, 스크롤 끝 96px(용어사전 버튼에 가리지 않게). 값은 `DESIGN.md` Layout & Spacing (2026-11-05 사용자 「숨이 턱 막히게 꽉 찬다」)
  - 기사 화면 — 북마크 · 원문 보기는 반씩 나눈 44px 두 칸, 그 아래 이슈 보기 한 줄. 흐름지도는 머리 줄(h1 과 같은 제목)을 두지 않는다. 마인드맵 범례는 한 줄로 두고 가로로 민다(오른쪽 끝을 흐려 더 있다는 것을 보인다)
  - 홈 추천 이슈 머리 — 제목이 한 줄을 다 쓰고 그 아래에 설명 | *관심사 편집*
  - 서랍 — 큰 「메뉴」 제목 대신 로고 · 닫기 줄 (앱 셸 사이드바 행, 2026-11-04 S15P31A102-163). 헤더 지금 화면 강조 · 분야별 이슈 수 · 마이페이지 머리 줄도 v1 에 있지만 넓은 화면도 같아서 각 행에 적었다
  - 일부러 v1 과 다르게 둔 것 — 랜딩 소개 섹션(S15P31A102-44), 가입 4단계(S15P31A102-66), 나의 뉴스함 분야 탭(S15P31A102-67), 마이페이지 「새 사건 N」 배지(A25 보류)

## Key Flows

페르소나와 여정 전체는 `docs/user-flow.md` 에 있다. user-flow 는 10월 20일 회의 전 내용이라, 여기서는 각 여정이 지금 지나는 주소와 상태를 적는다.

### Flow A — 사쿠, 매일 아침 동향을 챙기는 취준생

1. `/` 랜딩에서 *서비스 시작하기*를 누르고 `/login?next=/home` 에서 로그인한다.
2. `/home` 추천 이슈의 맨 앞 탭은 관심 분야 「경제」다. 그 탭의 이슈 카드를 누른다.
3. `/issues/:issueId` 에서 이슈 헤더와 타임라인을 본다.
4. 가장 최근 사건을 누른다. 주소에 `?event=` 가 붙고 사건 패널이 열린다.
5. **핵심 순간** — 미정 ([아직 정하지 않은 것](#아직-정하지-않은-것)).

실패: 로그인에 실패하면 폼 안에 안내가 뜬다. 타임라인을 불러오지 못하면 그 자리에 *다시 시도*가 뜬다.

### Flow B — 요섭, 점심에 업계 기사를 읽는 직장인

1. `/home` 에서 최신 기사를 누른다. `/articles/:articleId` 가 흐름지도 보기로 열린다.
2. 가지 네 개를 위에서 아래로 읽는다.
3. *이 기사가 속한 이슈 보기*를 누른다. 이슈 화면(`/issues/:issueId?event=:eventId`)이 이 기사가 속한 사건을 고른 채 열린다 (F11).
4. **핵심 순간** — 미정 ([아직 정하지 않은 것](#아직-정하지-않은-것)).

실패: 마인드맵이 아직 없으면 「분석 중」을 안내한다. 기사가 아직 이슈로 묶이지 않았으면 버튼 대신 안내 문구가 뜬다.
