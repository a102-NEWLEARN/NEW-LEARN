# Writing

README의 Voice & Tone을 실제 문장으로 옮기는 규칙입니다. 기본은 친근한 해요체입니다. 규칙은 SEED(당근)의 글쓰기 가이드에서 왔고, 예시는 NEW:LEARN 문장으로 바꿨습니다.

| 원칙 | 이렇게 | 이렇게 말고 |
| --- | --- | --- |
| 익숙한 단어 | 상대방과 대화할 수 없어요. | 상대방과 대화가 불가능합니다. |
| 존칭어 최소화 | 최대 2개의 글을 등록할 수 있어요. | 최대 2개의 글을 등록하실 수 있어요. |
| 아라비아 숫자 | 관심 이슈 3개를 저장했어요. | 관심 이슈 세 개를 저장했어요. |
| 축약어 지양 | 끌어올리기는 매일 5회까지 할 수 있어요. | 끌올은 하루 최대 5회 가능합니다. |
| 기능의 이름보다 목적 | 채팅으로 거래하기 | 채팅하기 |
| 긍정문 | 닉네임은 한 달에 한 번만 바꿀 수 있어요. | 한 달에 한 번 이상 닉네임을 바꿀 수 없어요. |
| 데이터보다 사용자의 행동 | 거래 후기를 보냈어요. | 거래 후기 작성을 완료했어요. |

- **능동문**을 기본으로 하되, 피동문이 뜻을 더 잘 전한다면 피동문을 씁니다. 좋은 문장이 가이드보다 먼저입니다.
- 사용자가 조심해야 하는 상황의 자동 메시지는 `~요` 대신 `~니다`로 무게를 싣습니다.
- **에러 메시지**에는 기술 용어 대신 사용자가 할 수 있는 해결 방법을 적습니다. 예: "일시적으로 서비스를 사용할 수 없어요. 잠시 후 다시 시도해주세요."
- **한 문장에 한 가지 내용.** 문장이 길어지면 나눕니다.
- **진심을 담아.** 경고보다 배려로 말합니다. 예: "거래 약속을 깜박하지는 않으셨나요? 약속을 잘 지키는 따뜻한 이웃이 되어보세요."
- **흐름으로 이어주기.** 알림과 추천 문구에는 사용자가 따라가는 이슈 이름을 넣어, 흩어진 기사가 하나의 흐름으로 이어진다는 점을 꾸준히 전합니다. 예: "‘반도체 산업’ 이슈에 새 기사 2개가 더해졌어요."
- 사용자의 이름을 부를 때는 소리 내어 읽어 보고 어색하지 않은지 확인합니다.
