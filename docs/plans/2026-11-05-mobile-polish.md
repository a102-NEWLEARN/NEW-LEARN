Jira 번호는 아직 없다(임시 `000`). 2026-11-05 사용자 「모바일 전체 손보기 — 지금은 숨이 턱 막히게 꽉 차니까 패딩 · 여백을 조절하고 더 예쁘고 모바일 친화적으로」. 기사 · 이슈 화면 애니메이션 브랜치(`…-000-article-mindmap-motion`)를 병합한 위에서 한다 — 같은 화면 파일을 고친다. 그 MR 이 먼저 머지돼야 이 MR 의 차이가 이것만 남는다.

## 무엇을 / 왜

393 × 852 폰으로 13개 화면을 찍어 보니(scratchpad `mob-before`) 답답한 까닭이 다섯이다.

1. 좌우 여백이 모든 화면에서 16px — 글 · 카드가 화면 끝에 붙는다
2. 세로 간격이 촘촘하다 — 기사 머리(분야 · 제목 · 정보 · 버튼 셋), 흐름지도 가지 · 카드 사이
3. 기사 화면에서 h1 바로 아래 흐름지도 머리 줄이 같은 제목을 또 보인다
4. 마인드맵 범례 칩이 두 줄로 꺾여 그래프 자리를 먹는다
5. 맨 아래 내용이 용어사전 버튼(52px)에 가린다

좁은 화면(767px 이하)만 바꾼다. 넓은 화면은 그대로다.

## 안 바꿀 것

- 넓은 화면(768px 이상)의 여백 · 배치
- 글자 크기 · 색 · 컴포넌트 모양
- 마인드맵 첫 배율(72 ~ 100%, -161 결정) · 타임라인 레인 칸 92px
- 개발 때만 뜨는 React Query 도구 버튼(왼쪽 아래) — 운영에는 없다

## 리스크

- 좌우 여백이 4px 씩 줄어 한 줄 글자 수가 조금 준다 — 이슈 카드 제목 · 기사 행이 한 줄 더 꺾일 수 있다. 360 폭에서도 찍어 넘침을 본다
- 흐름지도 머리 줄을 좁은 자리에서 뺀다 — 낭독에서 이미 뺀 장식 줄(h1 과 같은 글)이라 정보는 줄지 않는다
- jsdom 은 배치를 계산하지 않는다 — 기존 시험이 그대로 통과하는지만 보고, 모양은 스크린숏으로 본다
