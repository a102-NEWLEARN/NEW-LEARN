# S15P31A102-67 북마크 · 나의 뉴스함

2026-11-03 사용자 「진행해 — 오늘 최대한 해 두고 내일부터 고친다」. 계획을 따로 승인받지 않고 바로 만들었다. 다음 날 사용자가 화면을 보고 고친다.
최신 기사 브랜치(`feat/frontend/S15P31A102-45-latest-articles`) 위에서 딴다 — 북마크 버튼이 그 MR 에서 고친 기사 행에 들어간다. -45 MR 이 먼저 머지돼야 이 MR 의 차이가 이것만 남는다.

## 무엇을 / 왜

**F12 회원 · 관심 분야**의 기사 북마크가 화면에 없다. 백엔드 A20 · A21 · A22 는 dev 에 있고(Jira 63), 화면 쪽 API 함수 · 가짜 응답도 있다. 헤더 · 사이드바의 *나의 뉴스함* 은 「곧 제공」 안내만 띄운다.
EXPERIENCE 는 나의 뉴스함을 「범위 미정」으로 두었지만 A22 가 「담은 기사 전부, 최근 담은 순」으로 정했다(2026-10-26 계획 `bookmark-interest-spec`). 이 범위로 화면을 만든다.

## 정한 것 (사용자가 볼 것)

- **북마크 버튼** — 누르면 담기(A20) · 빼기(A21). 아이콘은 응답의 `bookmarked` 로 맞추고 스낵바는 「나의 뉴스함에 담았어요」 · 「나의 뉴스함에서 뺐어요」 (api-screen A20 · A21 「화면이 할 일」)
  - 기사 행(홈 최신 기사 · 사건 패널 · 나의 뉴스함): 원문 보기 왼쪽의 아이콘 버튼(40px). 이름은 「{제목} 나의 뉴스함에 담기」, 눌림(`aria-pressed`)으로 상태를 알린다
  - 기사 마인드맵 머리: 원문 보기 왼쪽의 글자 버튼 「북마크」 · 「북마크됨」 (api-screen A20)
  - 보내는 동안 다시 눌러도 보내지 않는다. 401 은 세션이 끝난 것 — 로그인 화면으로. 그 밖은 스낵바 「북마크를 바꾸지 못했어요. 잠시 후 다시 시도해 주세요.」 `[가정]`
  - 담기 · 빼기가 끝나면 받아 둔 기사 응답(최신 기사 · 사건 관련 기사 · 기사 상세)의 `bookmarked` 를 고치고 나의 뉴스함 목록을 새로 받게 한다. 그사이 로그아웃했으면 건드리지 않는다
- **나의 뉴스함** `/bookmarks` `[가정]` — 셸 안 화면. 제목 「나의 뉴스함」, 안내 「북마크한 기사를 모아 뒀어요. 최근에 담은 기사부터 보여줘요.」, 담은 기사를 기사 행으로(분야 표시). 없으면 「아직 담은 기사가 없어요. 기사 옆 북마크를 누르면 여기에 모여요.」 (v21 `LibraryScreen`). v21 의 분야 탭은 두지 않는다 — 담은 기사가 적을 때는 탭이 비어 보인다 `[가정]`
- 헤더 · 사이드바의 *나의 뉴스함* 이 이 화면으로 간다. 사이드바에서는 지금 화면이면 눌린 모양(`aria-current`)

## 안 바꿀 것

- 사이드바 *관심 이슈* — 관심 이슈 목록은 마이페이지(-68 브랜치)에 있다. 두 줄기가 머지된 뒤 잇는다
- 마이페이지 머리 줄 「관심 분야 N개 · 관심 이슈 N개 · 북마크 N개」 — 같은 까닭으로 나중에
- 가짜 API — A20 ~ A22 가 이미 있다

## 리스크

- 받아 둔 응답을 고치는 `setBookmarked` 가 기사 모양(`bookmarked` 칸이 있는 객체)을 찾아 고친다 — 다른 응답에 `bookmarked` 칸이 생기면 같이 바뀐다. 지금은 기사 요약 · 상세뿐이다
- 나의 뉴스함에서 빼면 목록을 새로 받아 그 줄이 사라진다 — 잘못 눌렀을 때 되돌릴 곳이 없다. 다시 담으려면 기사로 가야 한다
