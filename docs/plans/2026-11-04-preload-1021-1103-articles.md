# 10/21 ~ 11/3 최종 기사 먼저 넣기 · 덤프 적재 때까지 임시 공개 (2026-11-04)

Jira S15P31A102-169(152 와 연결). 2026-11-04 사용자 승인.

## 무엇을 / 왜

AI 팀원이 올린 `data/newsdata_2026-10-21_2026-11-03.sqlite` 의 최종 기사(`selection.status = 'selected'`, 79,335건)를 지금 운영 DB 에 B2 로 넣고, `released_at` 을 손으로 채워 덤프 적재 때까지 화면에 보이게 한다. 화면 개발이 배포 서버 데이터(`API_PROXY_TARGET=https://newlearn.io.kr`, `frontend/README.md` 33줄)로 목록 · 기사 머리 · 검색 · 북마크를 실제 분량으로 볼 수 있다. 덤프 적재는 결과만 붙이는 일이 되고, 시각 · 본문 실수는 「운영과 맞춘 기사」 검사가 잡는다. 덤프에 없는 기사는 적재 때 `released_at` 을 비워 내린다(판별은 `article_mindmap` 유무).

사용자 결정(2026-11-04 대화): 먼저 넣기 · 화면에 보여도 됨(사이트를 아직 알리지 않음) · 덤프에 없는 기사는 조회 안 되게.

## 정한 것

- **넣는 기사**: SQLite 최종 기사 중 `published < '2026-11-04'`(KST). `extra` · 뺀 기사는 넣지 않는다. 실측: 발행 10-21 18:50:55 ~ 11-03 23:59:59, B2 검증에 걸릴 값(빈 칸 · 길이 초과 · NUL · http 아님 · 겹친 링크) 0건, 언론사 110곳(새 `press` 110행)
- **값 변환은 스크립트 하나** `infra/server/sqlite_to_b2.py` — `link`→`url`, `source_id`→`pressSourceId`, `source_name`→`pressName`, `title`, `content`→`body`(손대지 않음), `published`→`publishedAt` 에 `+09:00`, `category` 를 쉼표로 나눠 `sourceCategories`(빈 값 · 겹침 뺌). 기자 · 태그는 SQLite 에 없어 보내지 않는다. 출력 경로를 받아 스크립트가 직접 쓴다(PowerShell `>` 는 바이트를 바꾼다) — B2 요청 모양 JSONL(UTF-8, LF, 발행 순)과 줄 수 · sha256 을 찍는다. AI 팀에도 같은 파일(같은 sha256)을 넘겨 로컬 B2 에 같은 값이 들어가게 한다
- **보내기는 수집 배치에 `INGEST_SOURCE=file` 하나를 더해서** — `news_ingest.py` 의 B2 보내기(`Run.load` · 출입증 멈춤 · 연결 끊김 멈춤 · 키 가리기)를 그대로 쓴다
  - 분기는 `load_config` 의 SOURCES 검사(232줄) · NewsData 키 검사(250줄)보다 앞, `run()` 의 fetch(531줄) · sort(540줄)보다 앞에 둔다. `main` 의 표준 입력은 맨 끝 선택 인자. 매일 수집은 `INGEST_SOURCE=latest` 라 이 길을 안 탄다
  - `load-only` 에서만 받는다. 매일 env(`INGEST_DAYS` · `INGEST_QUERY` · 상한 등)는 **있어도 무시한다** — CronJob 틀에서 `INGEST_SOURCE` 만 바꿔 돌리기 때문
  - 표준 입력을 한 줄씩 읽는다(메모리에 다 올리지 않음). JSON 객체가 아니거나 B2 필수 칸(`url` · `title` · `body` · `pressSourceId` · `pressName` · `publishedAt`)이 없는 줄은 B2 를 부르지 않고 「못 읽은 줄」로 센다
  - 5,000줄마다 진행 줄, 끝에 `수집 결과`(`source: file`, 읽은 줄 · 못 읽은 줄 · `b2`) — 기존 결과 줄과 따로 만든다(`SOURCES[source]` 를 안 읽게)
  - `INGEST_FILE_LINES`(기대 줄 수)가 있으면 읽은 줄과 견준다
  - 종료 코드: 출입증 2, 연결 끊김 1, 못 읽은 줄 · 거절 · 실패가 하나라도 있거나 기대 줄 수와 다르면 1, 다 되면 0
- **어디서 돌리나**: CronJob 틀로 Job `news-ingest-preload`(글자가 섞여 `ingest.md` 의 `news-ingest-[0-9]+$` 에 안 걸림)를 띄운다
  - `create job --from` → `set env --local INGEST_SOURCE=file INGEST_FILE_LINES=…` → command 는 `patch --type json` 으로 `/spec/template/spec/containers/0/command` 만 `["sleep","infinity"]` 로, `backoffLimit: 0` · `activeDeadlineSeconds: 10800` 은 `--type merge` 로 따로
  - `kubectl wait --for=condition=Ready` 뒤 서버 셸에서 `nohup sh -c 'kubectl -n app exec -i -c ingest job/news-ingest-preload -- python -I -B -u /opt/ingest/news_ingest.py < 파일; echo exit=$?' > preload.log 2>&1 &`. 결과는 exec 의 표준 출력이라 `kubectl logs` · Loki 에는 남지 않는다 — 서버 로그 파일이 기록
  - 이미지 · 이름표(`app: news-ingest`, `app/netpol.yaml` 이 8080 으로 들임) · 보안 설정 · Secret 이 매일 수집과 같고, 배치 키가 클러스터 밖으로 나가지 않는다. 같은 URL 은 B2 가 200 으로 돌려줘(`ingest.md` 36줄) 끊기면 다시 돌리면 된다
  - 끝나면 Job 을 바로 지운다 — 손 Job 이 성공으로 끝나면 CronJob 마지막 성공 시각이 바뀌어 경보 ①(`infra/k8s/alerts/rules.yaml`)이 가려질 수 있다. sleep 이 끝나면 exec 도 같이 죽으니 상한은 3시간
  - **카나리 먼저**: `head -n 100` 으로 한 번 넣고 3건 시각을 대조 · 걸린 시간을 잰 뒤 전체. 시작은 그날 10시 예약 Job 이 끝난 뒤(손 Job 은 CronJob 의 `Forbid` 가 막지 못한다)
- **넣은 기사 번호 범위**를 넣은 직후 남긴다(`created_at >= '2026-11-04 00:00+09' and published_at < '2026-11-04 00:00+09'` 의 id 최소 · 최대 · 수). 공개 · 지우기는 이 범위로 한다. `created_at` 은 `@CreationTimestamp`(`Article.java` 68 ~ 69줄)가 넣는 순간 채운다
- **임시 공개**: 확인이 끝나면 SQL 한 줄 — 그 id 범위이고 `released_at is null` 이고 발행이 11/4 전인 기사에 `released_at = now()`. 공개만으로는 분석이 걸리지 않는다 — `@Scheduled` 는 `AnalysisJobScheduler` 하나이고, 네 작업 모두 작업 행이 있거나 마인드맵 · 임베딩이 있어야 돈다(`AnalysisJobRepository.java` 60 ~ 120줄). `released_at` 을 읽는 코드는 조회 필터와 B1 의 409 뿐
- **내리기**: 덤프 적재 트랜잭션에서 결과를 붙인 뒤 `released_at is not null` 인데 `article_mindmap` 행이 없는 기사의 `released_at` 을 비우고, 내린 번호를 `load_undo` 에 남긴다(되돌릴 때 다시 공개). SQL 은 `data-load.md` 6절 한 곳에만 두고 `ingest.md` 는 가리킨다. 맞춘 기사의 `released_at` 을 덤프 쪽이 비었을 때 덮을지 둘지는 R1 에서 정한다
- **분야는 빈다** — 운영 `category_mapping` NEWSDATA 행이 0개(2026-11-04 확인, `docs/data-model.md` 5절 미정 7번 BE 몫). 원본 분류가 `source_categories` 에 남아 BE 가 행을 채우면 다시 계산할 수 있다. 이 계획은 대응 표를 건드리지 않고 BE 에 알린다
- **임시 공개 사실은 SSOT 9절 한 줄에만** 둔다. SSOT 2절 · 6절 · `api-screen.md` · `data-load.md` 는 9절을 가리킨다. 날짜는 「덤프 적재 때」로 쓴다(최종 덤프 날짜는 SSOT 8절 한 곳)

## 리스크

- **매일 수집이 깨짐** — 같은 파일을 고친다. file 분기를 기존 검사 앞에 두고 기존 시험 95개로 막는다. 머지는 10 ~ 11시 밖
- **덜 넣고 「됐다」** — 덜 올라간 파일 · 다른 파일 · 끊긴 스트림. 서버 `sha256sum` 대조, `INGEST_FILE_LINES`, 못 읽은 줄 1 로 막는다
- **시각이 9시간 어긋남** — 카나리 100건에서 3건 대조. 어긋나면 100건만 지우고 다시
- **backend 부하** — 약 8만 번 차례로 30 ~ 60분 어림(카나리로 잰다). 매 요청마다 「대응 표에 없는 원본 분류」 info 로그가 Loki 에 약 8만 줄, 새 언론사 110곳 로그. 넣는 동안 사이트 health 를 본다
- **DB · 백업 크기** — 본문만 244,507,186 바이트(SQLite 실측). DB 가 8.75MB 에서 수백 MB 로, 매일 백업 7일치가 관리 서버 볼륨(PVC 5Gi)에 쌓인다 — 다음 날 백업 파일 크기를 본다. EC2 루트는 27G 남음
- **팀 약속 예외** — 「마인드맵 뒤 공개」(Jira 34)를 덤프 적재 때까지 비켜 간다. 목록에 마인드맵 없는 기사가 보이고 기사 화면은 「이 기사의 마인드맵이 아직 없어요」. SSOT 9절에 적고 FE · BE 에 알린다
- **임시 공개 기사에는 B1 이 409** — 덤프가 실패해 운영에서 분석하는 길(`data-load.md` 4절)로 가려면 먼저 내려야 한다
- **내린 뒤 「공개 전 · 작업 없음」 기사가 수만 건** — 마감 뒤 B1 을 이 조건으로만 고르면 10/21 ~ 11/3 기사까지 GMS 로 간다. `data-load.md` 8절에 발행 날짜 범위를 못박는다
- **임시 공개 동안 운영 목록 JSONL 로 10/21 ~ 11/3 을 못 뽑음** — `export-articles.sql` 이 `released_at is null` 만. AI 팀은 같은 변환 JSONL 을 쓰니 필요 없다
- **AI 팀 값이 다름** — 덤프 적재가 멈춘다(조용히 틀리는 것보다 낫다). 같은 JSONL 을 넘기고 견본 R1 에서 먼저 본다
- **임시 공개 기사의 북마크** — 회원이 담은 기사가 내려가면 목록에서 사라진다(행은 남음)
- **경보 가림** — 손 Job 이 성공으로 끝나면 경보 ①이 가려질 수 있어, sleep 으로 띄우고 다 넣으면 바로 지운다
- **변환에 쓴 SQLite 가 다른 판** — 변환 전에 sha256 이 `data/README.md` 값과 같은지 본다(본 폴더 파일은 2026-11-04 13:56 받기 완료 · 577,716,224바이트 확인)
