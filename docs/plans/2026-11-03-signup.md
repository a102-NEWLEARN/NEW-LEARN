# S15P31A102-66 가입 화면

2026-11-03 사용자 「진행해 — 오늘 최대한 해 두고 내일부터 고친다」. 계획을 따로 승인받지 않고 바로 만들었다. 다음 날 사용자가 화면을 보고 고친다.

## 무엇을 / 왜

가입 화면이 없어서 새 사람이 가입할 길이 없다. `signUp()` 과 가짜 A14 만 있다.
**F12 회원 · 관심 분야**의 가입을 붙인다. EXPERIENCE.md 는 가입을 -66 에 걸어 두었다(「아직 정하지 않은 것」 `loginId` 행). 로그인 · 로그아웃은 이미 머지됐고, 이 MR 이 들어가면 -66 을 Done 으로 옮긴다.

## 정한 것 (사용자가 볼 것)

- `/signup?next=<보던 주소>` — 셸 없이 전체 화면. 로그인 화면과 같은 머리(로고 · 닫기 → 랜딩)
- 제목 「회원가입」, 안내 「관심 분야를 고르면 홈에서 그 분야 이슈를 먼저 보여드려요.」, 칸은 이름 · 아이디 · 비밀번호 · 비밀번호 확인 · 관심 분야, 버튼 *가입하기* (프로토타입 v21 `AuthPage`)
- 칸 아래 안내(placeholder): 이름 「이름을 입력해 주세요」, 아이디 「4자 이상」, 비밀번호 「8자 이상」, 확인 「비밀번호를 한 번 더 입력해 주세요」 (v21)
- 화면이 먼저 검사한다 — 문구는 EXPERIENCE State Patterns 「입력 오류」 · 「관심 분야 0개」 그대로. 틀린 첫 칸으로 포커스
- 서버 오류: `VALIDATION_FAILED` 는 `errors[].reason` 을 그 칸 아래에(`categoryCodes` 는 관심 분야 아래), `LOGIN_ID_TAKEN` 은 아이디 칸 아래 「이미 쓰는 아이디예요」, 429 는 폼 안에 「요청이 많아요. 잠시 뒤 다시 시도해 주세요」, 그 밖은 일반 오류 안내
- 가입하면 바로 로그인된다(A14) — 내 정보를 새 회원으로 바꾸고 스낵바 「가입을 마쳤어요」, `next` 로 간다
- 이미 로그인했으면 `/signup` 을 열어도 `next`(없으면 홈)로 보낸다
- 로그인 화면 아래에 「아직 계정이 없나요?」 줄과 *회원가입* 버튼, 가입 화면 아래에 「이미 계정이 있나요?」와 *로그인* (v21). `next` 를 그대로 넘긴다
- **관심 분야 칩**은 새 부품(`InterestChips`) — 마이페이지 관심 분야 바꾸기(-69)가 다시 쓴다. 여러 개 고른다(`aria-pressed`), 고르면 체크 · 안 고르면 더하기 아이콘. 마지막 남은 칩은 눌러도 풀리지 않고 「관심 분야를 1개 이상 골라 주세요.」. 스포츠 · 문화/연예는 「… · 준비 중」 칩이고 누르면 「…는 준비 중이에요」 스낵바 (Component Patterns 「관심 분야 칩」)
- 칩 모양: DESIGN.md 「선택된 필터 칩」(`bg-brand-weak` · `fg-brand-contrast` · 1px `stroke-brand-solid` · 체크), 높이 40px `[가정]` — 누르는 영역 44px 목표(Accessibility Floor)와 v21 38px 사이

## 리스크

- **인증 흐름을 건드린다** — AGENTS.md 「인증 · 권한 코드는 사람이 최종 확인」. 가입 뒤 세션은 서버가 연다(A14 201). 화면은 응답으로 내 정보만 바꾼다
- 아이디 글자 규칙(`^[a-z0-9_]{4,20}$`)은 화면이 먼저 보지 않는다 — State Patterns 문구가 4자 미만뿐이라서다. 대문자 · 한글은 서버 `reason` 으로 안내한다
