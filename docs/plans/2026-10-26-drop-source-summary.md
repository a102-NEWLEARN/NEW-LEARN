# Jira S15P31A102-113 기사 원본 요약 컬럼 제거

2026-10-26 사용자가 로컬 구현과 격리된 테스트 DB 검증을 승인했다.
최신 `origin/backend`(3f65733) 기반 별도 worktree에서 작업한다. 65번 미커밋 변경은 원래 작업 디렉터리에 보존한다.
최초 승인은 로컬 구현·격리 테스트까지였다. 검증 결과 확인 후 사용자가 8개 파일의 정상 훅 커밋·작업 브랜치 push·backend 대상 MR 생성을 추가 승인했다.
운영·공유 DB 접속·적용, 배포, MR 병합, 브랜치 삭제와 Jira 변경은 승인에 포함하지 않는다. 65번은 재개하지 않는다.

## 변경 파일과 제외 범위

- CoreSchemaTest: 컬럼 부재 단언을 먼저 추가하고 V3 적용 및 V2 데이터 보존을 검사한다.
- V3__drop_article_source_summary.sql: 사용을 중단한 컬럼만 삭제한다.
- ArticleApiFixtures·ArticleApiIntegrationTest·Article: 옛 INSERT와 임시 주석을 정리한다.
- data-model.md·기사 API 기능 스펙: 실제 스키마와 성공 기준을 맞춘다.
- 기존 V1·V2와 적용된 Flyway 이력, 요약 DTO·조립 로직·API 계약·인증·65번 변경은 수정하지 않는다.

## 위험과 운영 적용 전 확인

이 컬럼의 기존 값은 삭제된다. 티켓의 빈 컬럼 메모는 운영 DB 실측이나 백업 확인을 대신하지 않는다.
이번 작업은 임시 로컬 DB에 삭제 대상 값을 넣어 검증하며 운영·공유 DB에는 접속하지 않는다.

별도 배포 승인 후 담당자는 다음을 확인해야 한다.

1. 운영 스키마 버전·컬럼 존재·NULL 아닌 값의 수와 복원 가능한 백업을 확인한다. 예상과 다르면 적용을 멈추고 보존 방법을 확정한다.
2. 실행 중이거나 되돌릴 앱·배치가 해당 컬럼을 읽거나 쓰지 않는지 확인한다. Jira 112 이전 코드로의 롤백은 호환된다고 가정하지 않는다.
3. DDL 잠금 대기와 장기 트랜잭션을 확인하고 적용 시간과 중단 기준을 정한다. 잠금 대기로 서비스가 지연될 수 있다.
4. 최신 backend·dev와 병합 예정 변경의 마이그레이션 번호를 다시 확인한다. 2026-10-26 구현 직전 두 브랜치에는 V1·V2만 있었다.
   충돌 시 아직 적용하지 않은 이번 파일의 번호만 올린다. 적용된 파일과 Flyway 이력은 고치지 않는다.

## 실패 테스트와 검증

컬럼 부재 테스트는 마이그레이션 추가 전 실제 PostgreSQL에서 단언 실패를 확인한다.
빈 테스트 DB에서 V1부터 최신까지 적용하고 Hibernate의 `ddl-auto: validate`로 매핑을 확인한다.
V2 업그레이드는 고유 테스트 스키마에 기사 11행·마인드맵 6행과 삭제 대상 값을 넣는다.
업그레이드 전후 기사 전체 필드(삭제 대상 제외)와 마인드맵 전체 필드를 비교해 자체 요약도 보존되는지 본다.

포맷·전체 테스트·bootJar·저장소 필수 게이트와 기사·이슈·사건 API 회귀를 확인한다.
실제 HTTP는 새 임시 DB·Redis와 로컬 서버를 사용하며 종료 후 이번 검증 자원만 정리한다.
새 테스트의 되돌림 확인은 미적용 V3 파일을 잠시 분리해 단언 실패를 확인하고 원래 파일로 복원한다.

## 되돌리는 방법

미적용 상태는 이번 파일 변경만 되돌린다. 65번과 기존 변경은 건드리지 않는다.
DB에 적용한 뒤 Git revert만 해서는 컬럼과 값이 돌아오지 않는다.
필요하면 다음 사용 가능한 번호의 새 마이그레이션으로 nullable text 컬럼을 복원한다.
이것은 스키마만 복원하며 기존 값은 복구하지 못한다. 값은 사전 백업에서 기사 ID별로 복원해야 한다.
전체 DB를 과거 백업으로 덮으면 백업 이후 데이터까지 잃을 수 있으므로 별도 복구 DB에서 필요한 값만 추출하는 방법을 검토한다.
적용된 V3 삭제·수정, Flyway 이력 조작은 되돌리는 방법으로 쓰지 않는다.

구현 후 검증 결과를 사용자에게 보고하고 확인받은 뒤 커밋한다.
MR 전에는 작업 브랜치에 최신 origin/backend를 합치고 재검증한다. MR 대상은 backend이며 병합은 사람이 한다.

- 최초 컬럼 부재 테스트 1개가 실제 컬럼 존재에 대한 단언에서 실패했다.
- 빈 DB 전체 마이그레이션·매핑 검증과 V2 업그레이드 데이터 보존을 포함한 스키마 테스트 6개가 통과했다.

- 독립 읽기 전용 리뷰에서 수정 필요 사항이 없었다. 운영·공유 DB에는 접속하지 않았다.
