- 그림마다 이름에 「원본 docs/…」를 붙인다. md 를 고치면 그 그림만 다시 만든다

## 리스크

- 나누면서 옮긴 내용이 빠지거나 두 곳에 남을 수 있다. 옮긴 절은 원래 자리에서 지우고 가리키는 말만 둔다
- FigJam 의 표 모양 그림(4~6)은 md 표의 사본이라 어긋날 수 있다. 그림 이름에 원본과 날짜를 적고, md 를 고치면 다시 만든다
- Figma 의 mermaid 는 기능이 적다(sequence 의 노트 · 줄바꿈 · 이모지 안 됨, 테이블 모양은 erDiagram 상자로 흉내). 그림이 깨지면 그 그림만 단순하게 다시 만든다
- 같은 보드에 그림을 여러 장 넣으면 겹쳐 놓일 수 있다. 겹치면 Figma 에서 자리를 옮긴다(도구로 되면 내가, 안 되면 말씀드린다)
- Starter 팀은 파일 3개까지라 새 보드를 만들지 않고 기존 보드에 더한다
- 「어디서 오나」 칸을 쓰다가 설계 구멍이 보이면 고치지 않고 MR 에 후보로 적는다
- 절 번호가 바뀌어 다른 문서의 참조가 틀릴 수 있다. 저장소 전체에서 `api.md` 를 찾아 고친다

## 어떻게 검증하나

- 예시 JSON 의 키와 필드 표 이름이 빠짐없이 맞는지 스크립트로 대조한다
- 오류 코드 표의 코드가 모두 설명을 갖고, 문서에 나온 코드가 모두 표에 있는지 grep 대조
- `api.md` 를 가리키는 곳의 절 번호 grep 대조, 다섯 문서 모두 500줄 안쪽(`wc -l`)
- md 의 mermaid 를 로컬 화면에서 parse · render, MR 을 연 뒤 GitLab 에서도 본다
- FigJam 보드를 브라우저 창에서 열어 그림 13장이 모두 그려졌는지 스크린샷으로 본다
- 커밋 게이트 · `mr-check.sh` 통과
