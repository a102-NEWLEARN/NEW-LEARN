# Swagger 열기 — springdoc 넣기 · SecurityConfig 허용 목록 · 인프라 /swagger-ui.html 길

## 무엇을 / 왜

FE 가 API 를 Swagger 화면으로 보며 개발하게 연다(SSOT 6절 「공개 화면」: 개발하는 동안 잠그지 않음, 2026-10-22 사용자 결정). 인프라 길(`/swagger-ui` · `/v3/api-docs` → backend)은 이미 있다. 그런데 backend 에 springdoc 이 없고(dev · backend 두 브랜치 모두), dev 의 backend 에는 SecurityConfig 가 없어 Spring 기본 보안이 401 을 낸다(2026-10-23 확인). `/swagger-ui.html` 은 길이 없어 frontend 가 받는다.

알아 둘 것: backend 에는 아직 화면 API(컨트롤러)가 없다. Swagger 는 처음에 빈 목록으로 열리고 API 티켓(41 · 42 …)이 구현되는 대로 채워진다.

## 리스크
- **허용 목록이 넓어져 다른 주소가 열림** → GET 만 · 네 패턴만, 기존 보안 테스트(손님 401 · 내부 API 잠김 · Basic 꺼짐)가 그대로 통과하는지 같이 본다
- **springdoc 3.1.1 이 Boot 4.1.1 · Jackson 3 과 안 맞을 수 있음** → 테스트 · bootRun 에서 드러남, 안 되면 멈추고 보고(판을 마음대로 바꾸지 않음)
- **문서에 내부 API 가 보일 수 있음** → `paths-to-exclude` 와 테스트로 막음
- **Swagger 의 Try it out 으로 POST 를 보내면 403** — CSRF 번호표가 Jira 62 전에는 없다. FE 알림에 적는다(GET 은 됨)
- **backend → dev 가 커밋 8개를 같이 데려감** — API 공통 기반(오류 모양 · 보안)이 dev · 사이트에 들어감. 사이트 첫 화면은 health 만 불러 영향 없음, FE 가 `/api` 를 부르면 401 대신 문서대로의 ProblemDetail. 팀원 알림으로 미리 알림
- 사이트 반영 때 backend 교체 — 앞선 측정에서 교체 중 실패 0(10-22)·Envoy 앞 회선 끊김 1(10-23, 원인 미확인)
