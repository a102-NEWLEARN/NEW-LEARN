- **인사 줄 — 타자**: 회원 정보(A17)가 오면 인사 줄이 한 글자에 30ms 로 찍히고, 끝에 막대 커서가 한 번 깜빡인 뒤 사라진다(약 1초). 화면 읽기에는 처음부터 전체 문장을 준다(찍히는 글은 `aria-hidden`). 홈에 올 때마다 한 번. 동작 줄이기면 바로 전체
- **새로운 이슈 — 바뀌는 띠**: 「새로운 이슈 ▪ 제목」 한 줄. 3초마다 지금 제목이 위로 빠지며 흐려지고 다음 제목이 아래에서 올라온다(350ms). 3개를 돈다 — 개수는 그대로 3(`api-screen.md` A2 「화면은 3개」와 맞음). 세 제목을 한 칸에 겹쳐 놓아 폭이 가장 긴 제목에 맞춰 고정 — 바뀔 때 줄이 흔들리지 않는다. 마우스를 올리거나 키보드로 들어오면 멈추고, 링크는 셋 다 DOM 에 있어 Tab 으로 차례로 간다(들어간 링크가 보인다). 바뀔 때 화면 읽기가 읽지 않는다(`aria-live` 없음). 동작 줄이기면 지금처럼 셋을 한 줄에

## 리스크

- **성능**: 노드 그물 · 마인드맵 미리보기가 계속 움직인다 → 좌표를 React 밖에서 고치고 화면 밖이면 멈춘다(홈 배경과 같은 방식). 랜딩 코드가 첫 번들에 붙어 커진다 → 빌드 크기를 전 · 후로 재고, gzip 기준 30KB 넘게 늘면 랜딩을 따로 불러오기(lazy)로 돌린다
- **스크롤 연출과 폰**: 화면에 붙는 긴 구간(330 · 410vh)은 폰 주소창 높이 변화에 흔들릴 수 있다 → `100svh` 를 쓰고 393 폭에서 확인. 너무 길게 느껴지면 높이를 줄인다
- **jsdom 시험**: 스크롤 · IntersectionObserver 가 없다 → `Reveal` 은 관찰을 못 하면 바로 보이게, 연출은 순수 함수로 시험
- **문구 사실**: 랜딩 문구는 팀 · PM 이 볼 글이다 — MVP 에 없는 기능(UPDATE · 원문 근거 인용)을 말하지 않게 위 표대로 고친다. MR 본문에 바꾼 문구를 적는다
- **스냅숏 데이터**: 운영 수치가 바뀌어도 랜딩 예시는 그대로다(「예시」라 괜찮다). 언론사 이름은 바른 곳만 골라 데이터 문제(`team-message.md` 1번)가 랜딩에 보이지 않게 한다
- **시간**: 연출 ① · ② 가 가장 크다 — 오늘 못 끝내면 5 까지 먼저 낸다
- **동작 줄이기 · 접근성**: 자동으로 바뀌는 띠 · 미리보기는 마우스 · 포커스로 멈추고, 화면 읽기가 바뀔 때마다 읽지 않게 한다
