## 리스크

- SEED Tabs 의 색 · 굵기를 className 으로 덮어쓴다. SEED 스타일이 이기면 덮어쓰기가 안 먹는다 — 화면을 찍어 확인한다
- 준비 중 분야를 탭 밖 버튼으로 둬서 프로토타입(탭 + `aria-disabled`)과 짜임이 다르다. 보이는 모양은 같게 맞춘다
- 좁은 화면 서랍에서 링크를 고르면 SEED SidePanel 이 포커스를 메뉴 버튼으로 돌려놓을 수 있다. 그러면 h1 포커스와 부딪친다 — 테스트와 화면으로 확인하고, 부딪치면 서랍 쪽은 SEED 동작을 둔다
- 인사 · 날짜 테스트는 시계를 고정해야 한다. `vi.useFakeTimers({ toFake: ["Date"] })` 로 Date 만 바꿔 MSW · React Query 타이머는 그대로 둔다
- 가짜 이슈의 최근 사건 제목이 「… 최근 사건」 꼴이라 화면이 어색하다. 스크린샷 전에 몇 개를 그럴듯하게 바꾼다

  - 흐린 앞 검색어 줄도 마우스로 누르면 열린다(키보드는 막힘). 보이는 줄을 직접 누른 것이라 그대로 둔다 (2026-10-28 결정)
  - 검색이 실패한 채 Enter 를 누르면 다시 불러온다. 「다시 시도」 버튼과 같은 동작이고 그대로 둔다 (2026-10-28 결정)
  - 지우기 버튼을 label 밖으로 빼면서(`53b94bc`) 상자 오른쪽 여백과 ✕ 위아래를 누르면 입력 칸이 포커스를 잃는다. 입력 칸과 ✕ 사이 12px 간격도 사라졌다
  - 「결과 없음」 안내(`role="status"`)는 내용과 함께 새로 끼우는 요소라 스크린 리더가 읽지 않을 수 있다
- 고친 커밋 다시 보기에서 남긴 것
  - Enter 뒤 결과를 기다리는 사이 창이나 탭을 바꾸면 입력 칸이 포커스를 잃어 이동이 취소된다. 돌아오면 목록은 다시 열리지만 Enter 를 다시 눌러야 한다. 「닫으면 취소」와 같은 길이라 그대로 두었다 — 사람이 확인할 것
  - 200ms 기다림이 끝난 뒤 응답이 오기 전(앞 결과가 남은 때)에 고르기를 막는 줄(`!results.isPlaceholderData`)은 지키는 테스트가 없다. 응답을 늦추는 시간 의존 테스트가 필요해 두었다
  - `ac2574e` 본문의 「fetchQuery 가 같은 promise 를 돌려줘」는 정확하지 않다. 부를 때마다 다른 promise 가 오고 둘이 같은 요청을 함께 기다린다. 결론(콜백 둘이 잇달아 돈다)은 같다
  - `queryClient.fetchQuery` 는 쓰는 판(5.104.4)에서 deprecated 다(`queryClient.query` 로 바꾸라고 한다). 앞 커밋부터 쓰던 것이다
