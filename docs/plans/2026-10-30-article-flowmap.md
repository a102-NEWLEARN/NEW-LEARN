가로 · 세로는 **컨테이너 쿼리**(Tailwind v4 `@container` · `@min-[1024px]:`)로 CSS 만으로 바꾼다. 같은 마크업 하나라 상태 · 포커스가 넓이에 따라 흔들리지 않고, 크기를 재는 코드가 없다. 프로젝트에서 처음 쓰는 방식이다.
강조 풀기의 Esc 는 `MindmapGraph.tsx` 의 방식을 따른다 — 먼저 받은 쪽이 `preventDefault` 했거나 다른 창(dialog) 안에서 누른 Esc 는 넘긴다. 가짜 API(A8 · A9)는 1차 것을 그대로 쓴다.

브랜치: `git nb feat frontend 58 article-flowmap` (origin/frontend 에서). 1차 브랜치는 머지되어 끝났다.

## 리스크

- **컨테이너 쿼리를 처음 쓴다** — jsdom 은 CSS 를 몰라 가로 · 세로 전환은 단위 테스트로 못 지킨다. 브라우저에서 1280 · 900 · 375px 로 확인한다. Tailwind 4.3 이 `@min-[1024px]:` 를 만드는지 빌드 CSS 로도 본다
- 강조한 카드의 바탕을 가지색으로 칠한다 — DESIGN.md 「카드 배경을 관점마다 색 바꾸기」에 걸릴 수 있다. 프로토타입을 따르고 MR 에 짚는다

- 기본 보기가 바뀌어 1차의 화면 테스트 몇 개가 마인드맵을 찾지 못하게 된다 — 그 테스트는 `?view=map` 으로 열게 고친다
- 설정 상태를 올리면 `MindmapView` 의 기존 테스트가 상태를 직접 들고 있어야 한다 — 테스트용 감싸개를 둔다
