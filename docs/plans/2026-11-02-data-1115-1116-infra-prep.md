## 무엇을 / 왜

11-15 에 AI 팀이 서버 밖에서 완성한 기사 · 마인드맵 · 사건 · 이슈를 DB 덤프로 넘기면 인프라가 운영 DB 에 넣는다. 11-16 부터는 NewsData 를 하루 약 100건 받아 분석에 건다. 발표(11-18) 시연 데이터를 미리 완성해 두고, 남은 며칠은 실제 수집 흐름을 소량으로 돌리려는 것이다.

API 이름: B1 기사 투입(`POST /internal/v1/articles/{articleId}/release`) · W1 분석 결과 전달 — `docs/api-internal.md` 2 · 5절. A2 이슈 목록 · A3 이슈 헤더 · A4 이슈 타임라인 · A5 사건 패널 · A6 사건 관련 기사 · A7 최신 기사 · A8 기사 상세 · A9 기사 마인드맵 · A13 통합 검색 — `docs/api.md` 3절 표.

### A. 11-15 외부 완성 데이터 적재

**덤프 약속** — AI 팀에 먼저 보내 맞춘다. A 를 시작하면 운영 메모(`infra/server/data-load.md`)로 옮기고 이 절은 그곳을 가리킨다.

1. 만든 길 — AI 팀 DB 는 `compose.yaml` 의 DB 에 dev 판 backend 를 붙여 마이그레이션하고, 결과를 W1 으로 저장해 채운다. 그래야 마인드맵 `content` 모양(A9 가 이 모양으로 읽는다), `issue_category`, `linked_at`, 작업 행이 운영과 같다. SQL 로 직접 넣은 표가 있으면 무엇을 넣었는지 알려 준다
2. 스키마 — 운영과 같은 Flyway 판(지금 V10, 11-15 에 dev 의 마지막 판)
3. 형식 — 그 DB 컨테이너 안의 `pg_dump -Fc --data-only` 로 표 열 개만: `press` · `press_mapping` · `article` · `article_mindmap` · `article_embedding` · `analysis_job` · `event` · `article_event` · `issue` · `issue_category`. 뜰 때 나온 경고를 같이 보낸다
4. 넣지 않는 것 — 회원 표(`member` · `member_category` · `bookmark` · `interest_issue`), `category`(마이그레이션이 넣음), `category_mapping`(BE 몫 — AI 팀이 만든 대응이 있으면 따로 BE 에 넘긴다), `ingest_run`, `flyway_schema_history`
5. 공개 · 카테고리 — 화면에 보일 기사는 `released_at` 이 있다. 기사 `category_code` 와 `issue_category` 가 채워져 있다(비면 카테고리 탭에 안 나온다)
6. 발행 시각 — `published_at` 은 NewsData `pubDate`(UTC)를 한국 시간으로 바꾼 값이다(`docs/data-model.md` 2절 article). 11-16 수집과 규칙이 같아야 A7 정렬과 발생 시점이 맞는다
7. 작업 행 — 모든 `analysis_job` 이 `SUCCEEDED`, 또는 `retry_at` 이 빈 `FAILED` 다. `QUEUED` 는 없다. 사건에 묶인 기사는 MATCH_EVENT `SUCCEEDED` 행이 있다. 대표 번호가 있는데 판정 작업도 사건 연결도 없는 기사는 넣지 않는다
8. 임베딩 — 사건에 묶인 기사는 모두 벡터가 있다. 모델 · 판 · 입력이 운영 ai 와 같다(`dragonkue/BGE-m3-ko` 판 `7074d66a…` — `infra/k8s/services/ai/ai.yaml`, 본문 앞 800자 — `SSOT.md` 3절). `model` 칸 문자열을 AI 팀과 하나로 정한다
9. 전달 — 공유 드라이브 · 메신저로 파일과 sha256 을 같이. 저장소에는 올리지 않는다
10. 견본 — 11-10 전후로 사건 몇 개 분량의 덤프를 먼저 받아 시험한다

**운영의 시험 데이터는 모두 비우고 넣는다** (AI 팀장 확인 뒤). 덤프도 id 를 1부터 쓰고, 언론사 `newsis` 가 겹치고, 시험 기사 셋은 기반 만들기 후보(10/21 ~ 28 NewsData)라 같은 URL 이 덤프에 있을 수 있다. 11-15 전에 EMBED 워커가 먼저 떠 운영에 사건 · 이슈가 생겼을 수도 있어, id 를 집어 지우지 않고 내용 표를 외래 키 순서로 모두 비운다.

1. `analysis_job` · `article_mindmap` · `article_embedding` · `article_event`
2. `article` — 그 기사를 담은 북마크가 같이 지워진다. 행 수를 먼저 본다
3. `issue_category` · `event`
4. `issue` — 관심 이슈가 같이 지워진다. 행 수를 먼저 본다
5. `press_mapping` · `press`

회원 · `category` · `category_mapping` 은 건드리지 않는다. 임시 언론사 코드(`yonhapnewstv` · `mbn`)는 덤프의 언론사 행으로 바뀐다. 시험 기사를 남기는 갈래는 고르지 않는다 — 덤프에서 겹치는 언론사를 빼고 id 를 띄워야 해서 약속이 복잡해진다.

**큐 정리** — 비운 작업 행의 메시지가 큐에 남으면 같은 번호의 덤프 작업으로 읽힌다(메시지에 작업 번호가 들어 있다 — `ReleasedMessageFactory.java:35-48`).

- `embed` 그룹이 안 읽은 투입 메시지(EXTRACT 와 같은 메시지, 지금 셋)는 `XGROUP SETID` 로 건너뛴다. `$` 대신 `XRANGE` 로 확인한 마지막 메시지 ID 를 준다 — 확인 뒤 들어온 메시지를 건너뛰지 않게
- `extract` 그룹의 lag(`XINFO GROUPS analysis.released`)과 미ACK(`XPENDING analysis.released extract`)가 0 인지 본다. 남아 있으면 적재 뒤 ai 가 읽어 GMS 를 부른다
- `analysis.match_event` · `analysis.issue` 길이도 본다

**순서**

1. 덤프 약속을 운영 메모로 쓰고 AI 팀에 보낸다
2. 견본 덤프로 일회용 DB 시험(R1, 관리자 PC) — `compose.yaml` 의 DB · Redis(운영과 같은 이미지) + backend 마이그레이션 → 덤프 적재. 같은 덤프를 한 번 더 넣으면 기본 키 충돌로 통째로 되돌아가 행 수가 그대로인지 본다. backend 를 그 DB 에 붙여 띄우고 화면 API · 스케줄러를 본다(검증 1)
3. 최종 덤프로 R1 을 한 번 더
4. 11-15 — 서버 일회용 DB 시험(R2): 그날 손으로 뜬 매일 백업을 같은 Pod 의 `newlearn_load_check` 에 되살리고(`db-backup.md` 「되살리기 연습」) 비우는 SQL · 적재를 그대로 해 본 뒤 지운다. 회원 정보가 PC 로 나오지 않는다
5. 적재 직전 — 운영 DB 행 수 · 큐 상태를 읽고, 매일 백업 잡과 S3 잡을 손으로 하나씩 돌린다. 파일 이름 · 크기는 매일 잡 로그, sha256 은 S3 잡 로그에서 남긴다. 그 파일은 PC 에도 받아 둔다(쓰고 나면 지운다)
6. 적재 — 비우는 SQL 과 덤프(`pg_restore --data-only --disable-triggers -f -` 로 SQL 로 푼 것)와 시퀀스 맞추기(`setval` 을 최댓값 이상으로)를 **한 psql 트랜잭션**(`psql -1 -v ON_ERROR_STOP=1`)으로 넣는다. 실패하면 비운 것까지 통째로 되돌아간다. `--disable-triggers` 는 사건의 자기 참조 외래 키 때문이다 — 한 표 안 행은 저장된 순서로 나와, 반응 사건이 대상 사건보다 먼저 나오면 외래 키 검사에 걸린다. 슈퍼유저가 필요해 `newlearn` 의 `rolsuper` 를 먼저 본다. 끄고 넣었으니 적재 뒤 고아 행을 따로 검사한다
7. 큐 정리(위) → 확인(검증 2) → AI 팀장 · FE 에 결과와 함께 넘긴다

### B. 기사 적재 내부 API (BE 공동)

- 새 주소 하나(가칭 B2 기사 적재, 번호 · 모양은 BE 명세 때 정한다). 배치 키(`X-Internal-Key`, 역할 BATCH)로 연다. `/internal/v1/articles` 아래에 두면 지금 규칙(`InternalApiSecurityConfig.java:38-39`)이 덮는지 시험으로 확인한다
- 받은 기사를 `article` 에 넣고 id 를 돌려준다. 같은 URL 이면 넣지 않고 그 기사 id 를 돌려준다. 배치는 늘 B1 을 부르고, 이미 건 기사는 B1 의 409 로 건너뛴다 — 적재 뒤 B1 이 실패한 기사가 다음 실행에서 다시 걸리게
- 입력 검사 — 필수 값이 빠지면 저장하지 않고 이유를 돌려준다(PRD FR-1). URL 은 `http` · `https` 만(A8 의 원문 링크로 화면에 나간다). U+0000 이 든 값은 400(text 칸이 받지 않는다 — `QueryText.containsNul` 과 같은 방식)
- B 에서 정할 것 — 처음 보는 언론사의 코드(`docs/data-model.md` 5절 15번은 NewsData `source_id` 가 유력하다는 가정뿐), `pubDate`(UTC) → 한국 시간(2절 article 의 관찰 그대로 쓸지), 카테고리 대응(5절 7번 행이 없으면 비움), `released_at` 은 비움
- `ingest_run` 은 이번에 쓰지 않는다 — 하루 약 100건 최신 기사라 이어 받을 위치가 필요 없다. 실행 한 번의 받은 수 · 넣은 수 · B1 결과는 배치 Job 로그 한 줄로 남긴다
- 실패하는 시험 먼저. 정한 것으로 `docs/api-internal.md` 2절 앞 명세 · `docs/api.md` 내부 API 표 · F01 스펙 · `docs/data-model.md` 5절 15번(정했으면 표에서 지움) · `SSOT.md` 8절(적재 길)

## 리스크

- **덤프가 약속과 다름** — 판이 다른 스키마, 빈 `released_at` · 카테고리, `QUEUED` 작업 행, 벡터 없는 사건, 다른 마인드맵 모양. 큐에 안 넣은 `QUEUED` 는 스케줄러가 GMS 를 부르고, 큐에 넣은 `QUEUED` 는 판정 줄을 영영 막는다. 「3분 동안 새 작업 0」만으로는 막힌 줄을 못 보니 SQL 검사(아래 검증 1)를 기준으로 둔다
- **임베딩 모델이 다름** — 운영은 막지 않고 그대로 비교해 11-16 기사가 엉뚱한 사건 후보를 받는다. 덤프 `model` 칸을 AI 팀과 정한 문자열과 견주고, 판은 AI 팀 확인으로 대신한다(칸에 판이 없을 수 있다)
- **자기 참조 외래 키** — 견본이 작으면 R1 은 통과하고 최종 덤프에서 터질 수 있다. 처음부터 `--disable-triggers` 로 넣고 고아 행을 검사한다. `newlearn` 이 슈퍼유저가 아니면 R1 에서 드러난다 — 그때는 사건 표만 반응 대상 칸을 비우고 넣은 뒤 채우는 SQL 로 바꾼다
- **시퀀스가 낮게 남음** — 새 기사 · 사건 · 작업 INSERT 가 기본 키 충돌로 실패한다. 적재 트랜잭션 안에서 `setval` 하고 검증에서 다시 본다
- **적재 중 사이트** — 한 트랜잭션이라 비운 상태 · 반쯤 넣은 상태는 밖에서 안 보인다. 적재 동안 B1 을 걸지 않는다. 11-15 오후 조용한 때를 골라 팀에 알린다
- **큐에 남은 옛 메시지** — 덤프 작업 번호와 겹쳐 엉뚱한 작업으로 읽힌다. 큐 정리(A)에서 그룹마다 본다
- **판정 워커가 11-16 까지 없음** — 11-16 기사는 마인드맵만 생기고 사건 · 이슈에 안 붙는다. 시연이 「적재한 이슈 + 새 기사 마인드맵」 모양이 된다. AI 팀 일정에 달렸다. EMBED 워커가 뜨면 ai 메모리가 3.1 ~ 3.6GB 로 는다(요청 4Gi · 상한 5Gi 로 이미 잡음)
- **NewsData 구독이 먼저 끝남** — 끝나는 날 미확인. D 에서 묻는다
- **하루 100건이 같은 사건으로 안 모임** — 무작위로 고르면 사건으로 묶일 기사가 함께 안 들어온다(`SSOT.md` 8절). 고르는 조건은 AI 팀에 받는다
- **외부 값이 화면에 나감** — 적재 API 가 받는 URL 이 A8 원문 링크가 된다. B 의 입력 검사로 막는다
- **BE 일정** — 적재 API(B)가 늦으면 C 를 반영해도 켜지 못한다. 그때는 11-02 처럼 사람이 SQL 로 넣고 B1 을 거는 길이 남는다(그 SQL 은 저장소 밖 공유 노트에 있다 — A 의 운영 메모에 옮긴다)
- **12월까지 운영하면** — GMS 기간이 끝나고 11-30 에 토큰 넷이 만료된다(`SSOT.md` 8절). 이 계획 범위 밖
