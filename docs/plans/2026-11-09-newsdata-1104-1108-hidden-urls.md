# 11/4~11/8 수집과 숨김 URL 빼기 — 기반 분석 데이터셋

## 무엇을 / 왜
서버의 기존 DB(`minjun/issue_backfill/newsdata_collect/newsdata.sqlite`, 10/21~11/3 · 최종 72,402건)에 11/4~11/8을 NewsData로 직접 받아 넣는다. 그다음 운영에서 숨긴 기사 URL 목록 두 개로 데이터셋에서 그 기사를 뺀다. 지금 수집 노트북은 날짜가 10/29~11/3으로 박혀 있고, URL로 빼는 기능도 없다.

**확인한 것 (2026-11-09 10시)**
- **GitLab:** `data/`는 dev · infra · ai 브랜치 모두 10/21~11/3 SQLite 하나뿐이다. 11/5 뒤 MR에도 11/4~11/8 기사는 없다. 그래서 사용자 지시대로 직접 받는다.
- **`hidden-urls-1105.txt`:** URL 3,500개 중 3,434개가 우리 DB 기사와 그대로 맞는다(scheme · 끝 `/`를 맞춰도 늘지 않는다). 72,402판 기준으로는 최종(selected) 3,149 · 원본에 안 뽑힘(extra) 285 · DB에 없음 66이다. 빼면 10/21~11/3 최종은 **69,253건**이 된다.
- **`hidden-urls-1109.txt`:** 15개 모두 11/4~11/7 기사라 지금 DB에는 0개다. 받은 뒤에 맞춰 본다.
- **`articles-2026-11-04-v2.jsonl`:** 운영 DB의 11/4 기사 12,372건이다(id 79,338~91,775). 이번 일에는 쓰지 않는다.

## 바꿀 파일
- `ai/experiments/issue_backfill/newsdata_dataset.py`
  - `hidden_urls` 표(`link` PK · `source` · `added_at`)를 `SCHEMA`에 더한다.
  - `add_hidden_urls(conn, urls, source)`를 더한다. 목록을 넣고 `{새로 넣은 수, DB 기사와 맞은 수}`를 돌려준다. 같은 목록을 다시 넣어도 늘지 않는다. 링크는 그대로 비교한다. 팀 규칙이 "같은 URL = 같은 기사"이고, 1105 목록으로 확인했을 때 정규화해도 더 맞는 것이 없었다.
  - `build_day`에서는 원본을 고르고 불량 본문을 거른 **뒤에**, 고른 원본 안의 숨김 URL에 사유 `hidden`을 붙인다. 불량 본문 사유가 이미 붙은 기사는 그 사유를 둔다. 원본을 고르기 전에 빼면 빈자리를 다른 기사가 채워 데이터셋이 "빼기"보다 많이 바뀌므로 뒤에서 뺀다.
- `ai/experiments/issue_backfill/collect_source.py` (수집 노트북 원본)
  - 날짜 칸: archive `11/4~11/7`, latest `11/8`.
  - 상한: `ARCHIVE_MAX_CREDITS = 3000`(추정 2,670), `LATEST_MAX_CREDITS = 300`(추정 약 115).
  - 받기 전 백업 칸: `../_archive_20261109/`에 DB 사본을 둔다.
  - 새 칸 「숨김 URL 빼기」를 더한다.
    - 노트북 옆 `hidden_urls/*.txt`를 읽어 파일 이름을 `source`로 `add_hidden_urls`를 부른다.
    - 그 뒤 10/21~11/8을 `build_day`로 다시 만든다.
    - 목록별로 맞은 수와 상태별 수(selected · hidden · 불량 사유 · extra · DB에 없음)를 찍는다. 1109 목록은 URL마다 상태를 찍는다.
  - 11/4에 한 번만 돌린 「10/21~28 합치기」 칸은 지운다. 남은 기록은 커밋 4d6906f와 README에 있다.
- `ai/tests/test_newsdata_collect.py`: 테스트 3개를 더한다.
  - 고른 원본 안의 숨김 URL은 `hidden`으로 빠지고, raw는 그대로이며, 원본에 안 뽑힌 숨김 기사는 `extra`로 남는다.
  - 불량 본문 사유가 `hidden`보다 앞선다.
  - 목록을 다시 넣어도 늘지 않고, 맞은 수를 돌려준다.
- `ai/experiments/issue_backfill/README.md`
  - 「하루 단위 수집」 제목과 표를 11/8까지로 늘린다(결과 숫자는 서버 실행 뒤 채운다).
  - 「숨김 URL」 절을 새로 쓴다: 출처(운영 라벨 숨김, 주우님), 빼는 시점(원본 고른 뒤), 목록별 건수.

- **서버 백업은 약 600MB를 쓴다.**
