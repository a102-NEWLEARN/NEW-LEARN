# F12 회원 · 관심 분야 — A17·A18

계약 원본: [공통 인증·오류](../api.md), [회원 정보·A17·A18](../api-screen.md),
[회원 데이터 모델](../data-model.md), [62번 인증 기반](F12-member-auth-api.md).
분야 순서와 인증·CSRF 오류 우선순위는 2026-10-26 사용자 승인으로 원본에 반영했다.

- AC-1: A17은 로그인한 회원의 `MemberResponse`를 주고 민감정보는 내보내지 않는다. 분야 순서는 회원 정보 계약과 같다.
- AC-2: A18은 본인의 관심 분야만 통째로 교체하고 200과 같은 회원 응답을 준다. 반복 요청은 같은 결과이며 다른 회원을 바꾸지 않는다.
- AC-3: 중복은 합친다. 목록 누락·null·빈 목록·빈 코드·없는 코드(U+0000 이 든 코드 포함, 2026-10-30)는 400 `VALIDATION_FAILED`와 한국어 `errors[]`를 준다. 잘못된 요청 뒤 기존 목록은 유지된다.
- AC-4: 삭제·등록이 한 쓰기 트랜잭션이다. DB가 등록 중 실패해도 기존 목록이 복구된다. 동시 요청의 목록을 섞어 저장하지 않는다.
  시험에서는 두 요청이 실제로 겹쳐 회원 행 잠금에서 대기하는지 관측하고, 해제 후 각 요청과 최종 저장 목록을 확인한다.
- AC-5: 기존 세션의 A17과 변경 후 로그인 응답은 최신 목록을 읽는다. 62번 principal·회원 응답·조립 로직을 재사용한다.
- AC-6: 인증·CSRF 우선순위는 A18 계약과 같다. 실패한 요청은 관심 분야를 바꾸지 않는다.
- AC-7: 분야 1개·5개에서도 회원 조회의 SQL 수가 늘지 않는다. 62번과 기존 A1~A8 회귀를 유지한다.
- AC-8: Swagger에 기존 회원 태그·A17·A18 성공·오류 응답을 표시하고 인증 principal을 요청 인자로 노출하지 않는다.
