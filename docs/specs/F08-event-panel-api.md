# F08 사건별 관련 기사 조회 — A5·A6

계약 원본: [공통 규칙](../api.md#1-공통-규칙), [공통 조각·A5·A6](../api-screen.md),
[기사 분석 상태](../api-internal.md#6-작업-상태와-화면용-상태), [데이터 모델](../data-model.md).
정렬·요약 범위는 2026-10-26 사용자 승인으로 계약 원본에 반영했다.

- AC-1: A5는 사건 참조 필드·저장된 요약·발생 시점 근거·이슈 참조를 내보내며 요약을 재생성하지 않는다.
- AC-2: 이슈 밖 사건의 이슈와 앞뒤 참조는 null이다. 같은 이슈의 앞뒤 이동·동률 처리는 A5 계약과 같고, 공개 기사가 문턱보다 적은 사건은 건너뛴다(Jira 179 · 206) — 타임라인에 보이는 사건과 같은 집합이다.
- AC-3: 기사 수·언론사 목록은 공개 기사만 집계하고 언론사 중복·정렬은 A5 계약을 지킨다.
- AC-4: 없는 사건, 관련 기사 0건 · 공개 전 기사만 있는 사건은 두 API 모두 404 `EVENT_NOT_FOUND`다(`api.md` 1절, Jira 179).
- AC-5: A6는 A6 계약의 정렬·페이지 모양을 지키고 `size=5` 및 다음 쪽을 정확히 반환한다. 빈 쪽도 총개수를 유지한다.
- AC-6: A6는 기존 기사 요약 DTO·조립기와 공통 페이지·시간·참조 DTO를 재사용한다. 요약·결과 존재·분석 상태를 구분한다.
  `NOT_ANALYZABLE`은 계약에 적힌 W1 구현 범위이며 49에서 별도 상태 계산을 추가하지 않는다.
- AC-7: null 필드를 유지하고 시각은 +09:00이다. 로그인 없이 조회하고 잘못된 페이지 인자는 400이다.
- AC-8: 항목마다 SQL을 추가하지 않는다. 기존 A1~A4·A7·A8 계약과 테스트를 유지한다.
