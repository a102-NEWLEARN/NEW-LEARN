# /handoff — 다음 세션에 넘기기

## 왜 필요한가

AI 는 대화가 길어지면 앞부분을 잃는다. 사람도 하루가 지나면 잊는다.
그때 **다시 파악하는 비용**이 실제 작업보다 커지는 일이 흔하다.

이 스킬은 그 비용을 **한 화면짜리 메모**로 줄인다.

## 언제 쓰나

- 대화가 길어졌거나 곧 정리될 것 같을 때
- 오늘 작업을 여기서 끊을 때
- 한 작업을 여러 세션·여러 사람이 나눠 할 때
- 손대다 만 상태로 남길 때 ← **제일 중요하다**

## 지금 저장소 상태 (이 스킬을 부르면 채워진다)

!`git status --short`

!`git log --oneline -5 2>/dev/null || echo "(커밋 없음)"`

## 무엇을 쓰나

```
# HANDOFF — <날짜, 절대 표기>

## 지금 상태
(무엇이 되고 무엇이 안 되나. 커밋했나 안 했나)

## 마지막으로 한 것
- <커밋 해시 또는 파일> — 무엇을

## 다음에 할 것
1. (제일 먼저 할 것부터. 구체적으로)

## 🔴 함정 / 알아야 할 것
- (여기서 시간을 쓴 것, 실패한 시도, 착각하기 쉬운 것)

## 열린 질문
- (사용자에게 물어봐야 하는 것)

## 이어서 하려면 — 이 순서로
1. `git status` · `git log` 로 지금 상태를 본다
2. 이 메모와 계획표(`.claude/stack.md` §7 「진행 상태」) · 승인한 계획(§7 「승인한 계획」)을 읽는다
3. 새 기능을 시작하기 전에 `.claude/stack.md` §3 `<영역>_RUN`(비었으면 그 줄 주석이 가리키는 스킬)으로 기존 기능 하나를 끝에서 끝까지 확인한다.
   깨져 있으면 그것부터 고친다
```

## 지켜야 할 것

- 🔴 **날짜는 절대 표기로.** "어제"·"방금"은 다음 세션에서 아무 뜻이 없다.
- 🔴 **실패한 시도를 반드시 남긴다.** 이게 없으면 다음 세션이 **똑같은 것을 다시 해 본다.**
  성공한 것만 적힌 인계는 절반만 인계한 것이다.
- **짧게.** 한 화면을 넘으면 안 읽는다. 자세한 것은 문서를 가리킨다.
- 🔴 **메모는 `.claude/stack.md` §7 「인계 메모」 자리에 쓴다.** 채팅에만 남기면 `/clear` 할 때 같이 지워진다.
  자리가 비어 있으면 채팅에 남기고 어디에 둘지 묻는다. 새 파일을 마음대로 만들지 않는다.
- 자동 메모리(`/memory`)에 프로젝트 결정이 쌓였으면 기록(`.claude/stack.md` §7 의 DECISIONS)으로 옮기자고 말한다.
  자동 메모리는 이 컴퓨터에만 있어서 팀원에게 안 보인다 (`.claude/HARNESS.md` 6절).

## 커밋 안 한 변경이 남아 있으면

**반드시 그 사실을 적는다.** 다음 세션이 `git status` 를 안 보고 시작하면
남의 미완성 작업 위에 덮어쓴다.
