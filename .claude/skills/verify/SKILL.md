# /verify — 진짜 동작하나 확인하기

`.claude/HARNESS.md` 약속 1("증거 없이 됐다고 하지 않는다")의 **실행부**다.

## 3단계로 올라간다. 아래가 실패하면 위는 볼 필요도 없다.

### 1단계 — 기계 검사

**verifier 조수에게 맡긴다.** 출력이 길어서 메인 대화에 쌓으면 안 된다.

포맷 검사 → 린트 → 테스트. 명령은 `.claude/stack.md` §3 에서 읽는다.

> 🔴 **통과시키려고 테스트를 고치지 않는다.** 실패하면 실패한 것이다.

### 1-2단계 — 되돌림 확인 (테스트를 새로 썼을 때만)

새 테스트가 정말 그 변경을 지키는지 본다. **구현만 고치기 전으로 돌려 놓고 새 테스트가 빨개지는지 본다.**
안 빨개지면 그 테스트는 아무것도 지키지 않는다 — 구현을 베꼈거나 엉뚱한 것을 본다.

1. verifier 결과를 받은 뒤에 한다. 조수가 테스트를 돌리는 중에 파일을 바꾸면 결과가 섞인다
2. 새 테스트가 지키는 구현 파일을 고르고, 임시 폴더(`mktemp -d`)에 복사해 둔다. 테스트 파일은 그대로 둔다
3. 구현 파일을 고치기 전으로 돌린다. 원래 있던 파일은 `git show <기준>:<경로> > <경로>`, 새로 만든 파일은
   임시 폴더로 옮긴다. 기준은 커밋 전이면 `HEAD`, 이미 커밋했으면 작업을 시작하기 전 커밋이다
4. 새 테스트만 돌린다. **단언(assert)에서** 빨개져야 한다. import · 컴파일 오류로 빨간 것은 확인이 아니다
5. 임시 폴더의 구현 파일을 그대로 되돌려 놓고, 새 테스트가 다시 초록인지 본다

`git stash` 는 쓰지 않는다. 새 파일이면 실패하고, 이미 커밋했으면 아무것도 안 되돌리고, 꺼낼 때 스테이지가
풀리거나 예전에 저장해 둔 다른 변경이 꺼내진다. 위 방법은 작업 트리 파일만 바꿨다가 되돌려서 스테이지한 내용은 그대로다.

### 2단계 — 실제로 돌려본다

기계 검사가 통과해도 **그건 안 깨졌다는 뜻이지 새 기능이 된다는 뜻이 아니다.**

| 종류 | 어떻게 |
|---|---|
| 서버 · API | 실제로 호출해서 응답 본문을 본다 |
| 화면이 있는 것 | 띄워서 스크린샷 |
| CLI · 스크립트 | 실행 출력 |

`.claude/stack.md` §3 의 `<영역>_RUN` 을 쓴다. 끝나지 않는 명령이면 백그라운드로 띄우고 확인이 끝나면 끈다.

띄우는 법은 한 곳에만 둔다. 내장 `/run-skill-generator` 가 실행법을 `.claude/skills/run-<이름>/` 에
따로 적었으면 `.claude/stack.md` §3 의 RUN 줄 주석대로 한다.

### 3단계 — 인수 기준 대조

스펙의 **성공 기준**을 번호(AC-1 …)대로 한 줄씩 짚는다 (스펙은 `.claude/stack.md` §7 「기능 스펙」에 있다). 스펙이 없으면 원래 요청을 기준으로 삼는다.

## 출력 — 이 형식으로 보고한다

```
## 1단계 기계 검사
| 단계 | 결과 |
|---|---|
| 포맷 | 통과 |
| 린트 | 통과 |
| 테스트 | 통과 (42개) |
| 되돌림 확인 | 새 테스트 3개 — 고친 코드를 되돌리면 3개 다 실패 / 해당 없음 (새 테스트 없음) |

## 2단계 실제 실행
(명령 + 출력/스크린샷)

## 3단계 인수 기준
- [x] AC-1 <기준> — 어떻게 확인했는지
- [ ] AC-2 <기준> — **확인 못 함. 이유**

## 확인하지 못한 것
```

## 지켜야 할 것

- **숫자를 적는다.** "테스트 통과"가 아니라 "42개 통과". 0개가 돌아도 통과로 보인다.
- **확인 못 한 것을 비워 두지 않는다.** 못 한 것이 없으면 "없음"이라고 쓴다.
- 실패했으면 **실패했다고 말하고 출력을 붙인다.** 고쳐서 다시 돌린 뒤 보고해도 되지만
  고쳤다는 사실은 숨기지 않는다.
- 한 번 빨개졌다가 다시 돌려서 초록이면 **통과가 아니다.** 흔들리는 테스트라고 보고하고 기록에 남긴다
  (`.claude/stack.md` §7 의 OPEN). 재실행으로 덮으면 다음에 진짜 회귀가 와도 「또 그거겠지」로 지나간다.

## 커밋 직전에 자동으로 불렸을 때

Claude Code 는 이름이 `verify` 인 프로젝트 스킬을 커밋 직전마다 부르게 한다. 문서 · 테스트만 바뀐 커밋은 뺀다.

조건은 대화를 시작할 때 따진다 — Claude Code v2.1.286 이상 · Claude 가 이 스킬을 부를 수 있다(`disable-model-invocation: true` 같은 막음이 없다) ·
설정 `includeGitInstructions`(Claude 에게 내장 커밋 · PR 안내를 주는 설정)를 끄지 않았다.
셋 중 하나라도 어긋나면 자동으로 불리지 않는다.

이렇게 불렸으면 커밋 훅이 같은 명령을 바로 이어서 돌리므로 1단계(기계 검사)는 건너뛴다.
단 훅이 안 걸려 있으면(`git config core.hooksPath` 가 `.claude/hooks` 가 아니면) 건너뛰지 않는다.
1-2단계(되돌림 확인)는 건너뛰지 않는다 — 이 커밋에 새 테스트가 있으면 한다. 스테이지한 내용은 안 건드린다.

동작이 바뀐 커밋만 2 · 3단계를 한다. 동작이 그대로면 「해당 없음 — 동작 변화 없음」으로 끝낸다.
같은 변경으로 이 대화에서 이미 2 · 3단계를 했으면 그 결과를 다시 쓴다. 어느 단계든 실패하면 커밋하지 않고 보고한다.
