# /health-check — 살아있나 확인하기

**아래에서 위로 올라간다.** 낮은 층이 깨져 있으면 위층 결과는 믿을 수 없다.
설계 원리와 함정은 `.claude/docs/health-check.md`.

선언값은 `.claude/stack.md` 에서 읽는다 (주로 §5). **여기에 명령을 지어 넣지 않는다.**

---

## L0 — 하네스 자체 (제일 먼저)

하네스가 안 돌고 있으면 나머지 점검도 못 믿는다.

| 확인 | 방법 | 깨졌을 때 |
|---|---|---|
| git 훅이 걸렸나 | `git config core.hooksPath` 가 `.claude/hooks` 인가 | `bash .claude/hooks/install.sh` (다른 값이면 install 이 `--force` 를 요구한다) |
| 훅이 **실제로 도나** | `git commit --allow-empty -m " "` → 「커밋 전 게이트」가 찍히고 `empty commit message` 로 멈추면 훅이 걸렸다. 커밋은 남지 않는다. 아무것도 안 뜨면 설치가 안 됐다. 메시지는 공백 하나다 — 빈 문자열은 PowerShell 5.1 이 인자째 버린다 | 위와 같음 |
| 훅 파일 줄바꿈 | 파일에 `\r` 이 섞이지 않았나 | `install.sh` 를 다시 돌린다 |
| `settings.json` 문법 | JSON 으로 읽히나 | 깨지면 대화형 세션이 시작할 때 오류 창을 띄운다. 훅이 걸릴 도구는 matcher 가 고른다. matcher 의 오타(예: `Edit\|Wirte`)와 실패를 `exit 0` 으로 삼키는 훅 명령은 오류 없이 지나가니 눈으로 본다 |
| `.claude/stack.md` 빈칸 | `<채워넣기>` 가 남아 있나 — 대화를 시작할 때 절마다 센 수가 찍힌다 (`hooks/session-start.sh`) | §3 `AREAS` 가 비었으면 `/harness-init`. 아니면 그 칸을 채운다 (§4 실측값은 첫 CI 실행 뒤). 운영 모듈을 껐는데 *(운영)* 칸이 남아 있으면 지운다 |
| 시크릿 스캔 | `bash .claude/hooks/secret-scan.sh --all` | 걸린 것을 먼저 처리 |
| 검사기가 살아 있나 (새 컴퓨터 · 훅을 고친 뒤에만) | `bash .claude/hooks/tests/run.sh` — `test-*.sh` 를 전부 돈다. Windows 에서는 몇 분 걸린다 | 실패한 테스트부터 본다 |
| 지시문끼리 어긋나지 않나 (있으면) | `/doctor prompt-audit` 를 경로 없이 한 번. `CLAUDE.md` · `AGENTS.md` 와 `.claude/` · `~/.claude/` 아래의 규칙 · 스킬 · 조수를 다 본다. 한 폴더만 보려면 경로를 준다. Claude Code 2.1.283 이상, 내장 `/claude-api` 스킬이 켜져 있어야 한다 | 보고를 보고 없는 참조와 모순을 고친다 (도구는 승인 전에 파일을 고치지 않는다) |

🔴 **"설정했다"와 "돈다"는 다르다.** 두 번째 줄(커밋을 시도해 보기)을 건너뛰지 않는다.

## L1 — 로컬 (내 컴퓨터에서 개발이 되나)

`.claude/stack.md` §5 L1 표의 모든 줄을 확인한다. 아래는 줄마다 주의할 점이다.

| 확인 | 깨졌을 때 |
|---|---|
| 「다 됐는지 한 번에 보는 명령」을 먼저 돌린다 | 실패한 줄부터 아래 항목으로 좁힌다 |
| 필요한 도구가 깔렸나 · **버전이 맞나** | 버전이 어긋나면 "나는 되는데 CI 는 안 되는" 상태가 된다 |
| 환경변수가 다 있나 | **이름만 확인한다. 값을 출력하지 않는다** |
| 로컬 의존 서비스(DB·캐시)가 떠 있나 | 띄우는 명령은 `.claude/stack.md` |
| 의존성 설치가 됐나 | `.claude/stack.md` §3 의 `<영역>_INSTALL` |
| 짝을 맞춰야 하는 환경변수가 양쪽에서 같은가 | 값은 출력하지 않고 **같다 · 다르다만** 적는다 |

> ⚠️ **없는 환경변수는 대개 조용히 실패한다.** 프로그램은 정상 기동하고 그 기능만 안 된다.
> 그래서 "떴으니까 괜찮다"가 아니라 **목록과 대조**해야 한다.

---

## L2 — 런타임 (돌고 있는 서비스가 정상인가)

상주 프로세스가 없으면(CLI · 라이브러리) **`해당 없음`** 이라고 적고 넘어간다.

| 확인 | 방법 |
|---|---|
| 프로세스가 떠 있나 | `.claude/stack.md` §5 L2 의 헬스 엔드포인트 |
| 의존 서비스에 붙었나 | 헬스 엔드포인트 응답 |
| **배포 판정용** 헬스가 정상인가 | `.claude/stack.md` 의 배포 판정 엔드포인트 |

🔴 **"서비스가 건강한가"와 "배포해도 되는가"는 다른 질문이다.**
무엇을 배포 판정에 넣고 무엇을 빼는지, 왜 그렇게 나누는지는 `.claude/docs/health-check.md` §2.

---

## L3 — 배포 후 (방금 올린 게 진짜 살아났나)

배포가 없으면(`.claude/stack.md` §6 「배포가 있나」) **`해당 없음`** 이라고 적고 넘어간다.

| 확인 | 방법 |
|---|---|
| 실제 API 가 응답하나 | 🔴 **헬스 주소 말고 진짜 기능을 부른다** |
| 어떤 버전이 떠 있나 | `.claude/stack.md` §5 L3 「떠 있는 버전 확인」. 방금 올린 커밋 · 태그와 같아야 한다 |
| 로그에 새 에러가 없나 | 배포 직후 몇 분 |

> 헬스 주소를 믿으면 안 되는 이유는 `.claude/docs/health-check.md` §3. 배포 판정이 속는 경우는 같은 문서 7절.

실패하면 **고치려 들기 전에 `.claude/stack.md` §6 의 되돌리는 법**을 먼저 본다.

## 출력 — 이 형식으로 보고한다

```
| 층 | 항목 | 결과 |
|---|---|---|
| L0 | git 훅 | ✅ 동작 확인 |
| L0 | stack.md | ⚠️ 빈칸 3개 |
| L1 | 환경변수 | ❌ DATABASE_URL 없음 |
| L2 | — | 해당 없음 (상주 프로세스 없음) |

## 조치가 필요한 것
1. <무엇> → <어떻게>
```

- **확인 못 한 항목은 `확인 못 함`** 으로 적는다. ✅ 로 넘기지 않는다.
- **비밀값은 절대 출력하지 않는다.** "있음/없음"만 적는다.
