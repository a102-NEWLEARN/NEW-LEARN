# /feature-done — 진짜 끝났나

개발에서 제일 흔한 거짓말이 **"다 됐어요"** 다. 코드는 됐는데 문서는 옛날 그대로인 상태.
이 스킬은 그걸 막는다.

**하나라도 못 채웠으면 "완료"라고 말하지 않는다.** 그 항목을 먼저 채운다.

---

## 1. 테스트 · 동작 — 증거

`/verify` 를 돌린 결과가 있어야 한다. 없으면 지금 돌린다.

- [ ] 기계 검사 통과 (숫자까지)
- [ ] 실제로 돌려서 확인
- [ ] 인수 기준 충족 — 스펙이 있으면 성공 기준 번호(AC-1 …)마다

## 2. 문서 — 짝이 맞나

`.claude/stack.md` §7 의 단일 진실 문서 중 **이번 변경과 짝이 되는 것**을 찾아 갱신한다.

| 바꾼 것 | 같이 고쳐야 하는 것 |
|---|---|
| 동작이 스펙과 달라졌다 | 스펙 (§7 「기능 스펙」). 성공 기준 번호는 다시 매기지 않는다 |
| API 엔드포인트 | API 명세 |
| 데이터 구조 | 데이터 모델 문서 · 관계도 |
| 화면 · 이동 경로 | 화면/네비게이션 문서 |
| 설정 · 환경변수 | `.claude/stack.md` · 배포 문서 · 예제 파일 |

> 자동 생성되는 문서라면 **재생성하고 커밋했는지** 확인한다.
> `.claude/docs/drift-guards.md` 에 자동으로 잡는 방법이 있다.

## 3. 진행 상태 — git 로그 기준으로

계획표 위치는 `.claude/stack.md` §7 「진행 상태 (계획표 · 이슈 트래커)」. 해당 없음이면 이 절을 건너뛴다.

- [ ] 이번에 끝난 항목을 계획표에 반영
- [ ] 🔴 **`git log` 를 먼저 본다.** 다른 세션·다른 사람이 이미 커밋했는데
      계획표에 반영 안 된 것이 있으면 **먼저 발견한 쪽이 함께 갱신한다.**

> 계획표는 "지금 git 로그 기준으로 뭐가 진짜 끝났나"를 반영해야 한다.
> 특정 세션의 기억에 의존하면 안 된다.

- [ ] **구현 중인 항목은 체크하지 않는다.** 반쯤 된 것에 체크하면 계획표를 못 믿게 된다.

## 4. 리뷰

- [ ] **reviewer 조수**에게 맡긴다 (스펙 정합성 · 보안 · 엣지케이스 · 승인한 계획의 「안 바꿀 것」)
- [ ] 정확성 버그는 내장 `/code-review` 로 본다
- [ ] 인증 · 권한 · 입력 처리 · 비밀값 · 외부 전송에 닿는 변경이면 내장 `/security-review` 도 돌린다 (`origin` 원격이 있어야 돈다)
- [ ] reviewer 의 「고쳐야 함」과 두 내장 리뷰가 찾은 문제를 고쳤거나 **안 고친 이유를 적었다.** reviewer 의 「선택」은 적어 두고 넘어간다
- [ ] 고쳤으면 `/verify` 를 다시 돌리고 reviewer 를 한 번 더 부른다. 고친 자리가 새로 깨지는 일이 흔하다
- [ ] reviewer 판정이 「확인 필요」면 무엇을 확인해야 하는지 **사람에게 묻는다.** Claude 가 스스로 통과로 바꾸지 않는다
- [ ] reviewer 의 「확인하지 못한 것」은 보고에 그대로 옮긴다. 완료를 막지는 않지만 지우지도 않는다

## 5. 마지막 확인

- [ ] `.claude/stack.md` 를 고쳐야 할 변화가 있었나 (명령·경로·환경변수가 늘었나)
- [ ] 새로 생긴 **로컬 전용 파일**을 `.claude/stack.md` §8 과 `.gitignore` 에 적었나
- [ ] 배포에 영향이 있으면 → `/deploy-check`

## 6. 프로젝트 항목

`CLAUDE.md` 「완료 정의」 아래에 프로젝트가 더한 줄을 하나씩 짚는다. 줄마다 보고 표에 한 행씩 넣는다.
더한 줄이 없으면 「없음」이라고 적는다.

## 보고 형식

```
## 완료 정의 점검
| 항목 | 상태 |
|---|---|
| 테스트 | ✅ 42개 통과 |
| 인수 기준 | ✅ AC-1 · AC-2 · AC-3 |
| 문서 | ⚠️ API 명세 미갱신 → 지금 고침 |
| ... | |
| (프로젝트 항목) <CLAUDE.md 의 한 줄> | ✅ / ⚠️ / 없음 |

## 아직 안 된 것
- (없으면 "없음")

## 리뷰가 확인하지 못한 것
- (reviewer 의 「확인하지 못한 것」 그대로. 없으면 "없음")
```

🔴 **"안 된 것"이 하나라도 있으면 완료가 아니다.**
