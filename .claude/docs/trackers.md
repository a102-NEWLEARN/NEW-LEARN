# 기록 3종 운영법

세 가지를 **나눠서** 남긴다. 섞이면 아무것도 못 찾는다.

| 기록 | 담는 것 | 없으면 |
|---|---|---|
| **DECISIONS** | 정한 것 + **왜** | 몇 달 뒤 같은 논의를 다시 한다 |
| **EXPERIMENTS** | 재본 것 + **숫자** | 같은 시행착오를 반복한다 |
| **OPEN** | 아직 못 정한 것 | "추측 금지"가 지켜질 수 없다 |

파일 이름과 위치는 프로젝트가 정하고 `stack.md` §7 에 적는다.
진실 문서 하나에 절로 나눠 두는 방식(`HARNESS.md` 6절)이어도 항목 형식은 같다.

---

## 공통 규칙

- 🔴 **날짜는 절대 표기.** "지난주"·"최근"·"방금"은 6개월 뒤에 아무 뜻이 없다.
- **왜를 적는다.** 무엇을 정했는지는 코드를 보면 알 수 있다. **왜 그랬는지는 못 본다.**
- **뒤집을 때는 원래 근거가 아직 유효한지부터 확인한다.**
  전제가 사라져서 뒤집는 것과 까먹어서 뒤집는 것은 다르다.

---

## DECISIONS — 확정 / 폐기

```
## <결정 한 줄> (<날짜>)
- 상태:    확정 / 대체됨 → <대체한 결정 제목>
- 무엇을: 
- 왜:      (대안을 왜 안 골랐는지까지)
- 근거:    (측정했으면 EXPERIMENTS #N)
- 영향:    (이 결정에 기대는 것들)
```

뒤집은 결정은 지우지 않는다. 상태를 「대체됨」으로 바꾸고 새 결정을 가리킨다.
흔히 ADR(아키텍처 결정 기록)이라고 부르는 형식과 같다. 결정마다 파일을 따로 두는 팀은
`docs/decisions/0001-<제목>.md` 처럼 번호를 붙인다 (MADR 형식).

### 🔴 "되살리지 말 것" 절을 반드시 둔다

기능을 지웠으면 **왜 지웠는지**를 남긴다.

```
## <지운 것> — 되살리지 말 것 (<날짜>)
- 무엇을 시도했나:
- 왜 안 됐나:      (숫자로)
- 되살리려면:      먼저 이것부터 읽을 것
```

없으면 다음 사람이 **똑같이 다시 만든다.** 되돌리기 한 번이면 코드는 돌아오지만
**실패한 상태로 돌아간다.**

---

## EXPERIMENTS — 잰 것

```
## #<번호> <무엇을> (<날짜>)
조건:   (무엇을 어떻게 쟀는지. 재현 가능하게)
기준선: 
결과:   
판정:   채택 / 기각 / 판단 불가
왜:     (한두 줄)
⚠️ 이 측정이 말하지 못하는 것:
```

- **"판단 불가"도 정당한 결론이다.** 차이가 안 나면 안 난다고 적는다.
  억지로 결론을 내면 그 숫자가 나중에 혼자 걸어 다닌다.
- 🔴 **마지막 줄을 비우지 않는다.** 측정이 보증하지 않는 범위를 적어야
  다음 사람이 그 숫자를 과신하지 않는다.

---

## OPEN — 아직 못 정한 것

물어볼 수 없을 때 여기 적는다. 그 항목에 **의존하지 않는 부분부터** 만든다 (왜 필요한지는 `HARNESS.md` 6절).

```
## <항목> (<올린 날짜>)
- 무엇이 안 정해졌나:
- 왜 지금 못 정하나:
- 임시로 어떻게 하고 있나:
- 🔴 무엇이 이것에 기대고 있나:   ← 정해지면 같이 고쳐야 하는 것
```

정해지면 **DECISIONS(진실 문서면 그 사실이 있는 절)로 옮기고** OPEN 에서는 지운다.
양쪽에 남겨두면 어느 쪽이 최신인지 모르게 된다.

---

## INCIDENTS — 장애 기록 (첫 사고가 날 때 만든다)

세 기록과 따로 둔다. 사용자가 영향을 받았거나 · 데이터를 잃었거나 · 되돌리기를 했거나 ·
우리보다 사용자가 먼저 알았을 때 쓴다. 파일을 만들면 `stack.md` §7 에 한 줄 더한다.

```
## <무슨 일이 있었나 한 줄> (<날짜>)
- 영향:       (누가 · 얼마 동안 · 무엇을 못 했나)
- 타임라인:   (절대 시각으로. 처음 알아챈 때 · 손댄 것 · 정상이 된 때)
- 원인:       (왜 일어났나. 그리고 왜 미리 못 잡았나)
- 조치:       (그때 한 것)
- 다시 안 나게: (할 일과 맡은 사람 · 날짜)
```

🔴 **사람 탓을 적지 않는다.** 「누가 실수했다」에서 멈추면 다음에도 같은 자리에서 누군가 실수한다.
그 실수가 가능했던 구조(검사가 없었다 · 문서가 틀렸다)를 적는다.
배포 지표의 복구 시간 · 변경 실패율이 이 기록에서 나온다 (`docs/deploy.md` 4절).

---

## 크기 관리

이 기록들은 **계속 자란다.** `HARNESS.md` 5절의 크기 예산을 적용한다 (진실 문서 안의 절이면 면제).
넘으면 **연도·단계별로 쪼개고** 최신만 앞에 둔다. 오래된 것을 지우지는 않는다 —
"왜 그렇게 했나"는 오래될수록 값이 커진다.
