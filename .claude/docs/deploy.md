# 배포 설계 원리

`/deploy-check` 가 **무엇을** 확인하는지는 스킬에, 이 프로젝트의 값은 `stack.md` §6 에 있다.
이 문서는 **왜 그렇게 두는지**를 다룬다.

> **2절부터는 운영 모듈 이야기다** (`stack.md` §9). 장기 키 · 인프라 승인 · 배포 이력 · 비용 · 관측 · SLO 는
> 실사용자가 있거나 오래 운영할 때 값을 한다. 몇 주짜리 시연 · 프로토타입에서는 채울 사람도 볼 사람도 없는데
> 빈칸만 대화를 시작할 때마다 찍혀서, 정작 봐야 할 명령 빈칸(§3)이 묻힌다. 그래서 끌 수 있게 했다.
> 1절(데이터 구조를 두 번에 나눠 바꾸기)은 배포가 있으면 모듈과 상관없이 지킨다.

---

## 1. 데이터 구조는 두 번에 나눠 바꾼다 (expand / contract)

무중단 배포에서는 새 버전이 뜬 뒤에도 **옛 버전이 잠깐 트래픽을 받는다.**
그 사이 옛 코드가 새 구조 위에서 돈다. 컬럼 삭제 · 이름 바꾸기 · 필수값 추가는 그 순간 옛 코드를 깨뜨린다.

| 배포 | 하는 일 |
|---|---|
| ① 늘리기 (expand) | 새 컬럼 · 새 테이블을 **더하기만** 한다. 옛 코드는 모르고 지나간다 |
| ② 코드 | 새 구조를 쓰는 코드를 올린다. 옛 데이터는 이때 옮긴다 |
| ③ 줄이기 (contract) | 다음 배포에서 안 쓰게 된 것을 지운다 |

되돌리기도 같은 까닭으로 막힌다. ③ 을 한 뒤에 옛 버전으로 돌아가면 옛 코드가 찾는 컬럼이 없다.
그래서 `stack.md` §6 에 「되돌려도 안 돌아오는 것」 칸이 따로 있다.

## 2. CI 는 장기 키 없이 배포 대상에 붙는다

저장소 비밀값에 클라우드 액세스 키를 넣으면 그 키는 **만료되지 않는다.** 워크플로 하나가 털리거나
설치 스크립트 하나가 환경변수를 읽으면 그대로 밖으로 나간다. 환경변수는 로그 · 자식 프로세스로 잘 샌다.

**OIDC** 를 쓰면 CI 가 실행마다 짧게 사는 토큰을 받는다 — GitHub 은 그 잡에만 `id-token: write`,
GitLab 은 `id_tokens`(Free). 클라우드 쪽 신뢰 정책이 「이 저장소의 이 브랜치(또는 환경)에서 온 토큰만」
받게 묶는다. 묶음을 넓게 쓰면(저장소 이름만 보기 등) 다른 브랜치 · 포크의 잡도 들어온다.

- GitHub 은 2026-07-15 이후 만든 저장소의 토큰 `sub` 에 저장소 ID 를 붙인다. 예제 신뢰 정책을 베끼지 말고
  실제 토큰의 `sub` 를 보고 쓴다
- 역할의 권한은 배포에 쓰는 것만 둔다. 무엇을 썼는지는 클라우드의 접근 분석 도구(AWS 면 Access Analyzer)로
  실제 기록을 보고 줄인다

빌린 서버 한 대에 SSH 로 올리는 팀은 OIDC 가 해당 없다. 그때는 배포만 하는 사용자를 따로 두고,
그 키를 CI 의 보호 · 마스킹 변수에 넣는다. 기본 브랜치 파이프라인만 그 변수를 읽게 한다.

## 3. 인프라 변경은 plan 을 보고 사람이 apply 한다

인프라를 코드로 두면(OpenTofu · Terraform) 바꾸기 전에 **무엇이 바뀔지**(plan)를 먼저 볼 수 있다.
문제는 그 목록에 **지우기(destroy) · 바꿔 끼우기(replace)** 가 섞여 있을 때다. DB 하나가 바꿔 끼우기면
데이터가 같이 사라진다. 그래서 둘을 나눈다.

| | 어디서 | 누가 |
|---|---|---|
| fmt · validate · test | 커밋 게이트 · CI (`stack.md` §3 의 인프라 영역) | 자동 — 자격 증명 없이 돈다 |
| plan | PR · MR 에 결과를 남긴다 | 자동 — 읽기 권한의 OIDC 토큰 |
| apply | plan 을 사람이 읽은 뒤 | **사람이 승인** (`HARNESS.md` 7절 — 되돌릴 수 없는 작업) |

- 상태 파일은 원격에 두고 잠근다. 둘이 동시에 apply 하면 상태가 깨진다. S3 는 1.11 부터 잠금 파일(`use_lockfile`)로
  잠그고 DynamoDB 는 안 써도 된다. GitLab 은 관리형 상태를 Free 로 준다
- 상태 파일에는 비밀값이 평문으로 들어간다. 저장소에 커밋하지 않는다
- 누가 콘솔에서 손으로 바꾼 것은 코드와 어긋난다. 주기적으로 `plan -detailed-exitcode` 를 돌려 잡는다
  (종료 코드 2 = 어긋남) — `drift-guards.md` 패턴 6
- Terraform 은 BSL, OpenTofu 는 MPL 라이선스다. `.tf` 공통 문법만 쓰면 명령만 바꿔 옮길 수 있다.
  한쪽에만 있는 기능(OpenTofu 의 상태 암호화 등)을 쓰면 옮길 수 없게 된다

## 4. 배포 이력이 곧 지표다

배포가 어디에 기록되는지 정해 두면(`stack.md` §6 「배포 이력이 남는 곳」) 되돌릴 태그를 바로 찾는다.
같은 기록으로 배포가 건강한지도 잰다. DORA 의 배포 지표는 다섯이다.

| 지표 | 무엇 | 원천 |
|---|---|---|
| 배포 빈도 | 얼마나 자주 내보내나 | 배포 이력 |
| 변경 리드 타임 | 커밋에서 배포까지 | 배포 이력 + 커밋 시각 |
| 변경 실패율 | 배포 중 되돌리기 · 장애가 난 비율 | 배포 이력 + 장애 기록 |
| 실패 배포 복구 시간 | 깨진 배포에서 정상까지 | 장애 기록 |
| 배포 재작업률 | 계획에 없던 고침 배포(핫픽스)의 비율 | 배포 이력 |

작은 팀은 대시보드 없이 한 달에 한 번 손으로 세면 된다. 표본이 작아서 숫자보다 흐름을 본다.
**팀끼리 비교하지 않는다** — 비교하는 순간 숫자를 맞추려 들고 지표가 망가진다.

---

## 5. 비용은 첫날 알림부터

클라우드 비용 사고는 대개 「켜 둔 것을 잊었다」다. 예산 알림을 첫날 켜 두면 그날 안다.
CI 러너처럼 가끔 쓰는 것은 쓸 때만 늘리고 한가할 때는 0대로 줄인다 (`stack.md` §4).

---

## 6. 이 템플릿이 기본으로 넣지 않는 것

| 무엇 | 왜 안 넣나 |
|---|---|
| GitOps (Argo CD · Flux) | 쿠버네티스를 전제한다. 서버 한두 대에는 무게만 는다 |
| 점진 배포 (카나리 · 블루그린 도구) | 트래픽을 나눌 로드밸런서 · 지표가 있어야 뜻이 있다. 무중단(새 것 띄우고 옛 것 끄기)이 먼저다 |
| PR 마다 미리보기 환경 | 서버 한 대에 브랜치마다 띄우면 메모리가 먼저 바닥난다 |
| 개발자 포털 (Backstage) | 포털을 직접 운영해야 의미가 있다. 서비스가 수십 개일 때 이야기다 |

필요해지면 그때 `stack.md` §6 에 칸을 더하고 이 표에서 지운다.
