# `.claude` — AI 작업 하네스

이 폴더는 **AI(Claude Code)가 이 저장소에서 일하는 방식**을 정해 둔 곳이다.
사람으로 치면 사규 + 업무 매뉴얼 + 선배 + 출입 게이트를 한 폴더에 모아 둔 것이다.

> 이 폴더의 **원본 템플릿**은 따로 보관된다. 새 프로젝트에 심는 절차는 원본 옆의
> `template/README.md` 를 본다. 이 문서는 **여기 있는 파일들이 뭔지**만 다룬다.

---

## 1. 파일은 네 종류뿐이다

이것만 구분하면 나머지는 다 쉽다.

| 종류 | 어떻게 작동하나 | 사람으로 치면 | 안 지키면 |
|---|---|---|---|
| **규칙 문서** | AI가 읽고 따른다 | 사규 | 그냥 넘어갈 수 있다 |
| **스킬** `skills/` | 채팅창에 `/이름` 을 **치면** 순서대로 일한다. Claude 가 설명을 보고 스스로 부르기도 한다 | 업무 매뉴얼 | 아무도 안 부르면 안 돈다. 사람만 부르게 하려면 `disable-model-invocation: true` |
| **에이전트** `agents/` | 별도 AI 조수에게 **따로 시킨다** | 선배·리뷰어 | 안 시키면 안 돈다 |
| **훅·설정** `hooks/`, `settings.json` | 아무도 안 불러도 **자동으로 돈다** | 출입 게이트 | 🔴 **커밋이 막힌다** |

가장 중요한 차이: 앞의 세 종류는 "안 지킬 수도 있는 것"이다. 훅은 **"안 지키면 아예 진행이 안 되는 것"** 이다.
규칙을 진짜로 지키게 만들고 싶으면 문서가 아니라 훅에 넣어야 한다.

> ⚠️ `/이름` 은 **셸 명령이 아니다.** 터미널이 아니라 Claude 와 대화하는 입력창에 친다.
> 폴더를 옮겨 다닐 필요도 없다 — `.claude` 는 저장소 맨 위에 한 벌만 있으면 된다.

## 2. 파일 지도

### 최상위 — 규칙과 배선

| 파일 | 종류 | 무엇 |
|---|---|---|
| `README.md` | 규칙 문서 | **이 문서.** 하네스 지도 |
| `HARNESS.md` | 규칙 문서 | 하네스 헌법. 스택과 무관한 원칙만 |
| `settings.json` | 설정 | 명령 권한(허용 · 확인 · 금지) + 훅 배선 (**실제로 동작하는 부분**) |
| `stack.md` | 규칙 문서 | 🔑 **빈칸 채우기 표.** 이 프로젝트의 명령·경로·게이트·문서 색인 선언 |
| `.gitattributes` | 설정 | 이 폴더의 줄바꿈을 LF 로 고정한다 (`install.ps1` 만 Windows 줄바꿈인 CRLF). **없으면 Windows 에서 훅이 안 돈다** |
| `VERSION` | 설정 | **어느 시점의 하네스를 복사해 왔는지.** 원본에 개선을 되돌릴 때 기준점이 된다 |

> `stack.md` 가 이 하네스를 **다른 서비스에도 쓸 수 있게 만드는 장치**다.
> 스킬들은 `flutter test` 같은 명령을 본문에 박지 않고 **전부 `stack.md` 에서 읽는다.**
> 스택이 바뀌면 이 표만 갈아 끼우면 된다.

### `hooks/` — 자동 검사기

| 파일 | 무엇 |
|---|---|
| `pre-commit` | 커밋 직전 자동 실행: 시크릿 스캔 → 포맷 → 린트 → 테스트. CI 도 같은 파일을 부른다(`--ci-fast` · `--ci`). `--changed-areas <기준>` 은 검사 없이 바뀐 영역 이름만 찍는다 — GitHub 영역별 잡이 쓴다 |
| `commit-msg` | 커밋 **제목** 검사. `stack.md` §3 에 팀이 적은 규칙만 본다. 비워 두면 아무것도 막지 않는다 |
| `secret-scan.sh` | 비밀값(API 키·비밀번호·`.env`) 유출 검사. 에이전트 규칙 파일(`CLAUDE.md` · `AGENTS.md` · `.claude/` 와 Cursor · Copilot · Gemini 의 규칙)에 숨은 보이지 않는 문자도 막는다. 훅과 CI 양쪽이 쓴다. CI 는 `--range` 로 PR 의 커밋 이력까지 본다 — 마지막 커밋에서 지운 키도 원격에는 남는다 |
| `tests/test-secret-scan.sh` | **스캐너의 회귀 테스트.** 탐지 규칙이 살아 있는지 잰다. 시크릿 스캔은 조용히 망가져서 이게 없으면 「돌기는 하는데 아무것도 못 잡는」 상태를 모른다 |
| `tests/test-commit-msg.sh` | `commit-msg` 의 회귀 테스트. 「비우면 아무것도 안 막는다」부터 본다 |
| `tests/test-mr-check.sh` | `mr-check.sh` 의 회귀 테스트. 가짜 origin 을 만들어 GitLab · GitHub 흉내를 낸다 |
| `tests/test-pre-commit.sh` | `pre-commit` 의 회귀 테스트. 영역 틀 · git 없음 · 한글 파일 이름처럼 「검사 0개짜리 초록」이 나던 경우를 본다 |
| `tests/test-deny-sync.sh` | `settings.json` 의 읽기 금지 목록이 `secret-scan.sh` 의 비밀 파일 정의를 다 덮는지 대조한다. 한쪽만 늘리면 깨진다 |
| `tests/test-install.sh` | `install.sh` 의 회귀 테스트. 다른 훅 경로를 말없이 덮지 않는지, 워크트리에서도 기존 훅을 알리는지 본다 |
| `upgrade.sh` | 템플릿 새 버전을 이미 심은 프로젝트에 들인다. 두 버전의 차이만 얹고, 실패하면 아무것도 안 바꾸고 멈춘다 (루트 `README.md` §3) |
| `tests/test-upgrade.sh` | `upgrade.sh` 의 회귀 테스트. 지운 파일 · 커밋 안 한 변경 · 없는 태그 · 충돌 · CI 파일 합치기를 본다 |
| `session-start.sh` | 대화를 시작할 때 Claude Code 훅이 부른다. 브랜치 · git 훅 배선 · `stack.md` 빈칸 수(절마다, §3 은 따로)를 알린다 |
| `tests/test-session-start.sh` | `session-start.sh` 의 회귀 테스트. 늘 0 으로 끝나는지, 알릴 것이 있을 때만 알리는지 본다 |
| `tests/run.sh` | 위 `test-*.sh` 를 전부 돌린다. CI 와 `/health-check` 는 이 파일 하나만 부른다 — 테스트를 더해도 CI 를 고치지 않는다 |
| `mr-check.sh` | MR 안의 **모든 커밋**과 브랜치 이름 · MR 제목을 다시 검사. `commit-msg` 를 그대로 부른다. CI 에서는 `ci/*.yml` 의 `convention` 잡 주석을 풀어야 돈다 |
| `install.sh` | 훅 설치 (macOS/Linux/Git Bash) |
| `install.ps1` | 훅 설치 (Windows PowerShell) |

> 이 폴더에 **파일을 넣으면 그 이름의 git 훅이 자동으로 걸린다** (`core.hooksPath` 방식).
> 맥 · 리눅스에서는 실행 비트가 git 에 기록돼 있어야 돈다.

> ⚠️ 훅 파일은 **놔두면 안 돈다.** `install` 을 한 번 돌려야 git 이 이 폴더를 본다.

### `ci/` — CI 설정 템플릿

| 파일 | 무엇 |
|---|---|
| `github-actions.yml` | GitHub 용. `.github/workflows/gate.yml` 로 복사해서 쓴다 |
| `gitlab-ci.yml` | GitLab 용. `.gitlab-ci.yml` 로 복사해서 쓴다 |
| `dependabot.yml` | GitHub 용. `.github/dependabot.yml` 로 복사한다. 커밋 SHA 로 고정한 액션을 새 버전으로 올리는 PR 을 낸다 |

`/harness-init` 이 **어느 쪽을 쓰는지 묻고** 맞는 것을 제자리에 놓는다.

> 🔑 **두 파일 다 검사 명령을 적지 않고 `pre-commit --ci-fast` 와 `--ci` 를 부른다.**
> 검사 명령은 `stack.md` 에만 있으므로, GitHub 에서 GitLab 으로 옮겨도
> **검사 내용은 그대로**고 고칠 것은 이 껍데기 파일 하나뿐이다.
>
> 껍데기는 **두 층**이다. 층마다 무엇이 도는지는 `stack.md` §4.
> 빠른 층이 **하네스 자체 검사**(`hooks/tests/run.sh`)도 돌린다. 하네스를 고친 PR 이 커밋 게이트나
> 시크릿 스캐너를 망가뜨리거나, 두 곳에 적힌 목록 · 숫자(읽기 금지 목록 ↔ 비밀 파일 정의, 문서 상한)를
> 어긋나게 하면 여기서 깨진다.
>
> 공급망 공격에 맞춰 잠가 뒀다. 액션 · 도구 이미지는 태그 대신 커밋 SHA · digest 로 고정하고,
> 워크플로 권한은 0 에서 잡마다 연다. checkout 은 토큰을 남기지 않는다. GitHub 은 워크플로 파일 자체를
> actionlint · zizmor 로 검사한다. PR · MR 이면 시크릿 스캔이 그 사이 커밋 이력까지 본다.

두 파일에는 **CI 가 느려졌을 때 켜는 주석 예시**가 있다. 무엇부터 켤지는 `stack.md` §4 의 「재 보니 → 할 일」 표가 정한다.

| 예시 | 언제 |
|---|---|
| 영역별 병렬 · PR 에서는 바뀐 영역만 | 영역마다 런타임이 다르거나, 한 영역만 고친 PR 이 전 영역을 기다릴 때. GitHub 은 필수 검사를 `gate` 잡 하나로 모은다 |
| 캐시 | 설치가 잡 시간의 큰 몫일 때. 재 보고 이득이 큰 영역에만 |
| 테스트 나눠 돌리기 (`CI_SHARD`) | 테스트가 잡 시간의 대부분이고 러너가 남을 때 |
| 머지 큐 · 머지 트레인 (파일 머리말) | 기본 브랜치가 자주 움직여 PR 마다 리베이스 · 재검사가 반복될 때 |
| 이미지 굽기 → 검사 → 올리기 | 이미지로 배포할 때. 검사를 통과한 이미지만 커밋 SHA 태그로 레지스트리에 올린다 |

### `agents/` — AI 조수

에이전트는 `/` 로 부르지 않는다. **말로 시킨다** — *"explorer로 결제 코드가 어디 있는지 찾아줘"*.
말로 시키면 어느 조수에게 맡길지는 Claude 가 고른다. 꼭 그 조수가 돌게 하려면 `@"explorer (agent)"` 처럼
멘션한다 (`@` 를 치고 목록에서 고른다).

| 파일 | 무엇 | 왜 따로 두나 |
|---|---|---|
| `explorer.md` | **읽기 전용** 조사원 | 파일 수십 개를 뒤진 내용이 대화에 쌓이면 AI가 원래 하던 일을 잊는다. 내장 조사 기능과 달리 **`stack.md` §7 문서부터** 본다 |
| `reviewer.md` | 독립 리뷰어 | 자기가 짠 코드를 자기가 보면 놓친다. 아무것도 모르는 눈으로 본다 |
| `verifier.md` | 검증 실행원 | 테스트 출력은 수백 줄이다. 실제로 돌리고 **결과만** 요약해 온다 |

### `skills/` — 채팅창에 치는 매뉴얼

| 부르는 법 | 무엇 |
|---|---|
| `/plan` | 계획서를 쓴다. **바꿀 파일 · 안 바꿀 것 · 리스크 · 검증 · 되돌리는 법** 5가지 |
| `/spec` | 코드 짜기 **전에** 기능 설계서를 쓴다. 모르는 건 추측하지 않고 물어본다 |
| `/verify` | 바꾼 게 **진짜 동작하는지** 확인한다. 포맷 → 린트 → 테스트 → 실제 실행 → 결과를 증거로 남긴다. 새 테스트는 고친 코드를 되돌리면 빨개지는지도 본다 |
| `/health-check` | 살아있나를 아래부터 확인 (하네스 / 로컬 / 런타임 / 배포 후) |
| `/handoff` | "여기까지 했고 · 다음은 이것 · 함정은 이것" 을 남긴다. 대화가 길어졌거나 오늘 끝낼 때 |
| `/feature-done` | "진짜 끝났나" 검사. 테스트·문서·설계도가 다 최신인지 |
| `/deploy-check` | 배포 전후 안전 점검 + 되돌리는 법 |
| `/evals` | *(선택)* AI 기능이 있을 때. 프롬프트를 바꾸면 평가셋으로 검증하고 나서 내보낸다 |
| `/write` | 계획 · MR 본문 · 커밋 메시지 · 보고를 사람이 읽게 쓴다. 글을 내보내기 전에 한 번 거른다 |
| `/harness-init` | 이 하네스를 새 저장소에 심는다 (`mvp.md` 를 읽고 빈칸을 채운다). 사람만 부를 수 있다 — `/harness-init` 을 직접 친다 |

> **일반 코드 리뷰 스킬은 만들지 않는다.** Claude Code 에 `/code-review` 와 `/security-review` 가
> 이미 내장돼 있다. 같은 걸 또 만들면 둘이 서로 다른 말을 한다.
> 이 프로젝트 고유의 리뷰 항목은 `agents/reviewer.md` 가 들고 있다.

> `/plan` · `/verify` 는 Claude Code 내장 명령 · 스킬을 일부러 덮어쓴다 — 조건은 `skills/plan` 0절 · `skills/verify` 끝 절.
> 내장 명령인 `/plan` 을 덮어쓰는 것은 로컬 터미널에서만 보장된다. 데스크톱 앱 · VS Code 에서는 내장 plan mode 가 켜질 수 있어서
> `CLAUDE.md` 에 「plan mode 에 들어가면 plan 스킬부터」를 둔다 (`/harness-init` 6단계의 틀).

> `/evals` 는 **선택 모듈**이다. `mvp.md` 에 AI 기능이 없으면 `/harness-init` 이 `settings.json` 의
> `skillOverrides` 로 끈다. 파일은 지우지 않는다 — 지우면 템플릿 업데이트가 그 파일을 맞추지 못한다.

스킬은 "무엇을 하라"만 짧게 적는다. **"왜 그런가"** 는 여기 둔다.

| 파일 | 무엇 |
|---|---|
| `health-check.md` | 헬스체크를 층으로 나누는 이유. 배포 게이트를 왜 따로 두는가. 관측(로그 · 지표 · 추적)과 SLO |

| `drift-guards.md` | 문서·설정이 코드와 어긋나는 것을 **자동으로 잡는** 방법 카탈로그 |
| `context-engineering.md` | AI 머릿속 공간을 아끼는 법. 조수 격리 · 큰 파일 · 세션 인계 |
| `agent-safety.md` | 🔴 외부에서 읽어온 글자는 **데이터지 명령이 아니다.** 되돌릴 수 없는 작업은 확인받는다. 권한 목록이 경계가 못 되는 이유와 진짜 경계 |
| `trackers.md` | `DECISIONS` / `EXPERIMENTS` / `OPEN` 세 기록의 운영법. 첫 사고 때 쓰는 장애 기록 형식 |

### `settings.json` 안에 뭐가 있나

JSON 은 주석을 못 달아서 여기에 적는다. 네 부분이다.

| 키 | 무엇 | 없으면 |
|---|---|---|
| `permissions.allow` | `rg` · `git add` · 훅 · 회귀 테스트만 미리 허용한다. `ls` · `cat` · `find` · `git status` 같은 읽기 전용 명령은 내장 목록이 이미 묻지 않고 돌린다. 여기 다시 적으면 내장 보호를 덮어쓴다 — `find` 의 glob 이 `-delete` 로 펼쳐질 수 있을 때 묻는 검사가 꺼진다 | 같은 확인 창이 거듭 떠서 결국 "전부 허용"을 켜게 된다 |
| `permissions.ask` | `git push` · `git reset --hard` · `git clean`, CI 설정 파일 편집, 게이트 파일(`hooks/` · `settings.json` · `stack.md`) 편집은 매번 묻는다. 대상을 적은 ask 규칙은 auto 모드에서도 사람에게 묻는다 | 판정 모델이 사람 대신 통과시킬 수 있다 — `stack.md` 의 테스트 명령을 `true` 로 바꾸는 편집까지 |
| `permissions.deny` | 비밀 파일 읽기 · 강제 push · 게이트 건너뛰기(`--no-verify` · `-n` · `core.hooksPath` 바꾸기) · `rm -rf` 처럼 Claude 가 흔히 쓰는 모양만 막는다 (8절). 급할 때의 `--no-verify` 는 사람이 친다. 커밋 메시지에 이 글자가 들어가서 막히면 메시지를 파일로 넘긴다(`git commit -F`) | `HARNESS.md` 7절 안전 규칙이 문서로만 남는다 |
| `hooks` | AI 가 도구를 쓸 때 자동 실행 | 아래 두 가지가 안 돈다 |

**권한 모드 — auto 가 기본이다** (Claude Code v2.1.283 이상, 터미널 · VS Code). 사람 대신 판정 모델이
명령을 하나씩 본다. 이 판정 모델은 `CLAUDE.md` 를 읽는다 — 「건드리지 말 것」에 적은 것이 판정에도 들어간다.
`.claude/` · `.git` · `.mcp.json` 같은 보호 경로에 쓰는 것은 auto 에서 판정 모델이 본다 (Manual · acceptEdits 에서는 묻는다).
판정 모델이 작업의 일부로 보고 통과시킬 수 있어서 게이트 파일은 ask 에 따로 적었다.
auto 를 기본으로 하는 설정(`defaultMode: auto` · `autoMode`)은 프로젝트 설정에서 무시되므로 여기 적지 않는다.

**배선된 훅 2개**

| 언제 | 뭘 하나 |
|---|---|
| 대화 시작 | `hooks/session-start.sh` — 브랜치 표시 + **git 훅이 `.claude/hooks` 를 보는지** + `stack.md` 빈칸 수를 절마다 알린다. 명령 자리인 §3 이 비었으면 따로 경고한다 |
| 파일을 고친 직후 | 포맷터를 돌린다 (`hooks/pre-commit --format-only`). 120초를 넘기면 끊는다 — 기본 600초면 멈춘 포맷터가 대화를 10분 붙든다 |

> 막는 훅(PreToolUse)을 더하면 `"onFailure": "block"` 을 단다 (v2.1.295 이상). 안 달면 스크립트 경로가
> 틀리거나 스크립트가 죽었을 때 훅이 실패한 채로 명령이 그냥 돈다 — 막는 장치가 말없이 꺼진다.

> ⚠️ **git 훅과 Claude Code 훅은 다른 것이다.**
> git 훅(`hooks/install.sh` 로 설치)은 `git commit` 때 돌고 **사람이든 AI든** 막는다.
> Claude Code 훅(이 파일)은 **AI 가 도구를 쓸 때** 돌고 미리 고쳐준다. 둘 다 필요하다.

> ⚠️ JSON 이 깨지면 시작할 때 오류 창이 뜬다. **조용히 지나가는 것은 matcher(훅을 걸 도구를 고르는 칸) 오타와 실패를 삼키는 훅 명령이다.**
> matcher 가 틀리면 훅이 아예 불리지 않는다. 명령 끝에 `|| true` · `exit 0` 을 달면 실패가 안 보인다.
> 진짜 도는지는 `/health-check` 가 확인한다.

## 6. 이 하네스가 지키는 4가지 약속

1. 증거 없이 "됐다"고 하지 않는다
2. 추측하지 않는다
3. 한 번에 작은 작업 하나
4. 같은 사실을 두 곳에 적지 않는다

👉 **판단 기준과 이유는 `HARNESS.md` 2절.** 이름만 여기 두고 내용은 옮겨 적지 않는다 —
약속 4 가 바로 그 이야기다.

## 7. 고칠 때 — 어디를 고치나

| 바꾸고 싶은 것 | 고칠 파일 |
|---|---|
| 테스트·린트 명령이 달라졌다 | `stack.md` **만** |
| 폴더 구조가 달라졌다 | `stack.md` **만** |
| 커밋 전 검사 항목을 늘린다 | `hooks/pre-commit` |
| "완료" 기준을 바꾼다 | `skills/feature-done/SKILL.md` |
| 리뷰에서 볼 항목을 늘린다 | `agents/reviewer.md` |

> 🔴 **스킬 본문에 명령어를 박지 말 것.** `stack.md` 에 넣고 스킬은 거기서 읽는다.
> 이 규칙이 깨지는 순간 이 하네스는 이 프로젝트 전용이 되고, 다음 프로젝트에 못 쓴다.

이 폴더를 고쳤으면 **원본 템플릿에도 반영**한다. 안 하면 다음 프로젝트가 같은 실수를 반복한다.

## 8. 이 하네스가 못 하는 것

착각하지 않도록 적어 둔다.

- **`.claude/README.md`(이 파일)는 자동으로 안 읽힌다.** 무엇이 매번 읽히고 무엇이 열 때만
  읽히는지는 `HARNESS.md` 1절. 그래서 `CLAUDE.md` 가 이 문서를 가리키게 해 둔다.
- **스킬은 불러야 돈다.** Claude 가 스스로 부를 수도 있지만 반드시 부른다는 보장은 없다.
  `/feature-done` 을 안 부르면 문서 갱신은 안 일어난다. 진짜로 강제하고 싶은 것은 훅이나 CI 로 옮겨야 한다.
- **턴 끝 자동 검사는 없다.** 필요하면 `/goal`(조건이 맞을 때까지 턴을 넘겨 계속 일하게 한다)이나
  Stop 훅(Claude 가 답을 마칠 때 도는 훅)을 쓴다. Stop 훅에 Claude 가 못 고치는 검사를 걸면
  같은 실패를 되풀이하며 턴을 붙든다.
- **훅은 로컬에서만 돈다.** 팀원이 `install` 을 안 했으면 그 사람에게는 게이트가 없다.
  최종 방어선은 CI 다 — 훅은 "CI 가기 전에 미리 잡는 것"이지 대체물이 아니다. 그래서 `ci/` 를 같이 둔다.
  하지만 CI 설정을 저장소에 놓는 것까지가 하네스의 일이다. 그 CI 가 실제로 도는지 확인하고
  머지를 막는 설정을 켜는 것은 사람이 한다 (설정 이름은 `ci/*.yml` 머리).
- **시크릿 스캔은 완벽하지 않다.** 알려진 패턴만 잡는다. 한 번 새어나간 키는 되돌릴 수 없으므로
  스캔을 믿지 말고 애초에 커밋 대상에 넣지 않는다. 플랫폼의 푸시 보호(push protection)도 켠다 —
  GitHub 공개 저장소는 무료고 사설은 유료다. GitLab 은 Ultimate 에만 있다.
- **커밋 게이트의 포맷 · 린트 · 테스트는 작업 트리를 본다.** 파일의 일부만 스테이지하면 초록이
  그 커밋을 보증하지 않는다. 스테이지 기준으로 보는 것은 시크릿 스캔뿐이다. 최종 판정은 CI 가 한다.
- **권한 목록은 경계가 아니다.** `permissions.deny` 는 Claude 가 흔히 쓰는 명령 모양만 맞춘다.
  비밀이 있는 저장소나 남의 코드를 돌릴 때 기댈 경계는 `docs/agent-safety.md` 6절에 있다.
- **AI 가 읽은 외부 글자를 하네스가 걸러주지 않는다.** 웹페이지·이슈·문서에 적힌 지시문은
  사람이 시킨 것이 아니다. 판단 기준은 `docs/agent-safety.md` 에 있다. 최종 확인은 사람이 한다.

**확인하지 못한 것** — macOS 에서 훅 설치와 회귀 테스트를 돌려 보지 않았다. Windows Git Bash ·
alpine(busybox) · Debian 에서만 돌렸다. 맥에서 돌려 보면 이 줄을 지운다.
