# 사건 · 이슈 묶기 정확도 평가

운영에 묶인 사건 · 이슈가 얼마나 맞는지 정답과 견줘 숫자로 낸다. 조회 속도가 아니라 정확성이다. 계획은 `docs/plans/2026-11-13-event-issue-accuracy.md`, Jira S15P31A102-206.

| 파일 | 하는 일 |
|---|---|
| `eval_export.sql` | 운영에서 읽기만으로 이슈 · 사건 · 사건에 묶인 기사를 JSONL 로 뽑는다(기사 글은 제목과 본문 앞 240자). 사건마다 공개 기사 수 · 언론사 수(`released_articles` · `released_presses`)도 싣는다 |
| `clustering_eval.py` | 후보 만들기 · Sonnet 묶음 나누기 · 모으기 · 사람 표본 · 기록 · 일치율 · 지표. 표준 라이브러리만 |
| `extract_primary.py` | EXTRACT 가 대표 사건(`primaryCoreIndex`)을 고르는 정확도 채점. 표본이 층화라 층마다 재고 모집단 비율로 다시 묶는다. 표준 라이브러리만 |

| 시험 | `infra/ci/test_clustering_eval.py` · `test_final_gold_also.py` · `test_eval_threshold.py` · `test_extract_primary.py` (CI `infra_TEST`) |

## 1. 무엇을 판정하나

| 일 | 질문 | 판정 |
|---|---|---|
| `M:<사건>:<기사>` | 이 기사가 이 사건에 맞나 | `Y` · 다른 한 사건 `B` ~ `Z` · 혼자 / 사건 없음 `0` |
| `P:<사건>:<사건>` | 두 사건이 같은 사건인가 | `same_event` · `same_issue` · `unrelated` |
| `I:<이슈>:<사건>` | 이 사건이 이 이슈 흐름에 드나 | `Y` · `B` ~ `Z` · `0` |
| `O:<사건>:<이슈>` | 이슈 밖 사건이 이 이슈에 드나 | `Y` · `N` |
| `Q:<이슈>:<이슈>` | 두 이슈가 한 흐름인가 | `same_issue` · `unrelated` |
| `E:<기사>` | 이 기사에 대표 사건이 있나 | `Y` · `N` |

`E` 는 묶기 전 단계다 — 대표 사건이 없다고 본 기사는 판정(`MATCH_EVENT`)을 **아예 걸지 않아서**(`docs/api-internal.md` 3절) 여기서 틀리면 그 기사는 어떤 사건 · 이슈에도 못 들어간다. `clustering_eval.py` 는 세 토막 키만 다루므로 `E` 는 `extract_primary.py` 가 따로 채점한다.

`P` 후보는 발생일 ±3일 안에서 제목 글자 겹침 상위 3 ∪ 벡터 중심 코사인 상위 3, 겹침 0.10 · 코사인 0.60 둘 다 아래면 뺀다. 후보 밖 놓침은 같은 날 사건 쌍 무작위 40개로 어림한다. 벡터는 AI 팀 파일(`dragonkue/BGE-m3-ko`, 제목 + 줄바꿈 + 본문 앞 800자)이다.

### 어느 것이 train · validation · test 인가

표준 용어로 적어 둔다. 어디까지 손댄 데이터이고 어디가 손대지 않은 데이터인지가 숫자를 읽는 기준이다.

| 우리 것 | 표준 용어 | 쓰임 | 이 몫으로 정확도를 보고하나 |
|---|---|---|---|
| 보정 50건 (`human.tsv` stage `calib`) | **train (fit)** | Sonnet 지시문의 「보탬」을 여기서 정했다 | **아니다** — 맞춘 데이터다 |
| Sonnet 전수 18,104건 (`sonnet.tsv`) | **silver label** (LLM-as-a-judge) | 정답 묶음을 만드는 바탕 | 사람 몫으로 보정해서만 |
| 검수 150건 (`human.tsv` stage `verify`) | **held-out audit** | silver 가 얼마나 맞는지 사람이 층화 표본으로 | **그렇다** — 역확률 가중치 · Wilson 구간 |
| 재생 개발 창 1일 | **validation (dev)** | 문턱 τ · 후보 수 k · 프롬프트 고르기 | 아니다 |
| 재생 시험 창 1일 | **test (held-out)** | 고른 값을 한 번만 돌려 보고 | **그렇다** |

- 모델 가중치를 학습하지는 않는다. 그래서 엄밀한 train 은 없고, 「개발 창에서 값을 고르고 시험 창은 손대지 않는다」가 그 자리를 대신한다. B1(임베딩만)의 문턱 τ 하나만 개발 창에서 맞춘다
- 사람이 단 판정만 gold 다. Sonnet 이 단 18,104건은 silver 이고, 둘을 섞어 「정답셋」이라 부를 때는 어느 쪽인지 밝힌다
- **보정 50건의 일치도는 held-out 값이 아니다.** 사람과 엇갈린 6건을 사람이 다시 가린 뒤에 잰 값이고, 그 가운데 둘은 지시문에 되먹였다. 깨끗한 일치도는 검수 150건에서 나온다 — 그 150건은 Sonnet 이 사람 답을 보지 않고 전수에서 미리 판정한 것이다

## 2. 돌리는 법

목록 · 벡터 · 작업 폴더는 저장소 밖에 둔다(기사 글이 있다). 예는 `C:/tmp/206-steps/`.

```bash
# 1) 운영에서 읽기만 — kubectl exec 출력이 끊기면 서버 파일로 받는다
ssh newlearn 'kubectl -n data exec -i postgres-0 -- psql -X -q -U newlearn -d newlearn -At > eval-export.jsonl; wc -l eval-export.jsonl' < infra/server/eval/eval_export.sql
scp newlearn:eval-export.jsonl C:/tmp/206-steps/export.jsonl && ssh newlearn 'rm eval-export.jsonl'

# 2) 후보 · 대표 기사(약 25초)
python -X utf8 -B infra/server/eval/clustering_eval.py prepare C:/tmp/206-steps/export.jsonl <벡터.sqlite> C:/tmp/206-steps/w2

# 3) 사람 보정 — 표본을 뽑고, 질문 상자로 4건씩 통과 · 불통과를 받아 바로 기록
python -X utf8 -B infra/server/eval/clustering_eval.py sample C:/tmp/206-steps/w2 infra/server/eval/gold calib
python -X utf8 -B infra/server/eval/clustering_eval.py record infra/server/eval/gold M:1183:22625 통과

# 4) 같은 표본을 Sonnet 으로 → 일치율 · κ
python -X utf8 -B infra/server/eval/clustering_eval.py split C:/tmp/206-steps/w2 --stage calib
#    묶음마다 Sonnet 조수 하나에 judge-prompt.md 를 주고 bNN.tsv 를 받는다
python -X utf8 -B infra/server/eval/clustering_eval.py merge C:/tmp/206-steps/w2 infra/server/eval/gold --stage calib
python -X utf8 -B infra/server/eval/clustering_eval.py agree infra/server/eval/gold --workdir C:/tmp/206-steps/w2 --stage calib --sonnet sonnet-calib.tsv

# 5) κ ≥ 0.6 이면 전수 → 사람 검수 150건(verify) → 지표
python -X utf8 -B infra/server/eval/clustering_eval.py split C:/tmp/206-steps/w2
python -X utf8 -B infra/server/eval/clustering_eval.py merge C:/tmp/206-steps/w2 infra/server/eval/gold
python -X utf8 -B infra/server/eval/clustering_eval.py sample C:/tmp/206-steps/w2 infra/server/eval/gold verify
python -X utf8 -B infra/server/eval/clustering_eval.py metrics C:/tmp/206-steps/w2 infra/server/eval/gold

# 6) 화면에 보일 몫만 — 사건마다 공개 기사 · 언론사가 이만큼은 돼야 채점한다(기본 1 · 1 은 거르지 않음)
python -X utf8 -B infra/server/eval/clustering_eval.py metrics C:/tmp/206-steps/w2 infra/server/eval/gold --min-articles 3 --min-publishers 3
```

사람 판정은 Sonnet 답을 보지 않고 한다. 같은 키를 다시 기록하면 뒤 줄이 이긴다. 지표를 낼 때 사람 판정이 Sonnet 판정을 덮는다.

### `E` — 대표 사건이 있나 (2026-11-15)

🔴 **기준은 운영 지시문을 그대로 쓴다.** `ai/app/extract/prompt.py` 의 `[대표 사건 primaryCoreIndex]` 대목(약 5,000자)이고, `docs/api-internal.md` 5절의 한 줄 요약(「운세 · 시세표 · 축사 · 해설」)으로 재면 안 된다. 2026-11-15 에 그 요약으로 쟀더니 건너뛴 기사의 32.2% 가 틀린 것으로 나왔는데, 지시문으로 다시 재니 **13.3%** 였다 — 같은 기사 120건 중 **25건(20.8%)이 답이 갈렸다**. 요약에는 「단순 모집 · 행사 · 이벤트 · 출시 · 공연의 일정 · 참여 안내」가 null 이라는 규칙이 빠져 있었다.

표본은 **층화**다 — 워커가 건너뛴 기사 90 + 고른 기사 30 을 따로 뽑아 섞어서 눈가림으로 판정했다. 그래서 날것의 정밀도 · 재현율은 모집단 값이 아니고, `--skip-share` 로 다시 묶어야 한다.

```bash
# 1) 정답셋의 기사 번호로 운영에서 워커 결과만 뽑는다(읽기만) — 「기사 번호<탭>1|0」, 1 이 대표 사건을 고른 것
#    표본 · 판정 이유처럼 기사 글이 있는 것은 저장소 밖에 둔다(예: C:/tmp/pci-1115/)
cut -f1 infra/server/eval/gold/sonnet-extract-primary.tsv | tail -n +2 | sed 's/^E://' | paste -sd, -

# 2) 채점 — 건너뛴 기사의 몫은 그때 운영에서 센다
python -X utf8 -B infra/server/eval/extract_primary.py \
  infra/server/eval/gold/sonnet-extract-primary.tsv <워커 결과.tsv> --skip-share 0.321 --daily-skip 1038
```

2026-11-15 결과(최근 3일 기사, 건너뛴 몫 32.1%): **정밀도 0.967 · 재현율 0.939 · F1 0.953**. 건너뛴 기사의 13.3%(95% 7.8 ~ 21.9%)가 사실은 사건이 있고, 고른 기사의 3.3%(0.6 ~ 16.7%)는 사실 사건이 없다. 하루로 치면 약 **138건**(81 ~ 227)이 사건이 있는데 판정 줄에 못 들어간다.

**말하지 못하는 것**: 판정자는 Sonnet 하나이고 사람 검수가 없다 — 그래서 파일 이름이 `sonnet-*` 이고 gold 가 아니라 silver 다(1절). 판정자끼리의 일치도도 재지 않았다. 표본은 최근 3일이다.

| ARI | 우연히 맞을 몫을 뺀 일치 |

### 공개 기사 수 · 언론사 수 문턱

`--min-articles N` · `--min-publishers N` 은 **채점 대상만** 줄인다. 정답 묶음은 그대로 두고, 문턱을 못 넘은 사건과 그 사건의 기사를 사건 · 이슈 지표에서 뺀다. 「사건에 기사가 이만큼은 모인 것만 화면에 보이면 지표가 어떻게 되나」를 보는 자다. 문턱은 `event` · `issue` 와 분야별 · 크기별 줄에만 걸린다 — 이행 합침 · 이슈 합침 · 언론사 수별 오류율 · 같은 날 무작위 쌍은 늘 전체다.

같은 명령이 **이슈에 붙은 사건의 언론사 수별 오류율**(1곳 이하 · 2곳 · 3곳 이상에서 `I` 판정이 `Y` 가 아닌 비율)도 낸다 — 문턱을 왜 두는지 보여 주는 표다. 첫 칸은 공개 기사가 없는 사건(언론사 0곳)까지 담아 「1곳 이하」다.

목록에 두 수가 없는 옛 내보내기는 `--event-counts <사건id|공개기사수|언론사수 파일>` 로 대신 넣는다. 수를 모르는 사건은 문턱을 넘지 못하고, 몇 개인지 찍는다.

**이 자가 말하지 못하는 것** — 「화면에 보일 몫의 정확도」라고 단정하지 않는다.

- **문턱을 올리면 재현율이 저절로 오른다.** 정답 한 묶음에서 한쪽만 남은 쌍은 분자에서도 분모에서도 빠진다. 숨은 사건과의 놓친 합침이 **고쳐진 것이 아니라 채점에서 사라진 것**이다. 몇 쌍이 끊겼는지 `threshold.gold_pairs_cut` 에 적고 화면에도 찍는다 — 재현율을 말할 때 이 수를 같이 말한다
- **남은 사건 안의 비공개 기사는 그대로 채점된다.** 문턱은 사건 단위라 「채점한 기사가 모두 화면에 보인다」는 뜻이 아니다
- **화면의 실제 규칙과 자리만 비슷하다.** 화면도 사건 단위로 공개 기사 수를 보지만 그 수는 설정이다 — `QUERY_MIN_PUBLIC_ARTICLES`(기본 1, 운영 3. `backend/src/main/java/kr/io/newlearn/common/PublicEventSql.java` · `PublicEventThreshold.java`, Jira S15P31A102-179 · 206). 여기서 `--min-articles 1` 은 「거르지 않음」이라 공개 기사가 0건인 사건도 채점에 남는다 — 기본값이 지금 숫자를 바꾸지 않게 하려는 선택이다. 운영 값을 바꾸면 이 자도 같은 수로 맞춰 재야 한다
- **이슈 쪽에는 자에 없는 규칙이 하나 더 있다.** 2026-11-15 부터 운영은 보이는 사건이 3개 미만인 이슈를 **목록에서** 뺀다(`QUERY_MIN_PUBLIC_EVENTS`, Jira S15P31A102-208). 이 자는 그 규칙을 쓰지 않아 그런 이슈의 쌍도 그대로 채점한다 — 즉 **이슈 지표는 화면에 나오는 이슈보다 넓은 범위**다. 묶기 품질을 재는 것이 목적이라 그대로 두지만, 「화면에 보이는 이슈의 정확도」로 옮겨 말하면 안 된다

비율은 Wilson 95% 구간, F1 · B³ 는 묶음 덩어리(정답이 잇는 시스템 묶음끼리) 단위 부트스트랩 1,000번. 사람 표본은 층별 역확률 가중치로 되돌린다. 숫자 옆에 범위를 적는다: 「사건에 묶인 기사 14,493건 안에서」, 「사람 1명 + Sonnet 판정」.

### 합침을 판정으로만 잇는다

처음 셈했을 때 이슈 쌍 F1 이 0.246 이었다. 판정한 적 없는 쌍까지 타고 묶음이 이어진 탓이다(정답 묶음 하나가 운영 이슈 24개를 삼켰다). 세 가지를 막았다.

| 막은 것 | 왜 |
|---|---|
| A~B, B~C 를 타고 잇기 | A~C 는 판정한 적이 없다. **묶음 안의 쌍이 모두 판정됐고 모두 같은 흐름일 때만** 합친다(`verified_issue_merges`) |
| 두 이슈에 각각 든 사건 쌍으로 잇기 | 사건 쌍의 성적은 사건 지표에서 이미 센다. 이슈끼리 합칠지는 `Q` 가 정한다 |
| 이슈 밖 사건이 여러 이슈에 걸치기 | 그 사건이 다리가 된다. 후보가 여럿이면 **한 이슈에만** 붙인다 |

고친 뒤 정답 묶음 하나가 삼킨 운영 이슈는 최대 3개이고, 남은 합침은 모두 판정으로 뒷받침된다. 같은 흐름으로 판정된 102쌍 가운데 **18쌍만 적용**했고, 84쌍(이슈 59개)은 묶음의 다른 쌍을 판정하지 않아 합치지 않았다 — 그래서 **정답이 실제보다 잘게 갈려 있다**. 정답 묶음을 더 합치면 정답 쌍(재현율의 분모)이 늘고 그 쌍들은 운영이 갈라 둔 이슈를 가로지르므로 **재현율은 내려간다**. 실제로 재 봤다 — 같은 흐름으로 판정된 102쌍을 모두 합치면 정답 묶음 225 → 175, **쌍 재현 0.758 → 0.211 · 쌍 F1 0.855 → 0.348**(정밀도는 0.982 그대로). 그래서 **0.758 은 위로 치우친 값**이고 참값은 0.211 과 0.758 사이다 — 폭이 넓다는 것 자체가 이 숫자의 한계다.

### 흔들림 시험 — 지시문을 채우고 사건 쌍을 다시 판정 (2026-11-14)

2판 지시문은 v4 를 **M 에만** 옮겨 적고 P · I · O · Q 는 장 번호만 가리켰다. 3판에서 v4 4-1 · 4-2 · 5 · 6장의 문장과 갈림막이(「애매하면 다른 사건」)를 네 일 모두에 옮긴 뒤, **데이터 · 후보 쌍 · 모델은 그대로 두고 지시문만 바꿔** 사건 쌍 2,064건을 다시 판정했다(`gold/sonnet-p3.tsv`).

| `same_issue` | 1,367 | 1,376 |

바뀐 113쌍의 내역은 `unrelated` ↔ `same_issue` 96쌍(거의 상쇄)과 `same_event` 경계 17쌍(12쌍이 내려가고 5쌍이 올라와 순 −7)이다.

**사람 둘이 겹쳐 본 사건 쌍 13건에서** 기준을 만든 쪽(팀원)과의 일치가 0.615 → **0.692** 로 올랐고, 기준을 줄줄이 대조하지 않은 쪽과의 일치는 0.846 → 0.615 로 내렸다. 두 사람이 갈렸던 5건 중 2건이 팀원 쪽으로 옮겨 갔다 — 「상정(11/5) → 가결(11/6)」과 「같은 날 다른 자리의 두 발언」으로, 각각 v4 의 「하루 다르면 같은 때가 아니다」와 예외 ③ 「같은 자리 · 같은 사안일 때만」이 걸린 것이다. 13건은 작은 표본이라 방향만 읽는다.

**그런데 최종 지표는 움직이지 않았다.**
