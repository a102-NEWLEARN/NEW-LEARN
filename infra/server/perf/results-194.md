A2 이슈 목록 SQL 을 「이슈별로 먼저 세고 → issue 를 붙이고 → 정렬 · 자르기 한 번」으로 바꾸고, Flyway V15 로 `article_event(event_id)` · `event(issue_id)` 인덱스와 기사 표 자동 VACUUM 기준을 넣은 전 · 후다(Jira S15P31A102-194). 계획 `docs/plans/2026-11-12-issue-list-query.md`, 도구는 같은 폴더(`README.md`).

## 요약

## 자동 VACUUM 기준

- 기사 표 설정 다섯(넣은 행 · 죽은 행 1,000건마다, 회차마다 로그)이 08:23 부터 들어가 있다
- 효과는 쓰기가 생긴 뒤에 본다 — 15분 수집이 켜지면 기사 표 자동 VACUUM 횟수 · 로그와 A1 기사 수의 Heap Fetches(11-12 3,267)를 다음 날 확인한다
- 참고: 11-12 10:00 수집이 넣은 12,422건은 기본 기준(약 1만 5천 6백) 아래라 다음 날 아침까지 자동 VACUUM 이 돌지 않았다(11-13 07:12 `n_ins_since_vacuum` 12,422). 11-13 다시 적재는 고친 행이 많아 기본 기준으로도 바로 돌았다
